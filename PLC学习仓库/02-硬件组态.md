# 02 硬件组态：先给 PLC 搭好"家"，再让它干活

## 📖 学习目标

1. 理解什么是硬件组态，明白为什么写程序之前必须先做硬件组态。
2. 学会在 TIA Portal 中新建项目并添加一台 S7-1500 PLC 设备（CPU）。
3. 学会设置 CPU 的基本属性（IP 地址、时区、启动方式等）。
4. 学会在机架上添加信号模块（DI/DQ/AI/AQ），并理解模块地址的自动分配规则。
5. 掌握"编译 → 下载到 PLCSIM → 在线查看"的完整流程，为后续所有章节的仿真练习打好地基。

## 一、什么是硬件组态

### 1.1 一个生活化的类比

想象你要开一家餐厅。在招厨师、买菜之前，你得先把**店面装修图**画好：厨房在哪、收银台在哪、桌子摆几排、每张桌子编号是多少。没有这张图，厨师不知道在哪儿炒菜，服务员不知道 5 号桌在哪。

PLC 工程也是一样。**硬件组态（Hardware Configuration）就是在 TIA Portal 软件里"画出"你这套控制系统的硬件图纸**：

- 用的是什么型号的 CPU（相当于餐厅的"总指挥"）；
- 机架上插了哪些信号模块（相当于厨房里有哪些设备）；
- 每个模块插在哪个槽位、占用哪些地址（相当于每张桌子的编号）；
- CPU 的参数怎么设（相当于餐厅的营业时间和规矩）。

### 1.2 硬件组态的正式定义

硬件组态是指在编程软件中，按照实际控制柜里硬件的**型号、数量和安装位置**，逐一对 PLC 系统进行"虚拟搭建"，并设置各项参数的过程。组态完成后，TIA Portal 里会出现一个与真实（或仿真）PLC 一一对应的"数字双胞胎"。

用一张图看看我们要搭建的目标（以本课程常用的配置为例）：

```
        S7-1500 机架（导轨）示意图
 ┌────────┬────────┬────────┬────────┬────────┐
 │ 槽0    │ 槽1    │ 槽2    │ 槽3    │ 槽4    │
 │ PS电源 │ CPU    │ DI模块 │ DQ模块 │ AI模块 │
 │ (可选) │ 1511-1 │ 16点   │ 16点   │ 8通道  │
 │        │ PN     │ I0.0~  │ Q0.0~  │ IW512~ │
 └────────┴────────┴────────┴────────┴────────┘
      ▲        ▲        ▲        ▲        ▲
    只供电   大脑     接按钮/  接接触器/ 接温度/
   不参与程序         传感器   指示灯    压力等模拟量
```

> 说明：电源模块（PS）只是给背板供电，可选项；CPU 是必须的；信号模块从 CPU 右侧依次排列。本课程用 PLCSIM 仿真，不需要真实模块，但我们依然要在软件里把它们"摆"上去。

### 1.3 组态、程序、硬件三者的关系

初学者最容易把这三种东西搅在一起，用一句话理清：

**组态是"户口本"——登记 CPU 和每个模块的身份与地址；程序是"工作计划"——按户口本上登记的地址去读写信号；硬件（或 PLCSIM 里的虚拟硬件）是"本人"——真正执行动作的一方。**

三者必须一致：

```
   组态（户口本）        程序（工作计划）        硬件/仿真（本人）
   ┌──────────────┐     ┌──────────────┐      ┌──────────────┐
   │ 槽2: DI 模块  │ ←── │ 用 I0.0 读按钮 │ ──→ │ I0.0 接按钮   │
   │ 槽3: DQ 模块  │ ←── │ 用 Q0.0 驱动   │ ──→ │ Q0.0 接接触器 │
   └──────────────┘     └──────────────┘      └──────────────┘
        三者对不上 → 编译报错 / CPU 报硬件故障 / 现场不动作
```

后面遇到"程序没错却不动"的问题，先回来检查这张三方对账图。

## 二、为什么必须先做硬件组态

很多零基础同学会问："我只想写个电机启停程序，能不能跳过组态直接写梯形图？"答案是：**不能**。原因有四条：

1. **程序必须有一个"落脚点"。** 在 TIA Portal 中，程序（OB1 等块）是挂在 PLC 设备下面的。没有 PLC 设备，连一个空程序都无处安放。

2. **编译检查需要它。** 编译时，TIA Portal 会检查：你程序里用到的 I0.0、Q0.0 这些地址，在组态的模块上到底存不存在。如果模块只组了 8 个输入点（I0.0~I0.7），你却用了 I1.0，编译直接报错。这就把"接线错误"消灭在了电脑里，而不是等到了现场才炸。

3. **CPU 需要知道"谁在自己身上"。** 真实 PLC 上电后，会把自己身上实际插着的模块与组态进行比对。对不上号，CPU 会报"硬件故障"，甚至拒绝进入运行状态。

4. **地址分配靠它。** 每个模块占用的输入/输出地址（I 区、Q 区）是由组态决定的。先组态，才知道按钮该接哪个点、程序该用哪个地址。

一句话总结：**硬件组态是程序的"地基"，地基不稳，房子盖不起来。**

## 三、在 TIA Portal 中添加 PLC 设备

### 3.1 第一步：新建项目

启动 TIA Portal（本课程兼容 V18/V20，操作几乎完全一样），在"启动"画面中选择 **创建新项目**：

1. 输入项目名称，例如 `电机控制练习`（路径随意，建议放在好找的文件夹）；
2. 点击"创建"。

进入项目后，你会看到左侧竖排的 **项目树**，它是整个项目的"目录"，后面所有操作都从这里展开。

### 3.2 先认识工作界面的五大区域

后面所有组态、编程、调试都在这几个区域之间切换，先混个脸熟：

```
 ┌────────────────────────────────────────────────────────────┐
 │ ① 项目树（左侧竖排）                                        │
 │    项目 → PLC_1 → 硬件 / PLC变量 / 程序块 …                 │
 ├──────────────┬─────────────────────────────┬───────────────┤
 │ ② 硬件目录   │  ③ 工作区                   │ ④ 属性/信息   │
 │ （右侧，组态 │  （设备视图/网络视图/        │ （下方或右侧， │
 │  时才重点用）│   梯形图编辑区/变量表）      │  看参数与错误）│
 ├──────────────┴─────────────────────────────┴───────────────┤
 │ ⑤ 检查窗口（最下方：编译结果、诊断信息都在这里报到）        │
 └────────────────────────────────────────────────────────────┘
```

| 区域 | 名称 | 干什么用 |
|------|------|---------|
| ① | 项目树 | 项目的总目录：打开硬件组态、变量表、程序块、在线与诊断都从这里双击进入 |
| ② | 硬件目录 | 全部可选的 CPU/模块"货架"，组态时从这里拖模块 |
| ③ | 工作区 | 当前编辑对象的主画面（画机架、画梯形图、填变量表） |
| ④ | 属性面板 | 查看和修改选中对象的参数（CPU 的 IP、模块的地址都在这改） |
| ⑤ | 检查窗口 | 编译结果的"成绩单"，错误警告都在这看 |

新手建议：暂时只记住"项目树 + 工作区 + 检查窗口"三件套，硬件目录在第四章组态模块时自然会熟。

### 3.2 第二步：添加 PLC 设备（CPU）

1. 在项目树中双击 **添加新设备**；
2. 弹出的对话框左侧选择 **控制器**；
3. 展开 **SIMATIC S7-1500** 文件夹；
4. 在列表中选择 CPU 型号，例如 **CPU 1511-1 PN**；
5. 点击右下角 **添加** 按钮。

完成后，TIA Portal 会自动打开 **设备组态（网络视图/设备视图）** 画面，机架上已经摆好一个 CPU。

### 3.3 新手推荐哪款 CPU？为什么？

| 推荐型号 | 推荐理由 |
|---------|---------|
| **CPU 1511-1 PN** | S7-1500 家族的"入门款"：功能完整、价格最低、PLCSIM 完全支持、市面教程和资料最多。学完它，升级到 1513/1515 零障碍。 |

选择建议：

- **纯仿真学习**：选 CPU 1511-1 PN 即可；也可以在"控制器"列表最上方选择 **非特定的 CPU**（不锁定具体型号，下载时由 PLCSIM 自动匹配，仿真更省事，但工程中不推荐这种习惯）。
- **预算/项目需要**：点位和性能要求更高时选 CPU 1513-1 PN、1515 系列，组态步骤完全相同。

> 提醒：TIA Portal 版本越新，支持的 CPU 固件版本越多。V18/V20 对本课程全部内容都绰绰有余，不必纠结版本差异。

### 3.4 CPU 属性设置

在设备视图中单击 CPU，下方会出现 **属性（Properties）** 面板，逐项检查以下设置（其余参数保持默认即可）：

#### （1）PROFINET 接口 → IP 地址

- 位置：属性 → **PROFINET 接口** → 以太网地址；
- S7-1500 出厂默认 IP 为 `192.168.0.1`，子网掩码 `255.255.255.0`；
- **仿真学习时**：保持默认即可，PLCSIM 并不真的通过这个 IP 通信；
- **真实工程中**：IP 必须与工厂网络规划一致，且同一网络内绝不允许两台设备使用相同 IP（详见本章第九节）。

#### （2）时间 → 时区（Time synchronization）

- 位置：属性 → **时间同步 / 模块时间**；
- 将时区设置为 **(GMT+08:00) 北京**（按你所在时区选择）；
- 取消勾选"夏令时"（我国不使用夏令时）；
- 作用：保证报警记录、数据时间戳的准确，仿真阶段影响不大，但建议一开始就养成习惯。

#### （3）启动（Startup）

- 位置：属性 → **启动**；
- 选择上电后的行为，常用 **暖启动 - 转入 RUN**（CPU 上电后自动进入运行状态）；
- 仿真时 CPU 首次下载后会处于 STOP，需要手动切到 RUN，这个知识点在下载一节讲。

#### （4）循环（Cycle）—— 扫描周期监控时间

- 位置：属性 → **循环**；
- "扫描周期监控时间"默认 150 ms：程序一个周期超过它，CPU 报错停机；
- 新手保持默认即可，学到循环中断、死循环排查时再回头理解它。

#### （5）保持性存储器（Retentive memory）

- 位置：属性 → **保持性存储器**；
- 可以为 M 区、DB 区划出一块"断电不丢数据"的区域；
- 新手阶段保持默认，后面学到数据块时再细讲。

#### （6）系统与时钟存储器（System and clock memory）——本课程必开项！

- 位置：属性 → **系统与时钟存储器**；
- 勾选 **启用系统存储器字节**，默认分配 **MB1**：其中 M1.0 = 首扫描脉冲（上电第一个周期为 1），可用于上电初始化；
- 勾选 **启用时钟存储器字节**，默认分配 **MB10**：系统自动生成一组不同频率的方波位，频率从低位到高位依次为：M10.0 = 10 Hz（0.1s 周期）、M10.1 = 5 Hz（0.2s）、M10.2 = 2.5 Hz（0.4s）、M10.3 = 2 Hz（0.5s）、M10.4 = 1.25 Hz（0.8s）、**M10.5 = 1 Hz（亮 0.5s 灭 0.5s）**、M10.6 = 0.625 Hz（1.6s）、M10.7 = 0.5 Hz（2.0s）；
- **本课程全套笔记约定：闪烁标志用 M10.5（1 Hz）/ M10.3（2 Hz）**——它们不是普通变量，而是由系统自动翻转的"心跳"位。想让报警灯闪烁，只需 `报警灯 = 报警条件 AND M10.5`；
- 仿真环境中时钟存储器照常工作，PLCSIM 里能看到 M10.5 自动 0/1 跳变。

> 忘了勾选启用，程序里用 M10.5 就"永远不闪"——这是后续章节的高频疑问，现在就把它配置好。

#### （7）防护与安全（Protection）

- 位置：属性 → **防护与安全 → 连接机制、访问保护**；
- 可设置访问保护等级（完全访问权限 / 读 / 不可访问）和连接配对；
- 仿真学习保持默认"完全访问权限（无保护）"即可；真实工程中要按工厂安全规范配置，防止未授权下载。

## 四、添加信号模块（DI/DQ/AI/AQ 模块）

### 4.1 四类信号模块是干什么的

CPU 本身的输入输出点很少，大量按钮、传感器、接触器要靠**信号模块**接入。按信号性质分四大类：

| 类型 | 中文含义 | 信号特点 | 典型连接的设备 | 地址前缀 |
|------|---------|---------|--------------|---------|
| **DI** | 数字量输入模块 | 只有"通/断"两种状态 | 按钮、行程开关、继电器触点、光电开关 | I |
| **DQ** | 数字量输出模块 | 只有"通/断"两种状态 | 接触器线圈、指示灯、蜂鸣器、电磁阀 | Q |
| **AI** | 模拟量输入模块 | 连续变化的数值 | 温度传感器、压力变送器、液位计 | I（字地址） |
| **AQ** | 模拟量输出模块 | 连续变化的数值 | 变频器频率给定、调节阀开度 | Q（字地址） |

记忆口诀：**D = 数字（Digital），A = 模拟（Analog），I = 输入（Input），Q = 输出（Output）**。按钮是"按没按"的问题 → DI；灯是"亮不亮"的问题 → DQ；温度是"多少度"的问题 → AI。

### 4.2 在机架上添加模块的操作步骤

以添加一块 16 点数字量输入模块为例：

1. 确认当前处于 **设备视图**（项目树 → PLC_1 → 设备组态 → 双击"设备组态"打开）；
2. 在右侧 **硬件目录**（Hardware Catalog）中搜索或展开找到：`DI → DI 16x24VDC BA`（16 点、24V 直流、基础型）；
3. 用鼠标把该模块**拖拽**到机架上 CPU 右侧的空闲槽位（槽2），松开鼠标；
4. 模块落位后，TIA 会自动给它分配默认地址，可在模块下方看到 `I0.0 ~ I1.7` 之类的字样。

同样方法，依次试试添加：

- `DQ → DQ 16x24VDC/0.5A BA` → 拖到槽3；
- `AI → AI 8xU/I HS` → 拖到槽4（可选，练习用）。

添加完成后机架效果：

```
 ┌──────────┬──────────┬──────────────┬──────────────┐
 │ 槽1      │ 槽2      │ 槽3          │ 槽4          │
 │ CPU      │ DI 16点  │ DQ 16点      │ AI 8通道     │
 │ 1511-1PN │ I0.0~I1.7│ Q0.0~Q1.7    │ (模拟量)     │
 └──────────┴──────────┴──────────────┴──────────────┘
```

> 删除模块：右键模块 → 删除；换槽位：直接拖动到新槽位即可。

### 4.3 数字量模块的后缀：BA / ST / HF 怎么选

硬件目录里同名模块常带不同后缀，代表性能档次：

| 后缀 | 档次 | 特点 | 适用 |
|------|------|------|------|
| BA（Basic） | 基础型 | 功能最少、价格最低，16 点/模块 | 一般开关量控制、教学首选 |
| ST（Standard） | 标准型 | 带诊断功能，可报断线等故障 | 需要诊断的中等要求场合 |
| HF（High Feature） | 高性能型 | 参数可组态性强、响应可调、支持等时模式 | 高端产线、精密控制 |

模拟量模块还有 HS（High Speed，高速）等后缀。**新手选 BA 系列**即可，功能完全够用，还和本课程变量表（I0.0~I2.x、Q0.0~Q0.4）的默认地址安排天然吻合。

### 4.4 模块地址的自动分配规则

TIA Portal 有一套"默认自动分配"规则，新手只需理解结论：

1. **按槽位顺序、从 0 开始分配**：CPU 右侧第一个信号模块（槽2）从地址 0 开始占址，第二个模块（槽3）接着往后排。
2. **数字量模块按实际点数分配**：16 点 DI 模块占用 2 个字节（16 个点位），如槽2 的 DI 占用 `I0.0~I1.7`；16 点 DQ 模块同理占用 `Q0.0~Q1.7`。具体分配的地址范围以 TIA Portal 中模块属性显示的为准。
3. **模拟量模块每通道 2 字节**：模拟量模块的默认地址通常从较高的固定区域开始（如 512），与数字量地址区相互独立、互不干扰。
4. **查看与修改**：单击模块 → 属性 → "地址"选项卡，可以看到默认地址；取消勾选"自动"后可手动指定。**新手强烈建议保持自动分配**，避免自己把地址改重叠了。

本课程的全套笔记统一使用如下地址（正好是默认分配的最前排地址）：

| 变量名 | 地址 | 说明 |
|--------|------|------|
| 启动按钮 | I0.0 | 数字量输入第 1 个点 |
| 停止按钮 | I0.1 | 数字量输入第 2 个点 |
| 热继电器 | I0.2 | 数字量输入第 3 个点 |
| 电机接触器（正转） | Q0.0 | 数字量输出第 1 个点 |
| 反转接触器 | Q0.1 | 数字量输出第 2 个点 |
| 报警灯 | Q0.2 | 数字量输出第 3 个点 |
| 蜂鸣器 | Q0.3 | 数字量输出第 4 个点 |
| 运行指示灯 | Q0.4 | 数字量输出第 5 个点 |

## 五、编译硬件组态（检查错误）

组态画完了，交卷之前要先"检查一遍卷子"，这个动作叫 **编译（Compile）**。编译时 TIA Portal 会检查：

- 模块之间有没有冲突（地址重叠、槽位超限）；
- 参数设置是否合法；
- （如果连程序一起编译）程序用到的地址是否超出模块范围。

### 编译步骤

1. 在项目树中右键点击 **PLC_1**；
2. 选择 **编译 → 硬件和软件（全部编译）**；
3. 观察下方的 **检查窗口（Inspect）**：

```
 检查窗口输出示例（正常）：
 ┌────────────────────────────────────────────┐
 │ ✓ 硬件   无错误，无警告（0 错误，0 警告）    │
 │ ✓ 软件   无错误，无警告                     │
 └────────────────────────────────────────────┘
```

- 出现 **红色错误**：必须修改后重新编译，直到 0 错误才能下载；
- 出现 **黄色警告**：可以下载，但建议点开看看原因。

> 也可以直接使用工具栏上的"编译"图标（一个带对勾的方块），编译当前选中的对象。养成习惯：**每次改动之后、每次下载之前，都先编译**。

### 编译报错示例与解读

```
 检查窗口（有错误时）：
 ┌────────────────────────────────────────────────────────────┐
 │ ✗ 硬件  PLC_1, 槽位 2, 模块 "DI 16x24VDC BA"               │
 │      消息: 地址 I0.0...I1.7 与模块 "DI 8x24VDC" 重叠        │
 │ ✗ 软件  Main [OB1], 网络 1:                                │
 │      消息: 地址 %I4.0 超出已组态模块的地址范围              │
 └────────────────────────────────────────────────────────────┘
```

读错误消息的三步法：

1. **看位置**：消息开头指明了出错对象（哪个 PLC、哪个槽位/哪个块哪个网络）；
2. **看关键词**："重叠" = 两个模块地址撞车，改地址或换槽位；"超出范围" = 程序用了模块上不存在的点，要么改程序地址，要么换更大点数的模块；
3. **双击消息**：TIA 通常会直接跳到出错位置，改完重新编译，直到 0 错误。

编译范围小知识：在项目树右键编译 PLC_1 会连硬件带程序全部编译；如果只改了程序，也可以只编译"程序块"节省时间；但**改过硬件组态后必须"硬件和软件"一起编**，否则一致性问题会留到下载时才爆出来。

## 六、下载硬件组态到 PLCSIM 仿真 PLC

本课程没有实物硬件，一切验证都在 **SIMATIC PLCSIM**（仿真软件）中完成。它相当于在你电脑里虚拟出一台 S7-1500，组态和程序都可以"下载"进去运行。

### 6.1 启动仿真 PLC

1. 在 TIA Portal 工具栏中点击 **启动仿真**（在线菜单 → 仿真 → 启动；工具栏上是一个圆形仪表盘样式的图标）；
2. 如果首次使用，系统会提示安装/启动 SIMATIC PLCSIM，按提示确认；
3. PLCSIM 窗口打开后，会询问装载方式，选择新建仿真项目或直接进入即可（V18/V20 界面略有差异，不影响流程）；
4. 保持 PLCSIM 窗口开着，**回到 TIA Portal**。

### 6.2 下载步骤

1. 在项目树中选中 **PLC_1**；
2. 点击工具栏 **下载到设备**（向下箭头进入芯片的图标），或菜单"在线 → 下载到设备"；
3. 首次下载会弹出 **"扩展的下载到设备"对话框**：
   - 接口类型：PN/IE（以太网）；
   - PG/PC 接口：选择带 PLCSIM 的虚拟接口（安装 PLCSIM 后系统会自动带上）；
   - 点击 **开始搜索**；
   - 搜索结果中出现 `PLC_1 [在线]`（目标子网显示为 PLCSIM），选中它；
4. 点击 **下载**；
5. 弹出 **装载预览** 对话框，确认信息后点击 **装载**；
6. 若提示"PLC 中已有数据将被覆盖/一致性下载需要停止 CPU"，选择 **全部装载 / 确认停止**；
7. 下载完成后，仿真 CPU 通常处于 **STOP** 状态：在 PLCSIM 的 CPU 面板上把运行开关切换到 **RUN**（面板上的 RUN 指示灯变黄→绿）；
8. 回到 TIA Portal，点击工具栏 **"在线"**（或"转到在线"），项目树中 PLC_1 旁边出现绿色小方块，表示在线成功。

```
 下载成功后项目树的样子：
 PLC_1 ■(绿色=在线)
 ├─ 硬件
 ├─ PLC_1 [CPU 1511-1 PN]
 │    ├─ 程序块
 │    │    └─ Main [OB1]
 │    └─ PLC 变量
 └─ 在线与诊断
```

> 以后每次修改了程序或组态，都要重复"编译 → 下载 → 切 RUN → 转在线"这套流程，请把它练成肌肉记忆。

### 6.3 下载失败的常见排查表

| 提示/现象 | 原因 | 解决办法 |
|-----------|------|---------|
| "未找到可装载的设备" | PLCSIM 没启动；或接口选错网卡 | 先启动仿真；接口选带 PLCSIM 的虚拟接口再搜索 |
| "存在不一致，无法下载" | 改动后没编译 | 先执行"编译 → 硬件和软件" |
| "检测到不支持的模块/固件" | 组态的模块或固件版本 PLCSIM 不支持 | 换成基础型模块（BA），或调整 CPU 固件版本 |
| "一致性下载需要停止 PLC" | 在线覆盖旧程序属正常提示 | 确认停止并全部装载 |
| 装载后 CPU 一直是 STOP | 下载后默认不自动启动 | 在 PLCSIM 面板手动切到 RUN |
| 转在线后全是灰色 | 实际未建立连接 | 检查"转到在线"按钮状态与在线连接配置 |

新手遇到下载问题，90% 落在前两行——先确认 PLCSIM 开着、先编译，再谈别的。

## 七、在线查看硬件状态

下载成功只是第一步，还要学会"体检"——在线查看硬件是否健康。

### 7.1 在线/离线符号速查

转到在线后，TIA Portal 用颜色和符号表达状态：

| 符号/颜色 | 含义 |
|-----------|------|
| 绿色实心方块 | 硬件与组态一致，模块正常，CPU 处于 RUN |
| 黄色/橙色 | 有警告，或 CPU 处于 STOP |
| 红色（方块/斜线） | 模块故障、组态与实际不符 |
| 灰色 | 未组态、无法诊断或该处没有模块 |

### 7.2 在设备视图中看模块状态

1. 项目树 → PLC_1 → **设备组态**，打开设备视图；
2. 点击工具栏 **在线/离线** 切换按钮（进入在线模式）；
3. 观察机架上的模块：正常时 CPU 和各模块显示绿色；如果某模块显示红色，点击它查看诊断信息。

### 7.3 在线与诊断工具

- 双击项目树中 PLC_1 下的 **在线与诊断**；
- 常用页面：
  - **诊断状态**：CPU 总体健康情况；
  - **诊断缓冲区**：CPU 的"病历本"，按时间记录每一次上电、停机、故障（排查疑难杂症的第一入口）；
  - **循环时间**：实际扫描周期有多长。

> 小技巧：故意在 PLCSIM 里把仿真 CPU 切到 STOP，再到"诊断缓冲区"看一眼记录，你就能读懂 CPU 的"日记"了。

### 7.4 诊断缓冲区长什么样

诊断缓冲区按时间倒序记录事件，最新的事件排在最上面。一条典型记录包含：时间戳、事件类型（信息/警告/错误）、事件描述：

```
 诊断缓冲区（示意）
 ┌──────────────────────────────────────────────────────────────┐
 │ 2026/01/15 14:32:05  ● 操作模式: 由 STOP 转为 RUN（暖启动）   │ ← 最新
 │ 2026/01/15 14:31:58  ● 装载存储器复位: 由软件触发             │
 │ 2026/01/15 14:31:40  ● 操作模式: 由 RUN 转为 STOP（下载所致） │
 │ 2026/01/15 14:30:12  ● 上电: CPU 启动                         │ ← 最早
 └──────────────────────────────────────────────────────────────┘
```

读缓冲区的方法：**从最新事件往回读，找到第一个"错误"级条目**，它通常就是停机的元凶；再往下是它的"前因"。真实项目中，"模块故障""组态不匹配""程序超时"等疑难问题，第一现场都在这里。

养成习惯：**每次 CPU 行为异常，第一步不是改程序，而是先转在线看诊断缓冲区。**

## 八、仿真环境中硬件组态的注意事项

在 PLCSIM 里做练习，和真实工程相比有几点特殊之处，务必心中有数：

1. **不需要真实硬件，但组态不能省。** PLCSIM 模拟的是 CPU 的"大脑"运行，程序照样要挂在组态好的设备上，下载流程一样都不能少。

2. **不需要真实接线。** 按钮、灯在仿真中用"仿真表/监控表"代替（后续章节详细讲），I0.0 的"1/0"由你在软件里手动改。

3. **IP 地址只是"形式上的"。** 仿真时不会真的走以太网，保持默认 192.168.0.1 即可，不会冲突；但下载对话框中的接口选择要正确（选 PLCSIM 虚拟接口）。

4. **模块型号要与仿真 CPU 匹配。** PLCSIM 支持 S7-1500 的绝大多数标准 CPU 和信号模块；个别工艺模块、安全模块、部分特殊功能卡仿真受限。如果下载时提示"模块不支持"，换成基础型模块（BA/HS 系列）即可。

5. **"非特定的 CPU"是仿真捷径。** 组态时若选了"非特定的 CPU"，下载时 PLCSIM 会自动匹配一个可用型号，适合快速练习；但组态具体型号更贴近工程习惯，课程两种都会演示。

6. **修改组态后必须重新编译 + 重新下载**，仿真 CPU 里的内容不会自动更新。

7. **仿真 CPU 断电不丢失**：关闭 PLCSIM 再打开，仿真项目仍在；但养成"改完即编译下载"的习惯最保险。

## 九、常见错误：IP 地址冲突、模块型号不匹配

这两个错误在真实工程中最常见，虽然仿真中较少遇到，但作为合格工程师必须提前认识。

### 9.1 IP 地址冲突

- **什么是冲突**：同一个以太网里有两台设备被配置了相同的 IP 地址（例如两台 PLC 都是 192.168.0.1，或 PLC 与编程电脑同 IP）。
- **典型现象**：下载/上载时搜索不到设备、时搜到时搜不到、通信频繁中断、程序监控数据乱跳。
- **排查方法**：
  1. 用电脑 `ping` 该 IP，观察是否时通时断；
  2. 用 TIA"扩展的下载到设备"对话框全网搜索，看同一 IP 是否出现两台设备（MAC 地址不同）；
  3. 临时断开其中一台，确认冲突方。
- **解决方法**：按网络规划表给每台设备唯一 IP；改完 IP 后设备需要重新下载组态（或用 Primary Setup Tool / CPU 面板按钮方式分配，本课程不展开）。
- **仿真提示**：PLCSIM 不真正走网络，通常不会冲突；若搜索不到 PLCSIM 中的 CPU，优先检查接口是否选了 PLCSIM 虚拟网卡。

### 9.2 模块型号不匹配

- **什么是不匹配**：组态里画的模块与真实/仿真 PLC 上实际的模块型号、订货号、固件版本对不上。
- **典型现象**：
  - 下载时一致性检查报错，无法下载；
  - 在线后模块显示"组态不匹配/已插入了错误的模块"（红色状态）；
  - CPU 报硬件故障，诊断缓冲区里记录槽位号和错误类型。
- **排查方法**：打开"在线与诊断 → 诊断缓冲区"，找到"哪个槽位的什么模块不符"；核对实际模块面板上的订货号（如 6ES7 ...），在硬件目录中按订货号重新选择组态。
- **解决方法**：按实际硬件订货号重新组态 → 编译 → 下载。
- **仿真提示**：若 PLCSIM 不支持某模块导致下载失败，替换为受支持的基础型模块。

### 9.3 其他高频小错误

| 错误 | 现象 | 解决 |
|------|------|------|
| 忘记编译就下载 | 提示"存在不一致/请先编译" | 先编译再下载 |
| 下载后忘了切 RUN | 程序在 CPU 里但一直 STOP，输出全 0 | PLCSIM 面板切到 RUN |
| 在线图标是灰色 | 看不到任何实时状态 | 点击"转到在线" |
| 槽位拖错/超限 | 编译报"无法放置" | 按目录允许的槽位重新拖放 |

## 📌 本章小结

1. 硬件组态就是在 TIA Portal 中画出控制系统的硬件图纸：CPU 型号、模块型号、槽位、地址、参数，它是程序的地基。
2. 添加设备的路径：**添加新设备 → 控制器 → SIMATIC S7-1500 → CPU 1511-1 PN**（新手推荐款）。
3. CPU 重点属性：IP 地址（仿真用默认 192.168.0.1）、时区（北京 +8）、启动方式（暖启动-RUN）、扫描周期监控时间（默认 150 ms）。
4. 四类信号模块：DI 接按钮开关、DQ 接灯和接触器、AI/AQ 处理连续量；数字量模块按实际点数分配地址，模拟量模块每通道 2 字节，地址自动从 0 开始按槽分配，新手保持默认。
5. 标准工作流：**组态 → 编译（0 错误）→ 下载到 PLCSIM → 切 RUN → 转在线 → 查看状态**。
6. 仿真环境无需真实硬件和接线，但组态、编译、下载一个都不能少。
7. IP 冲突 = 同网络同地址导致通信混乱；型号不匹配 = 组态与实际模块不符导致 CPU 报硬件故障。两者都要会认、会查、会改。

## ⚠️ 常见错误与注意事项

1. **不建项目/不组态直接想写程序**——程序必须挂在 PLC 设备下，先组态后编程。
2. **CPU 型号随意选**——工程中必须按实际订货号选型；仿真学习建议固定用 CPU 1511-1 PN，保证教程步骤可复现。
3. **改了组态不重新编译下载**——仿真 CPU 里跑的还是旧版本，现象会"莫名其妙"，务必改完就编译下载。
4. **下载后 CPU 停在 STOP 就以为程序没写对**——先检查 CPU 是否已切到 RUN，再看程序问题。
5. **手动改模块地址导致重叠**——例如把两个模块都改成从 0 开始，编译报地址重叠错误；新手请保持"自动分配"。
6. **IP 地址冲突在真实工程中的教训**——同一网络绝不允许两台设备同 IP；仿真中虽少见，但排查思路（ping、全网搜索、看 MAC）要掌握。
7. **模块型号不匹配仍强行下载**——CPU 会报硬件组态错误甚至停机；按订货号重新组态才是正解。
8. **忘记设置时区**——真实项目中报警时间戳会差 8 小时，排查记录时一头雾水。
9. **混淆"在线"与"离线"**——离线状态看到的是电脑里的程序，在线看到的才是 CPU 里正在跑的；诊断问题必须先"转到在线"。

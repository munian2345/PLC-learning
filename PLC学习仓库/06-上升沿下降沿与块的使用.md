# 06 上升沿、下降沿与功能块的初步使用

## 📖 学习目标

1. 理解上升沿（P）与下降沿（N）的概念，能看懂边沿检测的时序图；
2. 掌握 P/N 触点、P_TRIG/N_TRIG、R_TRIG/F_TRIG 的用法与区别；
3. 理解为什么需要边沿触发，能识别"不用边沿导致的经典错误"；
4. 初步认识功能块 FB/FC 与背景数据块（Instance DB），学会调用系统定时器、计数器；
5. 完成"按一次按钮切换灯状态"案例，并在 PLCSIM 中验证边沿触发效果。

## 一、先补一点基础：扫描周期与"一瞬间"

在学习边沿之前，先要弄清 PLC 的工作方式。PLC 并不是"看到输入一变就立刻反应"，而是**循环扫描**：每个扫描周期干三件事——

1. **读输入**：把所有输入端子的状态一次性读进来，存入"输入过程映像表"；
2. **算程序**：从第一条指令扫到最后一条，用输入映像表里的值算出结果；
3. **写输出**：把结果一次性送到输出端子。

然后从头再来。一个扫描周期通常只有几毫秒甚至更短，也就是说 CPU 每秒能把你的程序从头到尾执行成百上千遍。

所以对 PLC 来说：

- "信号是 1"，意思是"这个周期采样时它是 1"；
- "信号变了"，意思是"这个周期读到的值和上个周期不一样"。

**边沿，就是前后两个扫描周期读到的值不一样的那"一瞬间"。** 这一刻对人是转瞬即逝，对 PLC 来说却是一个实实在在的扫描周期——它可以在这一拍里"做一件事，只做一次"。

扫描周期的 ASCII 示意：

```
┌──────────────────────────────────────────────┐
│ ① 读输入：把所有输入端子状态刷新进输入映像表     │ ←──┐
│ ② 执行程序：从 OB1 第一条指令扫到最后一条        │    │ 一个扫描周期
│ ③ 写输出：把结果一次性送到输出端子               │ ───┘
└──────────────────────────────────────────────┘
        ↓ 立即开始下一个周期（循环往复，永不停歇）
```

边沿检测发生在第②步：程序里的每个 P/N 触点都拿"本周期读到的值"和"上周期存下来的值"比一比，不一样就是边沿。

## 二、什么是上升沿（P）与下降沿（N）

- **上升沿（P，Positive edge）**：信号从 0 跳变到 1（0→1）的那一瞬间。
- **下降沿（N，Negative edge）**：信号从 1 跳变到 0（1→0）的那一瞬间。

用文字描述时序：信号一开始为 0；某个时刻它跳到 1——这一跳就是**上升沿**；它保持 1 一段时间；然后跳回 0——这一跳就是**下降沿**。

ASCII 时序图：

```
输入信号
 1        ┌──────────┐             ┌───────►
          │          │             │
 0 ───────┘          └─────────────┘
           ▲          ▲             ▲
           │          │             │
        上升沿P     下降沿N       上升沿P
        （0→1）    （1→0）       （0→1）
```

关键概念：**边沿是"一瞬间"，它对应的输出脉冲只持续一个扫描周期。** PLC 检测到边沿后，会输出一个宽度仅为一个扫描周期的短脉冲：

```
输入信号            ┌────────────┐
              ──────┘            └─────────────

P 触点的输出         ┌┐
              ──────┘└──────────────────────────  ← 只在 0→1 瞬间接通 1 个扫描周期

N 触点的输出                      ┌┐
              ────────────────────┘└────────────  ← 只在 1→0 瞬间接通 1 个扫描周期
```

生活化类比：上升沿相当于"**进门的那一瞬间**"，下降沿相当于"**出门的那一瞬间**"。人一直待在屋里（信号保持 1）并不等于"进门"这个动作——动作只发生一次。边沿指令就是专门捕捉"动作"而不是"状态"的。

### 哪些场合该用哪种边沿

| 场景 | 推荐指令 | 理由 |
|---|---|---|
| 按钮按下做一次动作（启动、计数、切换） | P 触点 | 只认按下瞬间 |
| 按钮松开做一次动作（如"松手才确认"） | N 触点 | 认松开瞬间 |
| 几个条件同时满足的瞬间报一次信号 | P_TRIG | 盯的是组合逻辑的整体 |
| 设备停下来的瞬间做善后（记录停机时刻） | N 触点 / N_TRIG | 捕捉运行→停止的边沿 |
| 在 FC/FB 内部检测边沿 | R_TRIG / F_TRIG | 不占用全局 M 位，块更独立 |

## 三、为什么需要边沿触发？不用边沿会遇到什么问题？

PLC 每秒扫描成百上千次。你"按一下按钮"，对人来说是 0.3~0.5 秒，对 PLC 来说却是**几百个扫描周期的"一直按着"**。如果我们想表达"按一次做一次"，就必须用边沿。

**问题例子 1——数数变多了**：想统计按钮被按下的次数，若用普通触点直接去触发计数，按住 0.5 秒会被统计成几百次，而不是一次。

**问题例子 2——切换逻辑发疯**：想"按一次灯亮、再按一次灯灭"，用普通触点写出来的电路，在按住期间每个扫描周期都翻转一次状态，灯会以肉眼可见的"狂闪"方式抖动，松手时停在哪边完全随机（第六节反面教材详细分析）。

**问题例子 3——动作语义丢失**：例如"按一次确认键消音""每来一个产品做一次记录"，本质都是"事件"，不是"状态"。不用边沿，程序就没有"事件"的概念。

一句话总结：**边沿触发把"电平（状态）"变成"动作（事件）"——不管你按多久，只认变化的那一瞬间一次。**

**问题例子 4——正反转误切换**：想"按一次按钮让电机在正转/反转之间切换"，若不用边沿，按住按钮期间两个接触器会以扫描周期级速度反复切换——仿真里只是灯乱闪，真设备上就是严重事故隐患。凡是"按一次 = 一次动作"的需求，统统要先过边沿这一关。

## 四、TIA Portal 中的边沿检测方式

### 4.1 P 触点 / N 触点（检测某个操作数的边沿）

在指令面板 →"基本指令"→"位逻辑运算"里可以找到：

- `--|P|--`：扫描操作数的**信号上升沿**；
- `--|N|--`：扫描操作数的**信号下降沿**。

```
        I0.0
      ----|P|----
        M1.0
```

说明：

- 触点**上方**填**被检测的操作数**（例如 I0.0）；
- 触点**下方**必须填一个**边沿存储位**（用一个空闲的 M 位，例如 M1.0）。PLC 靠它记住"上个扫描周期这个信号是几"；
- 工作过程：本周期信号 = 1，而存储位（上周期存下来的值）= 0 → 判定为上升沿 → 触点导通一个扫描周期，同时把当前值 1 写入存储位；
- **每个 P/N 触点必须独占一个边沿存储位**，绝对不能两个触点共用同一个 M 位，否则互相覆盖，边沿检测会错乱；
- N 触点同理，只是判定方向相反（1→0）。

**P 触点工作过程逐周期推演**（检测 I0.0，边沿存储位 M1.0）：

| 扫描周期 | I0.0 本周期值 | M1.0（上周期存的值） | 判定 | P 触点导通？ | 本周期结束时 M1.0 |
|---|---|---|---|---|---|
| 1 | 0 | 0 | 无变化 | 否 | 0 |
| 2 | 1 | 0 | 0→1，上升沿！ | **是** | 1 |
| 3 | 1 | 1 | 无变化 | 否 | 1 |
| 4 | 1 | 1 | 无变化（一直按住） | 否 | 1 |
| 5 | 0 | 1 | 1→0，下降沿 | 否（P 不动作） | 0 |
| 6 | 1 | 0 | 又一个上升沿！ | **是** | 1 |

看第 3、4 行：按住不放期间，存储位已经是 1，与本周期值相同，不再判定为边沿——这就是"只认动作一次"的内部原理。存储位就像一本"上期值备忘录"，每个 P 触点必须有自己专属的一本。

### 4.2 P_TRIG / N_TRIG（检测一段逻辑结果的边沿）

P_TRIG 是一个功能框，它检测的不是一个单独的操作数，而是**流入它的能流**（即前面触点串并联后的逻辑结果，也叫 RLO）：

```
     启动条件        运行允许       +-------------+
      M0.0           I0.2          |   P_TRIG    |
   ----| |------------| |-----------+CLK       Q  +----( )----  M0.5
                                    | M_BIT:M1.0  |
                                    +-------------+
```

- 当"启动条件 与 运行允许"这个**组合结果**从 0→1 的瞬间，Q 输出一个扫描周期的脉冲；
- P_TRIG / N_TRIG 同样需要各自的边沿存储位（M_BIT）；
- 与 P 触点的区别一句话：**P 触点盯"某个点"，P_TRIG 盯"一段逻辑"。**

以最简单的 `I0.0 常开触点 → P_TRIG → 输出` 为例，逐周期看它的判断过程：

| 扫描周期 | I0.0 | P_TRIG 的输入（RLO） | M_BIT（上周期存的 RLO） | Q 输出 |
|---|---|---|---|---|
| 1 | 0 | 0 | 0 | 0 |
| 2 | 1 | 1 | 0 | **1（仅此一个周期）** |
| 3 | 1 | 1 | 1 | 0 |

和 P 触点一样，秘密全在"上周期存的值"上：一旦记忆跟上现实，就不再判定为边沿。

### 4.3 R_TRIG / F_TRIG（背景DB版边沿检测）

R_TRIG（上升沿）/ F_TRIG（下降沿）是**功能块 FB**，边沿记忆存在它自己的**背景DB**里，不需要 M 位：

```
                                    +-------------+
        I0.0                       |  R_TRIG_1   |
      ----| |----------------------+CLK       Q  +----( )----  M0.5
                                    +-------------+
```

- 第一次拖入时会弹出"调用选项"对话框，让你命名并自动生成背景DB（例如 R_TRIG_1）；
- 因为不占用全局 M 位，在 FC/FB 内部做边沿检测时特别方便（FB/FC 内部应尽量避免直接使用全局 M 位，这是好习惯）。

### 4.4 六种边沿指令对比表

| 指令 | 形式 | 检测对象 | 边沿记忆放哪 | 特点 |
|---|---|---|---|---|
| P 触点 | 触点 | 单个操作数 | 1 个 M 位 | 最常用，监控单个信号 |
| N 触点 | 触点 | 单个操作数 | 1 个 M 位 | 下降沿版本 |
| P_TRIG | 功能框 | 前级逻辑（RLO） | 1 个 M 位 | 检测组合条件整体 |
| N_TRIG | 功能框 | 前级逻辑（RLO） | 1 个 M 位 | 下降沿版本 |
| R_TRIG | FB（需背景DB） | CLK 输入 | 背景DB内部 | 不占 M 位，适合块内使用 |
| F_TRIG | FB（需背景DB） | CLK 输入 | 背景DB内部 | 下降沿版本 |

## 五、功能块（FB/FC）初步使用

### 5.1 为什么需要功能块——代码复用

定时器、计数器这类功能，几乎每个程序都要用，用法也一模一样。如果每个人都从零写一遍，既费时又容易出错。西门子把这些常用功能做成**功能块（FB）**：写好、测好、封装好，我们"拿来就调"。

类比理解：

- 功能块像**模具**：模子做好后，压一次出一个零件；
- 像**预制菜谱**：步骤标准化，谁做味道都一样；
- 你自己写的常用逻辑（比如"一台电机的启停保"）也可以封装成 FB，十台电机调用十次，只写一次代码——这就是**代码复用**。

FB 和 FC 的初步区别：

- **FC（函数 Function）**：没有自己的"记忆"，给它什么就按什么算，像一台计算器；
- **FB（功能块 Function Block）**：带一块"私人记忆"（背景DB），同一个 FB 调用多次，每次调用都有自己独立的记忆，像每个车间各配一本记录本。

本课程的定时器 TON/TOF/TP/TONR、计数器 CTU/CTD/CTUD 全部都是 FB。

| 对比项 | FC 函数 | FB 功能块 |
|---|---|---|
| 有无记忆 | 无（没有背景DB） | 有（每个实例一个背景DB） |
| 静态数据 | 不能保存 | 可以（存放在背景DB中） |
| 典型用途 | 数据换算、公式计算、文本处理 | 定时器、计数器、电机控制等需要"记住状态"的功能 |
| 类比 | 计算器：给数就算 | 带记录本的工人：干完活还要记一笔 |

现阶段只需记住：**要"记忆"就用 FB，纯"计算"就考虑 FC**。

### 5.2 如何调用系统功能块（以定时器为例）

1. 打开 OB1（LAD 编辑器），在右侧"指令"面板展开"基本指令 → 定时器操作"；
2. 把 TON 拖到网络中；
3. 此时会自动弹出**"调用选项"对话框**（示意图，版本不同外观略有差异）：

```
调用选项
┌──────────────────────────────────────┐
│  ● 单个实例      ○ 多重实例           │
│  名称：  [TON_闪烁1      ]           │
│  数据类型： IEC_TIMER                 │
│  号码：  [自动]                       │
│             [确定]      [取消]        │
└──────────────────────────────────────┘
```

4. 给实例起一个**见名知义的中文名**（本课程约定如 TON_闪烁、TON_延时启动、CTU_产品计数），点"确定"；
5. TIA 自动生成一个背景DB（项目树 →"程序块 → 数据块"里能看到），梯形图上的定时器框也长好了引脚（IN、PT、Q、ET），把实参填上即可。

计数器 CTU/CTD/CTUD 的调用方法完全相同，下一章（第 7 章）专门展开。

补充两个小概念：

- **调用选项里的"单个实例 / 多重实例"**：单个实例会生成一个独立的背景DB（本课程统一用这种，最直观）；多重实例不单独生成DB，而是把数据放进调用者自己的背景DB里，属于进阶用法，现阶段一律选"单个实例"；
- **块的调用层级**：CPU 上电后只自动执行 OB1（主程序），我们程序里的 FB/FC 都是被 OB1（或别的块）"调用"了才会运行。定时器、计数器是系统提供的 FB，由我们来调；将来你也能把自己的常用逻辑封装成 FB/FC 去调用，道理完全一样。

### 5.3 背景数据块（Instance DB）

**背景DB 就是这次调用的 FB 的"私人储物柜"**，里面存放这个实例的全部内部数据。对 TON 来说，存的是 PT（预设时间）、ET（当前计时值）、Q（输出）等。

三个要点：

- **一次调用一个柜子**：每调用一次 FB，就需要一个新的背景DB。两个 TON 共用一个背景DB → 数据互相覆盖 → 定时互相干扰，这是新手最常见的大坑之一；
- **自动生成**：背景DB 不是你手工建的，而是在"调用选项"对话框里填了名字后，由 TIA 自动创建并管理；
- **可以在线监视**：监控表里直接输入"TON_闪烁1.ET"就能看到当前计时值，非常方便调试。

### 5.4 形参与实参的初步概念

- **形参（形式参数）**：功能块定义里的"引脚名"，比如 TON 的 IN、PT、Q、ET。它只是"孔位"，本身没有具体值；
- **实参（实际参数）**：调用时你接到引脚上的**具体变量或数值**，比如 IN 接 I0.0、PT 填 T#1s。这才是真正"插上的电器"。

以定时器 TON_闪烁1 为例（示意）：

| 形参 | 引脚类型 | 本例的实参 | 含义 |
|---|---|---|---|
| IN | 输入 | M0.0 故障记忆 | 计时允许信号 |
| PT | 输入 | T#1s | 预设时间 |
| Q | 输出 | M0.1 闪烁方波 | 到时输出 |
| ET | 输出 | （可悬空不接） | 当前已计时值 |

类比：形参是插座上的孔位，实参是你插上去的插头。同一个插座（FB 定义），今天插台灯（I0.0），明天插风扇（另一个信号），用法不变、对象随选。

## 六、完整案例：按一次按钮切换灯状态

### 6.1 需求与 I/O 分配

**需求**：按一下按钮灯亮，再按一下灯灭，如此往复（俗称"交替/Toggle"）。

| 名称 | 地址 | 数据类型 | 说明 |
|---|---|---|---|
| 切换按钮 | I0.0 | Bool | 每按一次切换一次灯的状态 |
| 灯 | Q0.0 | Bool | 被切换的灯 |
| 按钮脉冲 | M0.0 | Bool | 按钮上升沿产生的一个扫描周期脉冲 |
| 边沿存储位 | M1.0 | Bool | 网络段1 中 P 触点专属的边沿记忆位 |

### 6.2 梯形图（逐网络段分析）

**网络段1：捕捉按钮上升沿，产生一个扫描周期的"按钮脉冲"**

```
       切换按钮 I0.0              按钮脉冲
         ----|P|------------------( )----  M0.0
         边沿存储位 M1.0
```

文字分析：

- I0.0 从 0→1 的瞬间，P 触点导通**一个扫描周期**，把 M0.0 点亮一拍，随后 M0.0 自动回 0；
- 触点上方填被检测信号 I0.0，下方填边沿存储位 M1.0——这个 M1.0 只属于本触点，程序里其他触点不得再用它；
- 如果把程序下载后一直按住按钮，M0.0 也只在按下的第一个周期为 1，之后一直是 0——这就是"只认动作、不认状态"。

**网络段2：用脉冲切换灯（单线圈写法，无竞态问题）**

```
       按钮脉冲          灯
         M0.0           Q0.0
  +------| |------------|/|------+
  |                              |
--+                              +----( )----  Q0.0 灯
  |    按钮脉冲          灯      |
  |      M0.0           Q0.0     |
  +------|/|------------| |------+
```

文字分析——这条网络里藏着三条"路"：

- **点亮路（上分支）**：脉冲出现（M0.0=1）且灯原来是灭的（Q0.0 常闭通）→ 灯亮；
- **自保持路（下分支）**：没有脉冲（M0.0 常闭通）且灯原来是亮的（Q0.0 常开通）→ 灯自己保持自己，继续亮；
- **熄灭**：脉冲出现且灯原来是亮 → 上分支被 Q0.0 常闭切断，下分支被 M0.0 常闭切断 → 两条路都断 → 灯灭。

**为什么用单线圈而不是"置位+复位"？** 如果写成两个网络分别 (S) 和 (R) 同一个输出，在按下瞬间它们会在**同一个扫描周期**里先后执行：先执行的网络改了 Q0.0，后执行的网络读到的已经是新值，结果会互相"打架"，灯永远切不动。单线圈写法两条分支用的是"本周期开始时"的同一个旧状态，天然没有竞态。

逐周期推演表：

| 时刻 | M0.0 | Q0.0（周期开始时） | 哪条路通 | Q0.0（周期结束后） |
|---|---|---|---|---|
| 平时 | 0 | 0 | 无 | 0 |
| 第 1 次按下瞬间 | 1 | 0 | 点亮路 | 1 |
| 按住不放 | 0 | 1 | 自保持路 | 1 |
| 松开 | 0 | 1 | 自保持路 | 1 |
| 第 2 次按下瞬间 | 1 | 1 | 全断 | 0 |
| 按住不放 | 0 | 0 | 无 | 0 |

关键：因为用了 P 触点，"按下瞬间"只发生**一个**扫描周期，之后 M0.0 立刻回 0，由自保持路维持——灯稳稳地亮着，绝不闪烁。

顺带一提：网络段2 的逻辑在数字电路里叫"异或（XOR）"——"脉冲"与"灯状态"相异时灯亮（有脉冲且灯灭 → 点亮；无脉冲且灯亮 → 保持亮），相同时灯灭（有脉冲且灯亮 → 熄灭）。现在不必深究术语，记住这个模式叫"**脉冲 + 自保持切换**"即可，它在按钮切换类程序里出场率极高。

### 6.3 反面教材：把 P 触点换成普通触点会怎样？

```
       切换按钮 I0.0       灯 Q0.0
  +------| |------------|/|------+
  |                              |
--+                              +----( )----
  |    切换按钮 I0.0       灯 Q0.0|
  +------|/|------------| |------+
```

按住按钮不放时，每个扫描周期都会：周期 1 点亮 → 周期 2 两条路全断、熄灭 → 周期 3 又点亮……以毫秒级速度反复翻转。肉眼看是灯"狂闪"，而松手的一瞬间停在哪边完全随机——这就是没有边沿意识的经典错误。这也解释了第三节"为什么需要边沿触发"。

### 6.4 另一种写法：P_TRIG 版的网络段1

如果想检测的是"一段组合逻辑"的边沿（这里虽然只有一个触点，写法是通用的）：

```
                                     +-------------+
       切换按钮 I0.0                 |   P_TRIG    |
     ----| |------------------------+CLK       Q  +----( )----  M0.0 按钮脉冲
                                     | M_BIT:M1.0  |
                                     +-------------+
```

效果与 P 触点版完全相同。只检测一个信号时用 P 触点更简洁；要检测多个触点的组合条件时，用 P_TRIG。

### 6.5 再一种写法：R_TRIG 版（背景DB版）

```
                                     +-------------+
       切换按钮 I0.0                 |  R_TRIG_1   |
     ----| |------------------------+CLK       Q  +----( )----  M0.0 按钮脉冲
                                     +-------------+
```

首次插入 R_TRIG 时同样会弹出"调用选项"对话框，命名 R_TRIG_1 并自动生成背景DB。它**不需要边沿存储位 M1.0**，边沿记忆存在自己的背景DB里，因此在 FC/FB 内部使用时更规范。三种写法（P 触点 / P_TRIG / R_TRIG）在本案例中效果完全一样，选择依据见 4.4 对比表：单个信号用 P 触点最省事，组合逻辑用 P_TRIG，块内使用用 R_TRIG。

## 七、PLCSIM 仿真验证步骤

### ① 需建立的变量清单

| 名称 | 地址 | 数据类型 | 用途 |
|---|---|---|---|
| 切换按钮 | I0.0 | Bool | 监控表修改，模拟按下/松开 |
| 灯 | Q0.0 | Bool | 观察切换结果 |
| 按钮脉冲 | M0.0 | Bool | 监视（瞬时脉冲，可能看不清，属正常） |
| 边沿存储位 | M1.0 | Bool | 监视（它的值始终跟随 I0.0 上个周期的状态） |

### ② 启动仿真并下载程序的步骤

1. 程序编写完成后保存项目，对 PLC_1 执行"编译 → 软件（全部编译）"，确认 0 错误；
2. 点击工具栏"启动仿真"，PLCSIM 打开后选择 SIMATIC S7-1500 系列 CPU；
3. 在 TIA 项目树选中 PLC_1，点"下载到设备"（硬件和软件）；
4. "装载预览"中点"装载"，按提示停止并"全部启动"模块；
5. 把 PLCSIM 中的 CPU 切到 RUN，TIA 右上角出现在线绿色标记。

### ③ 用监控表模拟输入信号

1. 新建监控表"边沿测试"，把 ① 中变量拖入；
2. 点"监视"（眼镜图标）进入在线状态；
3. 模拟"按一下"：I0.0 行"修改"列输入 1 → 点"修改"；过约 1 秒再输入 0 → 点"修改"。这一置一回就等价于一次完整的按压；
4. 想"按住不放"，就把 I0.0 一直保持为 1，观察几秒再松开。

> 同样，也可以直接在 PLCSIM 窗口的 SIM 表格里勾选 I0.0 复选框来模拟按压，效果一致。强烈建议专门做一次"按住不放"实验：把 I0.0 勾上保持三五秒，观察 Q0.0 纹丝不动地稳定亮着——亲眼见过这一次，你就真正理解了边沿触发的价值。

### ④ 预期结果

- 初始 Q0.0 = 0；
- I0.0 第一次 0→1：Q0.0 变为 1；M0.0 仅在按下瞬间为一个扫描周期的 1（监控表刷新很快，可能来不及看到它变 1，属正常）；
- **I0.0 一直保持 1（按住不放）几秒钟：Q0.0 稳定为 1，绝不闪烁**——这是边沿触发生效的铁证；
- I0.0 回 0（松开）：Q0.0 保持 1；
- I0.0 再次 0→1：Q0.0 变 0；再按一次又变 1，如此往复；
- M1.0 的值始终与 I0.0 一致（它存的就是上一周期的信号状态）。

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 按下按钮灯毫无反应 | P 触点没填边沿存储位（编译应已报错）；网络段2 触点开闭写反 | 检查 M1.0 是否填写；核对网络段2 |
| 灯狂闪、结果随机 | 误用了反面教材的普通触点版本 | 把网络段1 换回 P 触点 |

| 编译报"双线圈" | Q0.0 在其他网络也被普通线圈输出 | 全程序检查，Q0.0 只在网络段2 输出 |

| 按一次灯切换了两次 | 监控表修改 I0.0 时手滑多翻一次；P 触点存储位被其他触点共用 | 小步操作，一次只改一个值；确认 M1.0 专属 |

## 📌 本章小结

- 边沿 = 前后两个扫描周期信号状态不同的"那一瞬间"：**上升沿 P 是 0→1，下降沿 N 是 1→0**，对应的输出只持续一个扫描周期；
- PLC 把"按住"看成"几百个周期连续接通"，想表达"按一次做一次"就必须用边沿；
- TIA 中的边沿工具：**P/N 触点**（盯单个操作数，需 M 存储位）、**P_TRIG/N_TRIG**（盯一段组合逻辑，需 M 存储位）、**R_TRIG/F_TRIG**（FB，记忆在背景DB，不占 M 位）；
- FB 是带"私人记忆"（背景DB）的复用块，FC 是不带记忆的函数；定时器/计数器都是 FB，调用时通过"调用选项"对话框自动生成背景DB，**一次调用一个实例**；
- 形参是引脚孔位，实参是接上去的具体变量；
- 切换类逻辑推荐"单线圈 + 自保持"写法，避免同一扫描周期内置位/复位打架。

## ⚠️ 常见错误与注意事项

1. **边沿存储位必须独占**：每个 P/N 触点用自己专属的 M 位，两个触点共用一个 M 位会导致边沿检测错乱。选用 M 位时挑"程序里没被别处使用"的。
2. **P 触点上下参数别填反**：上面是被检测的信号（如 I0.0），下面是边沿存储位（如 M1.0）。
3. **切换逻辑别用"先 (S) 后 (R)"两个网络**：同一扫描周期内后执行的网络会读到前一个网络刚写入的新值，互相打架。用本案例的单线圈写法。
4. **同一个输出不要双线圈**：一个输出在程序里只用一个普通线圈（分支可以并联）；需要置位/复位语义时统一用 (S)/(R)。
5. **一个 FB 一个背景DB**：多个定时器/计数器共用一个背景DB是严重错误，数据会互相覆盖。
6. **P_TRIG 与 P 触点分工**：检测单个信号用 P 触点；检测"几个触点组合后"的边沿用 P_TRIG。
7. **瞬时脉冲看不见很正常**：M0.0 这类只亮一个扫描周期的中间变量，在监控表里通常捕捉不到变化，不代表程序错误。
8. **不要滥用全局 M 位**：在 FB/FC 内部优先使用 R_TRIG/F_TRIG 或块内变量做边沿记忆，保持块的可移植性。

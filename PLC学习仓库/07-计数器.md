# 07 计数器：让 PLC 学会"数数"

## 📖 学习目标

1. 理解计数器的作用与工作原理，建立"脉冲—当前值—预设值—输出"的整体概念；
2. 掌握三种 IEC 计数器 CTU、CTD、CTUD 的引脚与工作逻辑，能看懂它们的时序；
3. 学会选择计数器背景DB的数据类型（CSInt/CInt/CDInt 等），理解取值范围的影响；
4. 掌握计数器的复位方法，理解计数与上升沿配合时"多计/漏计"的原因与对策；
5. 完成案例"产品计件到 100 个自动停线"，并在 PLCSIM 中验证。

## 一、计数器的作用和原理

定时器解决的是"**等多久**"的问题，计数器解决的是"**数多少个**"的问题。工业现场到处都在数数：

- 流水线上数**产品个数**：够 100 个装箱、停线；
- 仓库里数**入库托盘**：数够一垛通知叉车；
- 设备上数**动作次数**：模具冲压 10 万次提示保养；
- 包装机上数**袋数**：数到 50 袋自动封箱。

### 1.1 计数器的三要素

把计数器想象成一位站在流水线旁的**检票员**：

- **计数脉冲输入**：每过来一个"人"（信号出现一次上升沿），他就在小本上划一笔；
- **CV（当前计数值）**：小本上已经划了几笔；
- **PV（预设值）**：票卖到多少张为止（目标值）；
- **Q（输出）**：达到目标后举起的旗子（CV 与 PV 比较的结果）。

### 1.2 计数的原理：数的是"上升沿"，不是"电平"

计数器数的不是"信号是几"，而是"信号**从 0 变成 1** 的次数"。也就是说，**每个计数输入内部自带上升沿检测**：信号从 0 跳到 1 一次，计数值加（或减）1；信号一直是 1，也只算一次。

这就带来两个重要推论：

1. 按住按钮不放，计数值只加 1——必须**松开再按**才会计下一次；
2. 信号质量很关键：抖动会产生多个假上升沿（多计），太窄的脉冲可能根本采不到（漏计）。详见第六、八节。

### 1.3 定时器与计数器对照

| 对比项 | 定时器 TON | 计数器 CTU |
|---|---|---|
| 数什么 | 数时间的流逝 | 数外部信号的上升沿个数 |
| 输入 | IN（计时允许） | CU（计数脉冲） |
| 当前值 | ET（已计时时间） | CV（已计数个数） |
| 目标值 | PT（预设时间） | PV（预设个数） |
| 输出 | Q：计时到则为 1 | Q：CV≥PV 则为 1 |
| 清零方式 | IN 断开自动回 0 | 必须用 R 引脚复位 |
| 共同点 | 都是 FB，都要背景DB，一次调用一个实例 | 同左 |

可以看出两者结构非常相似：ET 对应 CV，PT 对应 PV，一个"数时间"、一个"数事件"。学定时器时建立的概念几乎可以平移过来理解计数器。

## 二、三种 IEC 计数器

S7-1500 使用 IEC 标准计数器，共三种：**CTU**（加计数）、**CTD**（减计数）、**CTUD**（加减计数）。它们都是功能块（FB），调用时需要背景DB（第 6 章已讲过概念）。

### 2.1 CTU 加计数器（Count Up）

**引脚说明：**

| 引脚 | 类型 | 作用 |
|---|---|---|
| CU | Bool 输入 | 加计数脉冲输入，每个上升沿 CV 加 1 |
| R | Bool 输入 | 复位输入，R=1 时 CV 清 0（优先级最高） |
| PV | 整数 | 预设值（计数目标） |
| Q | Bool 输出 | CV ≥ PV 时为 1 |
| CV | 整数输出 | 当前计数值 |

**工作逻辑（按优先级）：**

1. R = 1 时：CV = 0（复位优先，CU 此时不计数）；
2. R = 0 时：CU 每来一个上升沿，CV 加 1，一直加到**该数据类型的上限**为止（如 CInt 上限为 32767）；
3. Q 是一个**比较结果（电平）**：只要 CV ≥ PV，Q 就是 1；CV 回落到 PV 以下（或复位后），Q 变回 0。

⚠️ 特别注意：**CV 不会自动停在 PV**！PV 只是 Q 比较的门槛，不是计数的终点。这是新手最常见的误解。

**时序描述（PV = 3）：**

```
CU        ┌─┐     ┌─┐     ┌─┐     ┌─┐
       ───┘ └─────┘ └─────┘ └─────┘ └────────►
           ①      ②      ③      ④
                                              （R 一直为 0）

CV   0    1       2       3       4   ……
                                            ↑
                         到达 PV 后 Q 变 1，但 CV 继续增加，
                         一直数到数据类型上限（CInt 为 32767）

Q    0    0       0       1       1   ……    （CV ≥ PV=3 → 1，并保持）
```

分步状态表：

| 时刻 | 动作 | CV | Q（CV≥PV?） |
|---|---|---|---|
| 初始 | —— | 0 | 0 |
| 第 1 个上升沿 | +1 | 1 | 0 |
| 第 2 个上升沿 | +1 | 2 | 0 |
| 第 3 个上升沿 | +1 | 3 | **1**（达标） |
| 第 4 个上升沿 | +1（不会停在 PV） | 4 | 1（仍达标） |
| R 置 1 | 清零 | 0 | 0 |

### 2.2 CTD 减计数器（Count Down）

**引脚说明：**

| 引脚 | 类型 | 作用 |
|---|---|---|
| CD | Bool 输入 | 减计数脉冲输入，每个上升沿 CV 减 1 |
| LD | Bool 输入 | 装载输入，LD=1 时把 PV 装入 CV |
| PV | 整数 | 预设值（这里实际是"起始值"） |
| Q | Bool 输出 | CV ≤ 0 时为 1 |
| CV | 整数输出 | 当前计数值 |

**工作逻辑（按优先级）：**

1. LD = 1 时：CV = PV（把"起始值"装进去，相当于倒计时的"预备——开始前拨到起点"）；
2. LD = 0 时：CD 每来一个上升沿，CV 减 1，减到该数据类型的下限为止；
3. Q：CV ≤ 0 时为 1。

⚠️ 常见坑：**CTD 上电后如果从未用 LD 装载，CV 从 0 开始 → CV ≤ 0 成立 → Q 一上电就是 1**。所以用 CTD 时通常先用 LD 装载 PV 再开始减。

**时序描述（PV = 3）：**

```
LD        ┌──┐
       ───┘  └─────────────────────────────►   LD=1 那一刻：CV ← PV=3

CV   0    3       2       1       0    0 ……
                  ←      ←      ←
                        （每个 CD 上升沿减 1）

Q    1    0       0       0       1    1 ……   （CV ≤ 0 → 1）
                                              ↑
                                    减到 0 后 Q=1 并保持

CD              ┌─┐     ┌─┐     ┌─┐
       ─────────┘ └─────┘ └─────┘ └────────►
                   ①      ②      ③
```

生活类比：CTD 像**火箭发射倒计时**：先把秒表拨到 10（LD 装载），然后每过一秒减 1（CD 脉冲），减到 0（Q=1）点火！

### 2.3 CTUD 加减计数器（Count Up/Down）

CTUD 是前两者的合体，既能加也能减，适合"有进有出"的场景（如车库：进一辆 +1，出一辆 −1，剩余车位数一目了然）。

**引脚说明：**

| 引脚 | 类型 | 作用 |
|---|---|---|
| CU | Bool 输入 | 加计数脉冲，上升沿 CV 加 1 |
| CD | Bool 输入 | 减计数脉冲，上升沿 CV 减 1 |
| R | Bool 输入 | 复位：R=1 时 CV = 0（优先级最高） |
| LD | Bool 输入 | 装载：LD=1 时 CV = PV（优先级低于 R） |
| PV | 整数 | 预设值 |
| QU | Bool 输出 | CV ≥ PV 时为 1（"达到上限方向的目标"） |
| QD | Bool 输出 | CV ≤ 0 时为 1（"减到零"） |
| CV | 整数输出 | 当前计数值 |

**工作逻辑：**

1. R = 1 → CV = 0（R 比 LD 优先）；
2. 否则 LD = 1 → CV = PV；
3. 否则 CU 上升沿使 CV 加 1（到上限为止），CD 上升沿使 CV 减 1（到下限为止）；若 CU 与 CD 在同一个扫描周期都有上升沿，两效果抵消，CV 不变；
4. QU = (CV ≥ PV)，QD = (CV ≤ 0)。

车库类比：CU 是入口地感线圈，CD 是出口地感线圈，PV 是总车位数，QU 表示"停满了"，QD 表示"空了"。

**CTUD 时序示意（PV = 3，先加后减）：**

```
CU        ┌─┐     ┌─┐     ┌─┐
       ───┘ └─────┘ └─────┘ └────────────►    加了 3 次
CD                                    ┌─┐
       ───────────────────────────────┘ └────►  减了 1 次
R/LD  ─────────────────────────────────────────  （一直为 0）

CV   0    1       2       3       2   ……
                                     ↑ 减 1

QU   0    0       0       1       1   ……    （CV≥PV=3 → 1）
QD   0    0       0       0       0   ……    （CV≤0？否 → 0）
```

若再连续按 3 次 CD 减到 0，QD 就会变 1——两个输出各管一头，互不冲突。

## 三、引脚详解总表

| 引脚 | 出现于 | 类型 | 作用 | 优先级备注 |
|---|---|---|---|---|
| CU | CTU、CTUD | Bool 输入 | 加计数：上升沿 CV+1 | 与 CD 同拍时抵消 |
| CD | CTD、CTUD | Bool 输入 | 减计数：上升沿 CV−1 | 与 CU 同拍时抵消 |
| R | CTU、CTUD | Bool 输入 | 复位：CV 清 0 | **最高**，压过 CU/LD |
| LD | CTD、CTUD | Bool 输入 | 装载：CV ← PV | 低于 R |
| PV | 三种都有 | 整数 | 预设值 | CTU 作比较门槛；CTD/CTUD 作装载起始值 |
| Q | CTU、CTD | Bool 输出 | CTU：CV≥PV；CTD：CV≤0 | 电平信号，非脉冲 |
| QU | CTUD | Bool 输出 | CV≥PV | 电平信号 |
| QD | CTUD | Bool 输出 | CV≤0 | 电平信号 |
| CV | 三种都有 | 整数输出 | 当前计数值 | 可在背景DB中在线监视 |

记忆口诀：**CU 加、CD 减、R 清零、LD 装数；PV 是目标，CV 是账本，Q/QU/QD 是报信的旗。**

## 四、计数器数据类型选择（背景DB说明）

### 4.1 为什么要选数据类型

CV 要存数字，数字就有"多大"的问题：数到 100 和数到 500 万，需要的存储空间完全不同。调用计数器时，TIA 在"调用选项"对话框里让你选择**背景DB的数据类型**，本质就是给 CV/PV 选一个合适的整数类型。

### 4.2 可选类型一览

| 背景DB数据类型 | 对应整数类型 | CV / PV 取值范围 | 适用场景 |
|---|---|---|---|
| CSInt | SInt | −128 ~ 127 | 很小的有符号计数 |
| CUSInt | USInt | 0 ~ 255 | 很小的纯加计数 |
| **CInt** | **Int** | **−32768 ~ 32767** | **最常用，本课程默认** |
| CUInt | UInt | 0 ~ 65535 | 中等数量的纯加计数 |
| CDInt | DInt | −2147483648 ~ 2147483647 | 大数量、有正负 |
| CUDInt | UDInt | 0 ~ 4294967295 | 超大数量纯加计数 |

（其余基础类型范围：SInt −128~127，USInt 0~255，Int −32768~32767，UInt 0~65535，DInt −2147483648~2147483647，UDInt 0~4294967295。）

### 4.3 选择方法与建议

1. 把 CTU/CTD/CTUD 拖入网络 → 弹出"调用选项"对话框 → 填写实例名（如"CTU_产品计数"）→ 在数据类型下拉框中选择（如 CInt）→ 确定，背景DB自动生成；
2. **本课程约定**：无特殊说明一律选 **CInt**（16 位有符号，−32768~32767），够用且好读；
3. 类型选小了的后果：CV 数到上限就"封顶"不再增加（例如选 CSInt 最多数到 127），而且**不会报错、不会回绕**，程序会"悄悄地数丢了"，所以宁可稍大勿小；
4. 背景DB中可以直接在线监视 `CTU_xxx.CV`、`CTU_xxx.PV`、`CTU_xxx.Q`，调试非常方便；
5. 类型一旦选定，PV、CV 的类型随之固定，与外接的变量/比较指令必须类型匹配，否则编译报错。

## 五、计数器的复位方法

| 方法 | 适用 | 操作 | 说明 |
|---|---|---|---|
| R 引脚复位 | CTU、CTUD | R=1（哪怕只有一个扫描周期）→ CV=0 | 最标准的方法；R 优先级最高 |
| LD 装载复位 | CTD、CTUD | LD=1 → CV=PV | 严格说是"装满"而不是"清零"，对减计数而言就是回到起点 |
| 监控表改 CV | 全部（调试用） | 在背景DB的 CV 上直接写入 0 | 仅限教学/调试，正式程序禁止 |
| 重新下载/重启 CPU | 全部 | 非保持数据初始化为 0 | 上电 CV 从 0 开始 |

注意：**不能用 MOVE 指令给 CV"赋值"**——CV 是计数器的输出参数，程序只能通过 R、LD 这两个输入引脚去影响它，这是 IEC 计数器与老式 S5 计数器的一大区别。

## 六、计数器与上升沿配合的注意事项（为什么会多计/漏计）

### 6.1 先明确：CU/CD 自带上升沿检测

CTU/CTD/CTUD 的计数输入内部**已经**做了上升沿检测，所以把普通触点直接接到 CU 上就是正确用法：

- 正确：`I0.0 产品检测 ──| |──→ CU`（每个 0→1 计一次）
- 多余但无害：`I0.0 ──|P|──→ CU`（先出 1 个扫描周期脉冲，CU 再检测一次边沿，结果仍是计一次）

真正会出问题的不是"要不要加 P"，而是下面这些情况。

### 6.2 多计（计多了）的三大原因

**原因 1：机械触点抖动。** 机械按钮、继电器触点在闭合瞬间会"哆嗦"几毫秒，产生一串假上升沿：

```
理想信号（1 次按压）          实际触点信号（抖动）
1                              1   ┌┐┌┐ ┌┐
                               ┌───┘┘└┘─┘└──────
0                            0 ┘
上升沿数：1                   上升沿数：4~5 个 → 计数器多计！
```

对策：优先用接近开关/光电传感器（无触点、无抖动）；机械开关则在硬件上加滤波，或用软件消抖（比如用 TON 延时 20ms 确认信号稳定后再送往 CU，第 4 章定时器的典型应用）。

**原因 2：一个产品被检测两次。** 传感器安装位置不当（反射/回扫）、产品在检测点轻微晃动，都会造成"一个产品两次脉冲"。对策：调整安装位置，或在程序里加最小间隔判断。

**原因 3：前级逻辑反复变化。** 若 CU 前面串联了一段会抖动/振荡的逻辑，这段逻辑的每次 0→1 都会被计数。对策：确保 CU 的输入信号干净、稳定。

### 6.3 漏计（计少了）的两大原因

**原因 1：脉冲太窄，短于一个扫描周期。** CPU 每个扫描周期只在开头读一次输入（输入映像），如果信号"闪一下"恰好发生在两次采样之间，CPU 看到的一直是 0：

```
              ↓采样    ↓采样    ↓采样
信号 1         ┌┐
               ││  ← 脉冲出现在两次采样之间
   0 ──────────┘└────────────────
结果：CPU 读到的全是 0 → 这个脉冲被彻底漏掉
```

对策：保证脉冲宽度至少为一个扫描周期（硬件上加脉冲展宽，或用 TP 定时器把窄脉冲展成固定宽度）；降低不必要的扫描负担。

**原因 2：按住不松手。** 这条最容易让新手误会："我按了 10 秒，怎么只计了 1 个？"——因为计数器数的是**上升沿**，按住期间只有一个上升沿。想计 10 次，就得完整地按 10 次（松开再按）。同理，两个产品紧挨着通过传感器、中间信号没有回落到 0，也只会计 1 次——这是传感器与物料间距的问题，不是程序错。

### 6.4 小结

| 现象 | 根源 | 对策 |
|---|---|---|
| 多计 | 触点抖动、重复检测、前级逻辑振荡 | 无触点传感器、硬件滤波、软件消抖 |
| 漏计 | 脉冲窄于扫描周期、按住不松、产品贴太近 | 脉冲展宽、完整脉冲、调整间距 |

## 七、完整案例：产品计件到 100 个自动停线

### 7.1 需求

生产线由电机带动，启动后持续运行；每通过一个产品，检测传感器发出一个脉冲。当累计产品达到 **100 个**时，生产线自动停止；按复位按钮清零计数后，才能再次启动。

### 7.2 I/O 分配表

| 名称 | 地址 | 数据类型 | 说明 |
|---|---|---|---|
| 产品检测 | I0.0 | Bool | 光电传感器，每过一个产品发一个脉冲 |
| 启动按钮 | I0.1 | Bool | 启动生产线 |
| 停止按钮 | I0.2 | Bool | 手动停止生产线 |
| 复位按钮 | I0.3 | Bool | 计数清零、清除计满标志 |
| 生产线运行 | Q0.0 | Bool | 控制生产线（接触器） |
| 计满标志 | M0.0 | Bool | 计数值达到 100 时为 1 |
| CTU_产品计数 | DB1 | CInt | 计数器背景DB |

> 停止按钮说明：本教学程序用**常闭触点 --|/|-- 串联**实现停止。实际工程中推荐停止按钮硬件接**常闭触点**以保证安全（断线也能被检测出来），此时程序中应使用**常开**触点——两种接法逻辑相反，切勿混淆。

### 7.3 梯形图（逐网络段分析）

**网络段1：生产线启停控制（计满自动停线）**

```
       启动按钮       停止按钮       计满标志          生产线运行
        I0.1          I0.2          M0.0                Q0.0
  +-----| |-----+------|/|-------------|/|-------------( )----
  |             |
  |  生产线运行  |
  |     Q0.0    |
  +-----| |-----+
```

文字分析：

- 经典"启保停"结构：按启动 → Q0.0 得电；Q0.0 的常开触点并联自保持，松手后继续运行；
- 串联两个常闭触点：**停止按钮 I0.2**（手动停）和**计满标志 M0.0**（数到 100 自动停）；
- 当 M0.0 = 1 时，常闭触点断开 → 自保持被切断 → 生产线自动停止。

**网络段2：产品计数**

```
                                    +------------------+
     产品检测                        |  CTU_产品计数    |
      I0.0                         |                  |
    ----| |------------------------+CU                |
                                    |                  |
     复位按钮                       |             Q    +----( )---- M0.0 计满标志
      I0.3                         |                  |
    ----| |------------------------+R                 |
                                    |                  |
                                    | PV := 100        |
                                    |           CV     |    （当前计数值，可在
                                    +------------------+     监控表看 CTU_产品计数.CV）
```

文字分析：

- **CU** 接产品检测 I0.0：每过一个产品（一个上升沿），CV 加 1；
- **R** 接复位按钮 I0.3：按下时 CV 清零。R 是电平复位，优先级最高，按住期间不会计数；
- **PV** 填 100：计数目标；
- **Q** 直接接到线圈 M0.0：CV ≥ 100 时 Q=1 → 计满标志置位 → 网络段1 立即停线；
- **CV** 引脚可以不接：调试时在监控表里直接监视背景DB变量 `CTU_产品计数.CV` 即可；如果程序其他地方要用计数值（如显示到 HMI），也可以把 CV 连接到一个 Int 型变量（如 MW20 当前计数值）。
- 另一种等价写法：Q 引脚悬空，在下一段网络里用触点 `CTU_产品计数.Q ──| |──` 去驱动 M0.0，效果相同。

### 7.4 运行流程串讲

1. 上电初始：CV=0，M0.0=0，生产线停止；
2. 按 I0.1 启动 → Q0.0=1 自保持，生产线运行；
3. 产品逐个经过传感器 → CV=1、2、3……99；
4. 第 100 个产品 → CV=100 → Q=1 → M0.0=1 → 网络段1 的常闭断开 → **自动停线**；此时 CV 停留在 100（Q 保持 1，它只比较、不封锁计数）；
5. 处理完产品后按 I0.3 复位 → CV=0、Q=0、M0.0=0；
6. 再按 I0.1 → 开始下一批 100 个。循环往复。

## 八、计数器容易遗漏的细节（非常重要）

1. **CV 不会停在 PV**：CTU 数到 PV 后 Q 置 1，但 CV 会继续涨到数据类型上限（CInt 是 32767）。想让"数到 100 就停"，必须靠程序（如本案例的 M0.0 停线 + 复位），而不是指望计数器自己封顶。
2. **Q/QU/QD 是电平不是脉冲**：达标后一直为 1，直到 CV 回落或复位。要"只动作一次"，请在 Q 后面自己加边沿检测或用本案例的标志位方式。
3. **R 是电平复位且优先级最高**：R 一直为 1，CV 就永远是 0——新手常把常开/常闭接反，导致"怎么按都不计数"，先查 R。
4. **CTD 必须先装载**：CTD 从未执行 LD 时 CV=0，Q 一上电就是 1（因为 CV≤0）。用 CTD 前记得先用 LD 把 PV 装进去。
5. **按住不松只计一次**：计数器数的是上升沿。演示或测试时，监控表里要"0→1→0→1"地完整翻转，才能一次次计数。
6. **背景DB一器一个**：多个计数器共用一个背景DB是严重错误，CV 会互相覆盖。每个计数器实例都要有自己的背景DB。
7. **类型宁大勿小**：选 CSInt 数到 127 就封顶且不报错。数量可能增长的需求直接选 CInt 甚至 CDInt。
8. **上电从 0 开始**：背景DB数据默认不具备断电保持属性，重启后 CV=0。工艺上需要"断点续计"时，要另行设置保持性存储（后续章节讲）。
9. **输入信号质量决定成败**：抖动多计、窄脉冲漏计，硬件选型和信号调理比"改程序"更能根治（见第六节）。

## 📌 本章小结

- 计数器数的是**上升沿**：CU/CD 输入内部自带边沿检测，按住不松只计一次；
- 三种 IEC 计数器：**CTU**（加，Q=CV≥PV）、**CTD**（减，先 LD 装载，Q=CV≤0）、**CTUD**（加减兼顾，QU/QD 两个输出）；
- 引脚口诀：**CU 加、CD 减、R 清零、LD 装数，PV 目标、CV 账本、Q 报信**；R 优先级最高；
- 背景DB类型决定 CV 范围：CSInt/CUSInt/CInt/CUInt/CDInt/CUDInt，本课程默认 **CInt**（−32768~32767），类型宁大勿小；
- CV 不会自动停在 PV，Q 是电平不是脉冲；停线、动作"只做一次"都要靠程序设计；
- 多计源于抖动与重复检测，漏计源于窄脉冲与"按住不松"，对策在信号质量与脉冲宽度；
- 案例模式：**启保停 + 计满标志常闭串入自保持回路**，即可实现计满自动停线。

## ⚠️ 常见错误与注意事项

1. **R 引脚接反**：误把常闭触点接到 R，复位条件长期成立，计数器永远为 0。先监视 R 再找原因。
2. **指望 CV 在 PV 停下**：PV 只是 Q 的比较门槛，CV 会继续涨。需要"到数即停"必须像案例那样用标志位参与控制。
3. **CTD 忘记装载**：没有 LD 就用 CTD，Q 一上电就是 1。用 CTD 前先设计装载逻辑。
4. **多个计数器共用背景DB**：数据互相覆盖，必须一器一DB。
5. **测试时只把 I0.0 置 1 不回 0**：边沿检测只在 0→1 时动作，必须完整翻转才能连续计数。
6. **PV 与比较变量的类型不一致**：背景DB选了 CInt，比较时却和 DInt 变量比，编译报错。全链路统一类型。
7. **用 MOVE 给 CV 赋值**：CV 是输出参数，不能直接写。清零用 R，装载用 LD。
8. **忘记真实硬件的抖动与窄脉冲问题**：仿真里一切干净，上真机就多计/漏计，提前按第六节做好消抖与脉冲展宽。
9. **停止按钮接法混淆**：本教学程序中程序内用常闭触点实现停止；实际工程停止按钮硬件推荐接常闭触点，此时程序内应改为常开触点，两者逻辑相反，切勿生搬硬套。

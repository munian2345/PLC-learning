# 17 - 数学函数与转换指令

> PLC 不只会开关量逻辑，还能做算术：加减速配比、功率计算、角度换算，以及工业现场最重要的技能——**把模拟量原始值换算成真实工程量**（比如把电流信号换算成温度）。本章学数学函数、类型转换，以及全课程的重点：NORM_X + SCALE_X 模拟量标定。

## 📖 学习目标

1. 掌握基本运算 ADD / SUB / MUL / DIV / MOD 的用法，知道整数除法会"截断"以及如何解决；
2. 了解 ABS、SQR、SQRT、LN、EXP 等数学函数和 SIN / COS / TAN 三角函数（重点记住"参数是弧度"）；
3. 会用 CONVERT 指令做数据类型转换，能区分 ROUND / TRUNC / CEIL / FLOOR 四种取整；
4. 理解模拟量原始值 0~27648（双极性 -27648~27648）的含义，掌握 NORM_X 与 SCALE_X 的标定流程；
5. 独立完成"4-20mA 电流信号 → 0~100°C 温度值"的完整案例，并能在 PLCSIM 中仿真模拟量输入。

## 一、数学函数

### 1.1 基本运算：ADD / SUB / MUL / DIV / MOD

五个指令都是"框式"指令，引脚含义统一：EN 使能输入、ENO 使能输出、IN1/IN2 参与运算的数、OUT 存放结果。

| 指令 | 功能 | 数学式 | 示例 |
| ---- | ---- | ---- | ---- |
| ADD | 加 | OUT = IN1 + IN2 | 5 + 3 = 8 |
| SUB | 减 | OUT = IN1 - IN2 | 5 - 3 = 2 |
| MUL | 乘 | OUT = IN1 × IN2 | 5 × 3 = 15 |
| DIV | 除 | OUT = IN1 ÷ IN2 | 7 ÷ 2 = 3（Int 相除会截断，见 1.4） |
| MOD | 取余 | OUT = IN1 MOD IN2 | 7 MOD 2 = 1 |

数据类型说明：

1. 整数类（SInt/USInt/Int/DInt 等）和浮点类（Real/LReal）都支持四则运算；**初学建议 IN1、IN2、OUT 用同一数据类型**，最不容易出错（TIA 允许混用并自动转换，但结果类型容易让新手迷糊）；
2. **MOD 只支持整数**：它的任务是求"除不尽的零头"，浮点数没有这个需求；
3. **除数为 0 会出错**：DIV/MOD 碰到 IN2 = 0 时指令报错、ENO 变 0、OUT 不更新。重要场合要用 ENO 信号做保护，或先比较 IN2 是否为 0。

ASCII 功能框（以 ADD 为例）：

```
                      ┌────────────────┐
  计算条件             │      ADD       │       计算完成
──────| |─────────────┤EN            ENO├────────( )──── "计算完成" M0.3
                      │                │
  "设定值"  MW32 ─────┤ IN1            │
  "偏移量"  MW34 ─────┤ IN2            │
                      │ OUT            ├────── "总设定" MW36
                      └────────────────┘
```

文字分析：计算条件接通时，MW32 + MW34 的和写入 MW36。注意 EN 断开时 OUT 保持上一次的值，不会清零。

DIV 与 MOD 的组合应用（装箱问题：95 个产品、每箱 12 个）：

```
                      ┌────────────────┐
──────| |─────────────┤EN      DIV   ENO├──
                      │ IN1: "总数" MW30│
                      │ IN2: 常数 12    │
                      │ OUT: "整箱数"   ├──→ 95 ÷ 12 = 7 箱
                      └────────────────┘   MW38

                      ┌────────────────┐
──────| |─────────────┤EN      MOD   ENO├──
                      │ IN1: "总数" MW30│
                      │ IN2: 常数 12    │
                      │ OUT: "零头数"   ├──→ 95 MOD 12 = 5 个
                      └────────────────┘   MW44
```

类比：MOD 就是小时候分糖果——7 颗糖分给 2 个人，每人 3 颗（DIV），剩下 1 颗（MOD）。

注意：上面 MOD 结果放在 MW44 而不是 MW40——因为 MW40~MW43 属于双字 MD40 的地盘（见后文工程量变量），地址重叠是新手大坑。

### 1.2 数学函数：ABS / SQR / SQRT / LN / EXP

这一组指令都是"单输入单输出"，只用一个 IN、一个 OUT：

| 指令 | 功能 | 数学式 | 示例 |
| ---- | ---- | ---- | ---- |
| ABS | 绝对值 | OUT = \|IN\| | ABS(-5) = 5 |
| SQR | 平方 | OUT = IN² | SQR(3.0) = 9.0 |
| SQRT | 平方根 | OUT = √IN | SQRT(9.0) = 3.0 |
| LN | 自然对数（以 e 为底） | OUT = ln(IN) | LN(2.718...) ≈ 1.0 |
| EXP | e 的指数 | OUT = e^IN | EXP(1.0) ≈ 2.718 |

关于 LOG（以 10 为底的对数）：TIA Portal 对 S7-1500 没有单独的 LOG 指令框，需要用**换底公式**自己算：log₁₀(x) = LN(x) ÷ LN(10)。例如 log₁₀(1000) = LN(1000) ÷ LN(10) = 3.0。用 SCL 写一行即可：

```scl
"对数结果" := LN("原始值") / LN(10.0);   // 以 10 为底的对数
```

重要：**SQR / SQRT / LN / EXP 只接受浮点数（Real/LReal）**，想对整数 9 开平方，要先用 CONVERT 转成 Real（9 → 9.0）。LN 的输入还必须大于 0，否则结果无效（NaN）。

ASCII 功能框（以 SQRT 为例）：

```
                      ┌────────────────┐
  计算条件             │      SQRT      │
──────| |─────────────┤EN            ENO├────────( )──
                      │                │
  "平方值" MD50 ──────┤ IN           OUT├────── "边长" MD54
                      └────────────────┘
```

ENQ：对负数做 SQRT 会得到无效值 NaN，后续用第 16 篇学的 NOT_OK 检查最稳妥。

### 1.3 三角函数：SIN / COS / TAN（角度与弧度！）

| 指令 | 功能 | 输入 | 输出 |
| ---- | ---- | ---- | ---- |
| SIN | 正弦 | 弧度（Real/LReal） | Real/LReal |
| COS | 余弦 | 弧度 | Real/LReal |
| TAN | 正切 | 弧度 | Real/LReal |

**最容易踩的坑：这三个函数吃的不是"角度"，是"弧度"！**

换算公式：**弧度 = 角度 × π ÷ 180**（π ≈ 3.14159）

| 角度 | 弧度 | SIN 值 |
| ---- | ---- | ---- |
| 0° | 0.0 | 0.0 |
| 30° | 0.5236 | 0.5 |
| 90° | 1.5708 | 1.0 |
| 180° | 3.1416 | ≈ 0.0 |

如果直接把 30 当弧度喂给 SIN，得到的不是 0.5，而是 sin(30 弧度) = -0.988——差了十万八千里。

正确计算 sin(30°) 的流程：

```
 角度30.0 ──► 乘 3.14159 ──► 除 180 ──► 弧度 0.5236 ──► SIN ──► 0.5
 (Real)
```

用 SCL 一行表达：

```scl
"正弦结果" := SIN("角度" * 3.14159 / 180.0);   // 角度 → 弧度 → 正弦
```

### 1.4 整数除法的截断问题和解决方案

**问题**：两个 Int 相除，结果也是 Int，小数部分被**直接砍掉**（向零截断），不是四舍五入：

```
7  ÷ 2 = 3     （不是 3.5！）
9  ÷ 4 = 2     （不是 2.25！）
-7 ÷ 2 = -3    （不是 -3.5！）
```

类比：3.5 个苹果装不进"Int 型"篮子，PLC 把 0.5 个苹果直接扔掉了。如果你的程序要算"平均温度"，被这么一砍，精度就全没了。

**解决方案**：先把两个 Int 转换成 Real，再用浮点除法：

```
"总数" MW20 (Int, =7)          "人数" MW22 (Int, =2)
        │                              │
        ▼                              ▼
  ┌────────────┐                ┌────────────┐
  │    CONV    │                │    CONV    │
  │  Int→Real  │                │  Int→Real  │
  └─────┬──────┘                └─────┬──────┘
        ▼                             ▼
  MD50 = 7.0                    MD54 = 2.0
        └──────────────┬───────────────┘
                       ▼
                ┌──────────────┐
                │  DIV (Real)  │
                │ OUT:  MD58   │ = 3.5（精度保住了）
                └──────────────┘
```

记住口诀：**要小数，先转 Real 再除**。

## 二、转换指令

### 2.1 CONVERT：数据类型转换

**作用**：把数据从一种类型转换成另一种类型，最常用的是 Int ↔ Real。

在框上点击类型标记，可以分别指定 IN 的源类型和 OUT 的目标类型：

| 转换方向 | 规则 |
| ---- | ---- |
| Int → Real | 数值不变，补上小数点：7 → 7.0，完全无损 |
| Real → Int | 小数部分按四舍五入处理；但**推荐用专门的取整指令**（见 2.2），取整规则一目了然、结果可控 |
| DInt → Int | 大类型转小类型，超出范围会出错（ENO 变 0），要确保数值放得下 |
| Byte → Int 等扩展 | 按数值转换，注意有无符号的差别 |

ASCII 功能框：

```
                      ┌──────────────────┐
  转换条件             │   CONV  Int→Real │
──────| |─────────────┤EN              ENO├─────────( )──
                      │                  │
  "温度值"  MW20 ─────┤ IN             OUT├────── "温度工程量" MD40
                      └──────────────────┘
```

文字分析：转换条件接通时，把 Int 型的温度值 MW20（例如 50）转成 Real 型 50.0 存入 MD40。框上的"Int→Real"就是通过点击框的类型字段设置的。

### 2.2 取整函数：ROUND / TRUNC / CEIL / FLOOR

Real 转 Int 有四种"砍法"，用错一个，报警点就差一度：

| 指令 | 规则（一句话） | 3.7 | 3.2 | 3.5 | 2.5 | -3.7 | -3.2 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| ROUND | 四舍六入五取偶（银行家舍入） | 4 | 3 | 4 | 2 | -4 | -3 |
| TRUNC | 只留整数部分（朝零砍） | 3 | 3 | 3 | 2 | -3 | -3 |
| CEIL | 向正无穷方向取整（进一法） | 4 | 4 | 4 | 3 | -3 | -3 |
| FLOOR | 向负无穷方向取整（去尾法） | 3 | 3 | 3 | 2 | -4 | -4 |

> 重点注意 **ROUND 的“四舍六入五取偶”**（IEEE 754 标准，又称银行家舍入法）：当小数部分恰好为 0.5 时，**舍入到最近的偶数**（例如 2.5 取整为 2，3.5 取整为 4，4.5 取整为 4）。这样在工业大数据连续累加时，正负舍入偏差大致对半抵消，避免了传统四舍五入导致系统统计结果整体偏大的累积误差。

数轴上看更直观：

```
正数 3.7 的四种归宿               负数 -3.7 的四种归宿
────┬─────┬─●─┬────►           ────┬─●─┬──────┬────►
    3    3.7   4                   -4  -3.7    -3
 ROUND→4   CEIL→4                ROUND→-4   FLOOR→-4
 TRUNC→3   FLOOR→3               TRUNC→-3   CEIL→-3
```

记忆类比：

- ROUND：考试打分，四舍五入最公平；
- TRUNC：铁面无私的裁缝，多长一律剪掉（不管正负，只留整数部分）；
- CEIL：天花板（ceiling），永远向上够；
- FLOOR：地板（floor），永远向下踩。

ASCII 功能框（以 ROUND 为例）：

```
                      ┌────────────────┐
  取整条件             │     ROUND      │
──────| |─────────────┤EN            ENO├────────( )──
                      │                │
  "温度工程量"         │ IN           OUT│────── "温度值" MW20
  MD40 (Real) ────────┤                │        (Int)
                      └────────────────┘
```

选型建议：显示、报警等常规场合用 ROUND（最符合人的直觉）；计算"能装几箱"这类宁可少不可多的场合用 TRUNC 或 FLOOR；需要"保底向上"（如至少需要几个托盘）用 CEIL。

## 三、模拟量转换（本章重点）

### 3.1 模拟量原始值（0~27648 / -27648~27648）的含义

传感器送来的温度、压力是连续的电流/电压信号，模拟量输入模块里的 ADC（模数转换器）会把它"打分"成一个整数，这个整数就是**原始值**，程序里读到的就是这个数。

西门子 S7-1500 的打分规则：

| 信号类型 | 原始值范围 | 说明 |
| ---- | ---- | ---- |
| 单极性（0~10V、0/4~20mA） | 0 ~ 27648 | 没有负半边 |
| 双极性（±10V、±5V） | -27648 ~ +27648 | 信号为 0 时原始值为 0 |

**为什么满量程是 27648 而不是 32767？** 因为西门子特意预留了约 18% 的余量：27649~32767 用来表示"过量程"（信号超上限），负方向表示"欠量程"。这样程序一看数值超出 27648，就知道传感器超了，而不是傻傻当成正常值。

以 4-20mA 电流信号为例（满量程 20mA 对应 27648）：

```
电流:    <4mA      4mA      8mA      12mA      16mA      20mA     >20mA
          │         │        │         │         │         │         │
原始值:   负数       0      6912     13824     20736     27648    27649~32767
        (欠量程)  (量程起点)          (正好一半)            (满量程)   (过量程)
```

要点：4-20mA 量程中，**4mA 是"活零点"，对应原始值 0**——这不是浪费，而是经典设计：电流掉到 0mA 就说明断线了，程序一识别"原始值为负"就能立刻报警。

### 3.2 NORM_X：标准化（原始值 → 0.0~1.0）

**作用**：把输入值按线性关系压缩到 0.0~1.0 之间。

| 引脚 | 作用 |
| ---- | ---- |
| MIN | 输入量程的下限 |
| MAX | 输入量程的上限 |
| VALUE | 被标准化的输入值 |
| OUT | 标准化结果（Real，0.0~1.0） |

计算公式：**OUT = (VALUE - MIN) ÷ (MAX - MIN)**

例：VALUE = 13824，MIN = 0，MAX = 27648 → OUT = 13824 ÷ 27648 = **0.5**

```
                      ┌────────────────────┐
                      │       NORM_X       │
  "原始值" MW20 ──────┤ VALUE              │
  （Int）             │ MIN: 0             │
                      │ MAX: 27648         ├──→  0.5（Real）
                      │ OUT: "标准化值"     │
                      └────────────────────┘    MD64
```

类比：把考试成绩换算成"百分制完成度"——原始分 13824，满分 27648，完成度 50%。

### 3.3 SCALE_X：缩放（0.0~1.0 → 工程量）

**作用**：把 0.0~1.0 的标准化值拉伸到实际工程量范围。

| 引脚 | 作用 |
| ---- | ---- |
| MIN | 输出量程的下限 |
| MAX | 输出量程的上限 |
| VALUE | 标准化值（0.0~1.0，Real） |
| OUT | 缩放结果（类型与 MIN/MAX 一致） |

计算公式：**OUT = VALUE × (MAX - MIN) + MIN**

例：VALUE = 0.5，MIN = 0.0，MAX = 100.0 → OUT = 0.5 × 100 = **50.0**（°C）

```
                      ┌────────────────────┐
                      │       SCALE_X      │
  "标准化值" MD64 ────┤ VALUE              │
  （Real 0.0~1.0）    │ MIN: 0.0           │
                      │ MAX: 100.0         ├──→  50.0（°C）
                      │ OUT: "温度工程量"   │
                      └────────────────────┘    MD40
```

两个指令接力，就是完整的线性标定流水线：

```
  IW64             NORM_X                SCALE_X
 原始值 ──────► 0.0~1.0 标准值 ──────► 真实工程量
 (Int)          (Real)                 (Real)
 13824    →      0.5          →        50.0 °C
```

合起来其实就是一条直线方程：工程量 = (原始值 ÷ 27648) × (量程上限 - 量程下限) + 下限。NORM_X 和 SCALE_X 只是把它拆成了两节标准车厢，接起来就能跑。

### 3.4 完整案例：4-20mA 电流信号转换为 0~100°C 温度值

**需求**：温度传感器输出 4-20mA，接到模拟量输入模块通道 0（地址 IW64），量程对应 0~100°C。4mA 对应原始值 0，20mA 对应 27648。要求换算出温度，并处理"低于 4mA（断线/欠量程）"的情况。

**分两步走**：

- 第一步：判断低于 4mA 的部分——原始值 < 0 视为欠量程，按 0 处理并给出标志；
- 第二步：对有效原始值做 NORM_X + SCALE_X 标准化缩放。

**变量表：**

| 变量名称 | 数据类型 | 地址 | 说明 |
| ---- | ---- | ---- | ---- |
| 4-20mA原始值 | Int | IW64 | 模拟量通道原始值 |
| 有效原始值 | Int | MW60 | 下限处理后的原始值 |
| 标准化值 | Real | MD64 | NORM_X 的输出（0.0~1.0） |
| 温度工程量 | Real | MD40 | 换算出的温度（0.0~100.0°C） |
| 温度值 | Int | MW20 | 取整后的温度（供报警等逻辑使用） |
| 欠量程标志 | Bool | M0.6 | 原始值 < 0 时置 1 |

**完整梯形图：**

```
网络 1：欠量程标志（原始值 < 0 = 信号低于 4mA，可能断线）

        4-20mA原始值       0
        IW64             常数
      ┌─────────────────────┐
──────┤     CMP    <   Int  ├──────────────( )────── "欠量程标志" M0.6
      └─────────────────────┘

网络 2：欠量程时，有效原始值按 0 处理

        4-20mA原始值       0
      ┌─────────────────────┐        ┌────────────────┐
──────┤     CMP    <   Int  ├────────┤EN       MOVE   │
      └─────────────────────┘        │ IN: 常数 0     │
                                     │ OUT: "有效原始值"├──→ MW60 = 0
                                     └────────────────┘

网络 3：原始值正常（>= 0）时，直接传送

        4-20mA原始值       0
      ┌─────────────────────┐        ┌────────────────┐
──────┤     CMP   >=   Int  ├────────┤EN       MOVE   │
      └─────────────────────┘        │ IN: IW64       │
                                     │ OUT: "有效原始值"├──→ MW60
                                     └────────────────┘

网络 4：NORM_X 标准化（原始值 → 0.0~1.0，无条件执行）

      ┌─────────────────────────┐
──────┤EN       NORM_X      ENO ├──
      │   MIN:  0               │
      │   MAX:  27648           │
MW60 ─┤   VALUE                 │
      │   OUT:  "标准化值"       ├──→ MD64
      └─────────────────────────┘

网络 5：SCALE_X 缩放（0.0~1.0 → 0.0~100.0°C，无条件执行）

      ┌─────────────────────────┐
──────┤EN       SCALE_X     ENO ├──
      │   MIN:  0.0             │
      │   MAX:  100.0           │
MD64 ─┤   VALUE                 │
      │   OUT:  "温度工程量"     ├──→ MD40
      └─────────────────────────┘

网络 6：ROUND 取整，得到整数温度（供第 16 篇的报警逻辑直接使用）

      ┌─────────────────────────┐
──────┤EN        ROUND      ENO ├──
      │   IN:  "温度工程量" MD40 │
      │   OUT: "温度值"   MW20  │
      └─────────────────────────┘
```

**计算过程推演（以 IW64 = 13824，对应 12mA 为例）：**

1. 网络 1：13824 < 0 不成立 → 欠量程标志 M0.6 = 0；
2. 网络 3：13824 >= 0 成立 → MOVE 把 13824 送入 MW60；
3. 网络 4：NORM_X → (13824 - 0) ÷ (27648 - 0) = 0.5 → MD64 = 0.5；
4. 网络 5：SCALE_X → 0.5 × (100.0 - 0.0) + 0.0 = 50.0 → MD40 = 50.0（°C）；
5. 网络 6：ROUND(50.0) = 50 → MW20 = 50。

**断线推演（IW64 = -2000，信号低于 4mA）：** 网络 1 置位 M0.6；网络 2 把 MW60 按 0 处理；最终 MD40 = 0.0、MW20 = 0，同时欠量程标志提醒维护人员"这不是真 0 度，是信号有问题"。

**常见输入对照表：**

| IW64 | 对应电流 | MD64（标准化） | MD40（°C） | MW20（取整） |
| ---- | ---- | ---- | ---- | ---- |
| -2000 | < 4mA（欠量程） | ——（按 0 处理） | 0.0 | 0 |
| 0 | 4mA | 0.0 | 0.0 | 0 |
| 6912 | 8mA | 0.25 | 25.0 | 25 |
| 13824 | 12mA | 0.5 | 50.0 | 50 |
| 20736 | 16mA | 0.75 | 75.0 | 75 |
| 27648 | 20mA | 1.0 | 100.0 | 100 |

### 3.5 PLCSIM 中如何仿真模拟量输入值

没有真实传感器，怎么测试？直接写 IW64 的原始值：

1. **硬件组态**：在设备组态中给 CPU 添加模拟量输入模块（如 AI 8xU/I/RTD 类），把通道 0 的测量类型设为"电流 4-20mA"；在该模块"地址"属性中确认输入地址为 64，对应 IW64；
2. **在 PLCSIM 的 SIM 表中添加 IW64**（显示格式选 Int/十进制）；
3. 在 SIM 表中直接输入 0~27648 之间的整数（如 13824），就等于"传感器此刻送来了 12mA"；
4. 想模拟断线，输入一个负数（如 -2000）；
5. 若你手头的组态没有 AI 模块，也可以临时把程序里的 IW64 换成普通中间变量 MW100 来测试，逻辑验证完全等效，正式使用前再换回 IW64。

- [ ] IW64 = 6912 / 20736 时，温度分别为 25.0 / 75.0（线性关系成立）；

### ⑥ 结果不符时的排查方法

1. **4mA 时温度不为 0（约 14.5 左右）**：通道测量类型组态成了 0-20mA（4mA 被折算成约 5529 的原始值）。把通道类型改为"4-20mA"，使 4mA 对应原始值 0；
2. **温度一直为 0**：IW64 没有真正写入（SIM 表修改后要回车）；或网络 3 的比较/传送条件写错导致 MW60 一直为 0；
3. **MD64 出现负数或大于 1**：NORM_X 的 MIN/MAX 写反（MAX 写成 0）；核对 MIN=0、MAX=27648；
4. **数值巨大且乱跳**：数据类型接错，例如把 Real 的 MD64 接到了 Int 引脚上，或 MIN/MAX 用了 Int 常数却没匹配类型；逐个核对引脚类型；
5. **温度比预期差一倍或一半**：MAX 写错（27648 写成 13824 等），或通道组态量程与程序假设不一致；
6. **MW20 与 MD40 对不上、总差 1**：检查用的是 ROUND（四舍五入）还是 TRUNC（截断），两种取整在 x.5 附近必然不同；
7. **报地址冲突**：MD40 占用 MB40~MB43，检查是否又把别的变量放在了 MW40、MW42 等重叠地址上；
8. **下载报硬件不一致**：确认组态中的 AI 模块型号 PLCSIM 支持，或改用 MW100 模拟原始值的临时方案。

## 📌 本章小结

1. 基本运算 ADD/SUB/MUL/DIV/MOD：框式指令，EN/ENO/IN1/IN2/OUT；除数为 0 会报错（ENO 变 0）；MOD 求余数、只支持整数；
2. ABS/SQR/SQRT/LN/EXP 只吃浮点数；TIA 没有独立 LOG 框，用 LN(x)/LN(10) 换底；三角函数 SIN/COS/TAN 的参数必须是**弧度**（弧度 = 角度 × π ÷ 180）；
3. Int÷Int 会截断小数，**要小数先转 Real 再除**；
4. CONVERT 做类型转换（Int→Real 无损，Real→Int 推荐用专门取整指令）；四种取整：ROUND 四舍六入五取偶（银行家舍入）、TRUNC 朝零砍、CEIL 向上、FLOOR 向下；
5. 模拟量原始值：单极性 0~27648，双极性 -27648~27648；27648 之外是过量程/欠量程余量；4-20mA 的 4mA 对应原始值 0（活零点）；
6. 标定流水线：NORM_X 把原始值压成 0.0~1.0，SCALE_X 把 0.0~1.0 拉成工程量；先判欠量程、再标准化缩放，是工程上的标准两步；
7. PLCSIM 仿真模拟量：组态好 AI 通道后在 SIM 表直接写 IW64 的原始值即可。

## ⚠️ 常见错误与注意事项

1. **三角函数直接喂角度**：SIN(30.0) 算的是 30 弧度不是 30 度，必须先乘 π 除 180；
2. **忽略整数除法截断**：7÷2 得 3 不是 3.5，求平均、算比例前先转 Real；
3. **对整数用 SQR/SQRT/LN/EXP**：这些函数只接受 Real/LReal，先 CONVERT 再算；
4. **除数可能为 0 却不做保护**：DIV 遇 0 报错、ENO 断开、OUT 保持旧值，关键场合先比较 IN2≠0；
5. **SQRT 负数得到 NaN**：NaN 一路传播会让后续所有比较失效，先用比较指令排除负数或用 NOT_OK 体检；
6. **四种取整函数混用**：-3.7 用 ROUND 是 -4、用 TRUNC 是 -3，报警边界就差这一度；明确需求再选；
7. **27648 写错**：写成 32767 或 27646 都会导致标定比例偏差，这是模拟量最高频的笔误；
8. **NORM_X 的 MIN/MAX 与 VALUE 类型不一致**：三者必须同类型（都用 Int 或都用 Real），OUT 是 Real；
9. **MD 地址重叠**：MD40 占 MB40~MB43，这个区域里不能再放 MW40、MW42 等重叠地址变量（本篇 MOD 案例特意选用紧邻其后的 MW44 避让）；
10. **不处理欠量程/断线**：传感器断线时原始值为负，不拦截就会出现"负温度"这种荒唐数据，务必像本篇案例一样先判断再换算；
11. **通道量程组态与程序不符**：4-20mA 和 0-20mA 只差一个组态项，温度却对不上号，排查时优先核对硬件组态。

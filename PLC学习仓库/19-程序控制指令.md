# 第19讲 程序控制指令：给程序装上"方向盘"

## 📖 学习目标

1. 掌握跳转指令 JMP、JMPN 与跳转标签 LABEL 的配合用法，能实现"根据条件跳过某段程序"；
2. 理解 RET 返回指令的作用，学会在 FC/FB/OB 中提前退出当前块；
3. 理解 CPU 循环监控时间（看门狗）的概念，掌握 RE_TRIGR 重触发指令的用途；
4. 搞懂 EN/ENO 机制，会用 ENO 串联检查指令链错误，并了解 GET_ERROR 的配合方法；
5. 知道跳转指令的使用场景与"不建议滥用"的原因，写出结构清晰的程序。

---

## 一、程序的执行顺序与为什么要"跳转"

先回顾 CPU 的工作方式：PLC 逐条、逐网络地**从上到下**扫描执行程序——读输入 → 执行程序 → 写输出，一个循环接一个循环。这就像一列火车沿着固定轨道开，每一站（每个网络）都要停。

但有时候我们希望"这一站直接开过去，不停"：

- 设备处于维修模式时，报警程序段完全没必要执行，直接跳过；
- 某些初始化工作只需要在特定条件下做一次，平时不必每个周期都扫一遍；
- 程序出现异常时，希望立即退出当前块，后面的代码一行都不再执行。

**程序控制指令**（位于 TIA Portal 指令目录【基本指令 → 程序控制】）就是给这列火车装上"方向盘"和"刹车"：JMP/JMPN 负责改道，LABEL 是路标，RET 是中途下车，RE_TRIGR 是给"限时比赛"重新计时。

用图对比一下"直行"和"改道"：

```
  无跳转（每个网络都顺序执行）      有跳转（按条件改道执行）

  网络1 → 网络2 → 网络3 → … → 网络N        网络1
  └────────── 每站都停 ──────────┘          │ 条件成立（JMP）
                                       ↓ 跳到标签「结束段」
                                       网络8 → 网络9（结束）
                                    （网络2~7 被跳过，一行都不执行，
                                      其中的输出线圈保持原值）
```

本讲要学的指令总览：

| 指令 | 类别 | 一句话功能 |
|------|------|------------|
| JMP / JMPN | 跳转 | 条件满足/不满足时跳到标签处 |
| LABEL | 标签 | 跳转的"着陆点" |
| RET | 返回 | 提前退出当前块 |
| RE_TRIGR | 看门狗 | 重置循环监控计时器 |
| EN / ENO | 框机制 | 控制执行 / 报告执行无错 |

## 二、跳转指令

### 2.1 JMP（条件跳转）：满足条件就"改道"

JMP 是一个**线圈型指令**：它像普通线圈一样接在能流上，当前面的逻辑结果（RLO）为 1 时，CPU 立刻跳到指定的标签处继续执行；RLO 为 0 时不跳，顺序往下走。

**使用方法**（两步）：

1. 在跳转目标位置插入**跳转标签（LABEL）**，给它起一个名字，如「结束段」；
2. 在跳转起点插入 JMP 线圈，填入同样的标签名。

```
网络 1：条件满足 → 跳到「结束段」
       条件
  ------|  |----------(  JMP  「结束段」  )----
                          │
                          ↓  RLO=1 时，程序"瞬间移动"到标签处

网络 2：这一段会被跳过（不执行）
       ……

网络 9：「结束段」← 跳转标签(LABEL)，程序从这里继续
       ……
```

### 2.2 JMPN（条件不满足时跳转）

JMPN 与 JMP 恰好相反：**RLO = 0 时跳转**，RLO = 1 时不跳。

| 指令 | 跳转条件 | 典型用法 |
|------|----------|----------|
| JMP | 前面条件 = 1（满足） | "满足某条件就跳过这段" |
| JMPN | 前面条件 = 0（不满足） | "只有不满足才跳过，满足时执行这段" |

举个直观例子：复位按钮 I0.3 接到 JMPN 的能流上——按钮**没按**（I0.3 = 0）时 JMPN 跳转，跳过"复位确认"那段程序；按钮**按下**时反而顺序执行，完成复位动作。

### 2.3 跳转标签（LABEL）的使用规则

标签是跳转的"着陆点"，在 TIA Portal 的【基本指令 → 程序控制】中叫 LABEL（插入后显示为一行标签名）。使用时必须遵守：

1. **同一个块内**：标签和引用它的 JMP/JMPN 必须在同一个 OB/FB/FC 里，不能跨块跳转（跨块请用调用 FC/FB）；
2. **名字唯一**：同一个块里标签名不能重复；
3. **先起名后引用或先引用后定义都可以**：JMP 在上、标签在下（向下跳）最常见；标签在上、JMP 在下（向上跳）语法也允许，但会形成"回环"，必须慎重（见 2.4）；
4. **标签要放在网络里的执行路径上**：程序执行到标签行时视为正常继续，标签本身不改变任何输出；
5. **被跳过的网络，其线圈不刷新**：跳过去的那些网络里的输出线圈保持**上一次的值**，不会自动变 0。这是跳转最重要的副作用，务必牢记。

### 2.4 跳转的使用场景与注意事项（为什么不建议滥用）

**适合用跳转的场景**：

- 模式切换：手动/自动/维修三种模式，用 JMP 快速选择执行哪一大段程序；
- 大段程序的条件旁路：调试期间临时跳过某段尚未完成的功能；
- 提前结束：块开头做完检查，发现条件不对就跳到块尾。

**为什么不建议滥用**：

1. **可读性差**：跳转多了，程序像"面条"一样上蹿下跳，读程序的人要在几十个网络之间来回翻，很快晕头转向；
2. **维护性差**：以后插入或删除一个网络，跳转关系可能悄悄错位，埋下隐蔽 bug；
3. **容易被跳过的输出"冻结"**：被跳过的网络不执行，输出保持旧值。初学者经常以为是"程序坏了"，其实是输出被冻结在最后一次的值上；
4. **向上跳转容易造成死循环**：如果跳回去的段落里没有退出条件，CPU 会在这一段里无限打转，超过循环监控时间（见第四节）后 CPU 直接停机；
5. **更优雅的替代品**：把可选择执行的程序段放进不同的 FC/FB，用 CALL 指令配合条件调用——结构清晰得多，这正是后续章节要讲的内容。

经验法则：**一个块里跳转不要超过两三处；能用 IF 思维（条件 + 线圈）解决的，就不用跳转。**

### 2.5 三种典型的跳转编程模式

**模式一：整段旁路**（本讲案例使用）——条件成立时跳过一大段程序：

```
网络 1：条件成立 → JMP 跳到「结束段」
网络 2~7：可被跳过的程序段
网络 8：LABEL「结束段」+ 收尾程序
```

**模式二：二选一路径**——两个 JMP 各奔东西，最后汇合：

```
网络 1：维修模式 → 跳到「维修显示段」
         I0.2
  --------|  |--------(  JMP  「维修显示段」  )----

网络 2~5：正常生产程序段（维修模式下被跳过）

网络 6：LABEL「维修显示段」+ 维修画面数据段
         （正常模式从网络 2 顺序执行到这里，同样会经过）

网络 7：汇合段——无论走哪条路，最后都要做的收尾工作
```

**模式三：边沿触发跳转**——JMP 线圈前的条件如果是普通电平信号，条件一直成立就一直跳；若希望"只在事件发生的一瞬间改道"（例如按一下按钮才做一次的特殊处理），在 JMP 前用上升沿触点：

```
网络 1：按下按钮的瞬间 → 跳到一次性处理段
        处理按钮
         I0.7
  --------| P |--------(  JMP  「一次性处理段」  )----
```

**JMP 与"条件调用 FC/FB"的对比**（调用指令是后续章节内容，先建立概念）：

| 对比项 | JMP 跳转 | 条件调用 FC/FB |
|--------|----------|----------------|
| 程序组织 | 仍在一个大块里翻页 | 天然按功能分块 |
| 可读性 | 差（跳来跳去像面条） | 好（每块职责单一） |
| 局部变量/接口 | 无 | 有，数据隔离清晰 |
| 复用性 | 无 | 同一块可多处调用 |
| 使用建议 | 只在少数场合使用 | 首选的结构化做法 |

## 三、返回指令 RET：提前退出当前块

RET（Return，从块返回）也是一个线圈型指令：前面的 RLO 为 1 时，**立即结束当前块**，回到调用者继续执行；RLO 为 0 时继续执行本块后面的程序。

```
网络 5：紧急情况 → 立即退出本块
       紧急停止
  ------|  |----------(  RET  )----
                         │
                         ↓ RLO=1 时本块到此为止，后面的网络全部不执行

网络 6~10：紧急停止时不会执行
```

**使用要点**：

1. RET 可以用在 OB、FB、FC 中。在 OB 里 RET 结束的是**本次循环对这个 OB 的扫描**；在 FC/FB 里 RET 结束本块、返回调用处；
2. 若 RET 线圈直接接在母线上（无条件），那么程序执行到这里**必然返回**，等于在块中间"截断"程序——除非有意为之，否则别这么干；
3. FC/FB 正常执行到最后一个网络也会自然返回，RET 的价值在于"**提前**"退出；
4. 典型用途：块开头的参数合法性检查——发现 IN 传来的数值非法，立即 RET，避免用错误数据继续运算。

## 四、看门狗指令 RE_TRIGR：长程序段的"保命符"

### 4.1 什么是循环监控时间（看门狗）

CPU 每个循环周期除了执行程序，还有固定开销。为了防止程序"卡死"，CPU 内置了一个**循环监控计时器**，俗称看门狗（Watchdog）：

```
  一个循环周期：
  |←读输入→|←——— 执行 OB1 程序 ———→|←写输出→|
  0ms      2ms                    25ms      27ms
  ↑ 从周期开始，看门狗开始计时
  ↑ 循环监控时间（在 CPU 属性中设置，默认 150ms）
  ↑ 若一个周期超过监控时间 → CPU 报"时间错误"，进入 STOP！
```

普通程序几十毫秒就跑完一个周期，离 150ms 很远。但如果程序里有超大循环（比如对大数组做复杂处理），单个周期可能超时——这时 CPU 会"看门狗超时"停机，现场设备瞬间失控。

### 4.2 RE_TRIGR：把看门狗的表"清零重计"

**指令位置**：【基本指令 → 程序控制】，框型指令 RE_TRIGR。

```
  （长任务开始前重新计时，直接接母线或接条件）
  --------+------------------+
          |    RE_TRIGR      |
          |                  |
          +------------------+
```

- 执行一次 RE_TRIGR，循环监控计时器就**清零重新计时**，相当于告诉看门狗："别急，我还在好好干活"；
- 它只有 EN（隐含在能流上）和 ENO，没有其他参数；
- 用法：在耗时很长的程序段**之前**调用一次；如果这段长任务内部可拆分，可在段中间再调用，让计时余量更足；
- 注意：RE_TRIGR 只是"续命"，不是免死金牌。如果程序逻辑上真的死循环（永远出不来），再多重触发也救不了，CPU 照样停机——重触发的前提是程序在**正常推进**，只是慢。

**长程序段中的典型布局**：

```
网络 1：长任务开始前，把看门狗的表清零
  --------+------------------+
          |    RE_TRIGR      |
          +------------------+

网络 2~40：耗时的数据处理段（比如对大数组逐项运算）
          ……

网络 41：长任务过半，再续一次表
  --------+------------------+
          |    RE_TRIGR      |
          +------------------+

网络 42~80：后半段处理
          ……
```

**在 CPU 属性中查看/修改循环监控时间**：设备组态 → 双击 CPU → 属性 → "循环"（Cycle）相关设置区，可以看到循环监控时间的当前值（默认 150ms），可按需加大，但"加大时间"和"优化程序"是两码事——能优化就别硬扛。

## 五、使能输出（ENO）：让错误"看得见"

### 5.1 什么是 EN / ENO

前面各章我们早就见过带 EN 的功能框（定时器、数学运算、MOVE 等）：

- **EN（Enable，使能输入）**：左侧能流接通（EN = 1）时，这个框才真正执行；EN = 0 时框不执行，输出保持旧值；
- **ENO（Enable Out，使能输出）**：框执行**且没有出错**时，ENO = 1，能流可以从右侧继续传给下一个框；执行中**发生错误**时 ENO = 0，能流中断。

可以把框想成流水线上的一道工序：EN 是"开工令"，ENO 是"本道工序合格，可流入下一道"的检验章。ENO 什么时候会是 0？举几个典型例子：

- 数学运算溢出（结果超出数据类型范围）；
- 转换指令遇到无法转换的内容（比如把非数字字符串转数值）；
- 时间运算超出 DTL/Time 的表示范围；
- 字符串指令的结果超过目标字符串的最大长度。

### 5.2 如何处理指令链中的 ENO 状态

**方法一：ENO 串联——"一错全停"**

把前一个框的 ENO 接到后一个框的 EN，形成链：

```
  ----+-------------+    +-------------+    +-------------+
      |  STRG_VAL   |    |   T_ADD     |    |    MOVE     |
  ----|IN        ENO|----|          ENO|----|             |
      |          OUT|    |             |    |          OUT|
      +-------------+    +-------------+    +-------------+
        （前一步出错 → ENO=0 → 后面的框全部不执行）
```

只要任何一环出错，后面的框都不执行，避免了"用错误数据继续往下算"的连锁灾难。链尾再接一个线圈（如「处理正常」M2.0），M2.0 = 1 就代表整条链都成功。

**方法二：分支检查——"出错走另一条路"**

把 ENO 接到一条分支上驱动线圈，正常时走主路、出错时置"故障标志"：

```
  ----+-----------+----( 处理正常 M2.0 )   ← ENO=1 时执行
      |  某指令    |
      |        ENO+----( 处理出错 M2.1 )   ← ENO=0 时执行
      +-----------+
```

**方法三：GET_ERROR 配合——"把错误号抓出来看"**

想知道到底错在哪，可以用 GET_ERROR 指令（在指令目录中搜索 GET_ERROR 即可找到，属于扩展指令中的错误处理类）：

```
  ----+---------------+
      |   GET_ERROR   |
      |               |
      |         ERROR-|----「错误代码」(Word)
      +---------------+
```

它读取当前块的错误状态并**复位**该状态，ERROR 输出就是错误编号。把错误号送到 HMI 或监控表，维护时一眼定位问题。配套的 GET_ERR_ID 则只读错误号、不复位状态。

**哪些情况会把 ENO 拉低？** 常见情况速查：

| 指令类别 | 典型的 ENO = 0（出错）情况 |
|----------|----------------------------|
| 数学运算（ADD/SUB/MUL/DIV 等） | 结果超出数据类型范围（如 Int 相加超过 32767） |
| 转换指令（CONV/ROUND 等） | 源操作数无法转换成目标类型 |
| STRG_VAL（字符串转数值） | 字符串内容不是合法数字 |
| T_ADD / T_SUB / T_DIFF | 时间运算结果超出类型表示范围 |
| 字符串指令（CONCAT/INSERT 等） | 结果超过目标字符串声明的最大长度 |
| 移动 MOVE | 长度不匹配等复制错误 |

**一条实用经验**：凡是"输入来自外部/人机界面/通信"的框，它的 ENO 都值得认真对待——外部数据天生不可信，ENO 串联就是你程序的自检保险丝。

## 六、典型案例：根据条件跳过程序段（JMP / JMPN 应用）

### 6.1 任务描述

电机控制系统新增两项需求：

1. **维修模式**：当维修开关 I0.2 接通时，跳过报警程序段（报警灯 Q0.2、蜂鸣器 Q0.3 保持现状，不受故障信号影响），直接执行结束段（运行指示灯 Q0.4 跟随电机 Q0.0）；
2. **复位确认**：只有真正按下复位按钮 I0.3 时才执行"复位确认段"；没按就跳过，别浪费扫描时间。

### 6.2 变量与资源清单

| 名称 | 数据类型 | 地址 | 用途 |
|------|----------|------|------|
| 启动按钮 | Bool | I0.0 | 电机启动 |
| 停止按钮 | Bool | I0.1 | 电机停止 |
| 维修模式 | Bool | I0.2 | ON 时跳过报警段 |
| 复位按钮 | Bool | I0.3 | 故障复位 |
| 过载故障 | Bool | I0.5 | 模拟故障信号 |
| 故障标志 | Bool | M0.0 | 故障锁存 |
| 电机 | Bool | Q0.0 | 主输出 |
| 报警灯 | Bool | Q0.2 | 报警指示 |
| 蜂鸣器 | Bool | Q0.3 | 声音报警 |
| 运行指示灯 | Bool | Q0.4 | 运行指示 |
| 复位确认记录 | Word | MW60 | 演示"复位段被执行过" |

### 6.3 程序（梯形图）

```
网络 1：电机启保停（标准自锁回路）
        启动按钮          停止按钮                电机
         I0.0              I0.1                  Q0.0
  +-------|  |-------+-------|/|------------------(    )----
  |                  |
  |      电机        |
  |      Q0.0        |
  +-------|  |-------+
       （自锁触点）

网络 2：故障锁存
        过载故障          故障标志
         I0.5              M0.0
  --------|  |------------------(  S  )----

网络 3：维修模式 → 跳到「结束段」（跳过报警段）
        维修模式
         I0.2
  --------|  |----------(  JMP  「结束段」  )----
                            │
                            ↓
网络 4：报警灯（维修模式下被跳过，Q0.2 保持原值）
        故障标志
         M0.0
  --------|  |------------------(    )----  Q0.2

网络 5：蜂鸣器（同样会被跳过）
        故障标志
         M0.0
  --------|  |------------------(    )----  Q0.3

网络 6：复位按钮没按 → 跳过复位确认段（JMPN：RLO=0 时跳转）
        复位按钮
         I0.3
  --------|  |----------(  JMPN  「复位确认段结束」  )----
                            │
                            ↓
网络 7：复位确认段（复位故障标志 + 写入确认记录 16#00AA）
  --------+------------------+
          |      MOVE        |
          |                  |
 16#00AA--|IN             OUT|-- MW60（复位确认记录）
          |               ENO|--------(  R  )---- M0.0（复位故障标志）
          +------------------+

网络 8：复位确认段结束 ← 跳转标签(LABEL)「复位确认段结束」

网络 9：结束段 ← 跳转标签(LABEL)「结束段」：运行指示灯跟随电机
        电机
         Q0.0
  --------|  |------------------(    )----  Q0.4
```

### 6.4 程序分析

- **网络 1~2**：常规的启保停与故障锁存，前面章节已学，不再展开；
- **网络 3**：维修模式 I0.2 接通 → JMP 跳转，网络 4、5（报警灯、蜂鸣器）被整体跳过。关键副作用：跳过期间 Q0.2、Q0.3 **保持跳转前一刻的状态**——如果跳转前报警灯是亮的，它会一直亮着"冻结"住，直到维修模式解除、网络重新执行；
- **网络 6~7**：JMPN 的能流条件是 I0.3。按钮按下时 I0.3 = 1 → RLO = 1 → JMPN **不**跳 → 执行网络 7（写标记值 16#00AA 到 MW60，并通过 MOVE 的 ENO 输出复位故障标志 M0.0，使报警灯和蜂鸣器熄灭）；按钮没按 → RLO = 0 → JMPN 跳过网络 7。这体现了 JMPN 的典型句式："**只有条件满足时才执行这一小段**"；
- **网络 8、9**：两个标签像两块"路牌"，网络 3 的 JMP 直接落在「结束段」，网络 6 的 JMPN 只跳过一小段。标签不产生任何动作，只提供着陆点。

### 6.5 PLCSIM 仿真验证步骤

**第①步：需要建立的变量清单**

| 名称 | 数据类型 | 地址 |
|------|----------|------|
| 启动按钮 | Bool | I0.0 |
| 停止按钮 | Bool | I0.1 |
| 维修模式 | Bool | I0.2 |
| 复位按钮 | Bool | I0.3 |
| 过载故障 | Bool | I0.5 |
| 故障标志 | Bool | M0.0 |
| 电机 | Bool | Q0.0 |
| 报警灯 | Bool | Q0.2 |
| 蜂鸣器 | Bool | Q0.3 |
| 运行指示灯 | Bool | Q0.4 |
| 复位确认记录 | Word | MW60 |

**第②步：启动仿真并下载程序**

1. 编译项目（所有网络必须无语法错误，尤其标签名要与 JMP/JMPN 中填写的一致）；
2. 点击"启动仿真"打开 S7-PLCSIM，选择对应 CPU 并确认；
3. "下载到设备"，接口选 PLCSIM，完成下载后把 CPU 拨到 RUN。

**第③步：用监控表模拟输入/修改变量**

1. 添加监控表，把上表变量全部拖入，点击"监视"；
2. 模拟按钮类输入：在"修改"列把 I0.0 从 0 改 1 再改回 0（模拟点动按钮），每次修改后点"立即修改"；
3. 模拟开关类输入：把 I0.2（维修模式）改为 1 并保持，模拟维修人员合上维修开关；
4. 模拟故障：把 I0.5 置 1（故障发生），再置 0（故障消失，M0.0 因锁存仍为 1）。

**第④步：预期结果**

- 正常时序：I0.0 启动 → Q0.0 = 1、Q0.4 = 1；I0.5 故障 → Q0.2 亮、Q0.3 响；
- 打开维修模式（I0.2 = 1）：Q0.2、Q0.3 **保持故障发生时的状态**（冻结），不再随 M0.0 变化；Q0.4 仍正常跟随 Q0.0；
- 关闭维修模式：Q0.2、Q0.3 立即恢复受 M0.0 控制（M0.0 仍锁存为 1 → 报警继续）；
- 复位：按下 I0.3 一瞬间，M0.0 被复位、MW60 变为 16#AA；不按 I0.3 时 MW60 保持 0；
- 电机停止（I0.1）后 Q0.0 = 0，Q0.4 随之为 0。

**第⑤步：功能验证清单（逐项）**

- ☐ 启保停正常：I0.0 启动、I0.1 停止、运行中自锁；
- ☐ I0.5 置 1 后 Q0.2 亮、Q0.3 响，I0.5 撤销后因 M0.0 锁存仍然报警；
- ☐ 维修模式打开后，网络 4、5 不再执行，Q0.2/Q0.3 冻结在打开前一刻的值；
- ☐ 维修模式期间，Q0.4 仍正常跟随 Q0.0（结束段没有被跳过）；
- ☐ 维修模式关闭后，报警输出恢复受控；
- ☐ 不按 I0.3 时 MW60 一直是 0（复位确认段被 JMPN 跳过）；
- ☐ 按下 I0.3 时 MW60 变为 16#AA 且 M0.0 复位（复位确认段被执行）。

**第⑥步：结果不符时的排查方法**

1. **提示"未定义跳转标签"或编译报错**：JMP/JMPN 中填的名字与 LABEL 名字不一致（注意中文标签别多空格），或标签插到了另一个块里；
2. **维修模式下报警没被"冻结"而是立刻熄灭**：说明跳转没生效，检查 I0.2 是否真的为 1、JMP 线圈前是否还有别的串联条件；
3. **维修模式解除后报警不恢复**：检查被跳过网络的触点条件（M0.0 锁存逻辑），以及维修模式开关是否真的断开；
4. **MW60 一直是 16#AA**：JMPN 写成了 JMP（条件相反），或 I0.3 常闭/常开用反；
5. **按了复位按钮程序没反应**：确认 I0.3 的修改在监控表里点了"立即修改"；检查网络 7 中的 ( R ) M0.0 线圈是否已正确连接到 MOVE 的 ENO 输出端；
6. **CPU 转入 STOP**：查看诊断缓冲区；若自行加了向上跳转造成死循环，会触发时间错误——删掉回环或在其中加入 RE_TRIGR 与退出条件。

## 📌 本章小结

| 指令 | 类型 | 触发条件 | 作用 |
|------|------|----------|------|
| JMP | 线圈 | RLO = 1 | 跳到同名标签处继续执行 |
| JMPN | 线圈 | RLO = 0 | 条件不满足时才跳转 |
| LABEL | 标签 | — | 跳转的着陆点，与 JMP 同块、名字唯一 |
| RET | 线圈 | RLO = 1 | 提前退出当前块，返回调用处 |
| RE_TRIGR | 功能框 | EN = 1 | 重触发循环看门狗计时，防长程序超时停机 |
| EN/ENO | 框引脚 | — | EN 控制是否执行；ENO 报告执行无错，可串联检查 |
| GET_ERROR | 功能框 | EN = 1 | 读取并复位块内错误状态，输出错误代码 |

核心思想：**JMP/JMPN 是方向盘，LABEL 是路牌，RET 是紧急出口，RE_TRIGR 是给看门狗续表的秒表按钮，ENO 是流水线的合格检验章。**

## ⚠️ 常见错误与注意事项

1. **以为被跳过的输出会变 0**：跳过的网络根本不执行，线圈保持旧值（冻结）。需要"跳过时输出为 0"的效果，应在跳转之前先把相关输出清零；
2. **标签与 JMP 不在同一块**：跨块跳转非法，编译报错。跨块请改用条件调用 FC/FB；
3. **JMPN 条件理解反了**：JMPN 是"RLO = 0 才跳"。调试时先单独验证这个指令的行为，再接入正式逻辑；
4. **向上跳转造成死循环**：跳回前面的网络且没有退出条件，CPU 会在本周期内打转直到看门狗超时停机。新手请只向下跳；
5. **滥用跳转**：满屏 JMP 的程序没人愿意接手。能用条件线圈/条件调用的就别用跳转，一个块里的跳转控制在两三处以内；
6. **RET 无条件接母线**：RET 前面没有任何条件时，程序执行到那里必然返回，后面的网络永远执行不到，属于典型"自杀式"写法；
7. **把 ENO 当普通输出位用**：ENO 表达的是"执行是否出错"，不是业务结果。判断业务结果请用比较指令；
8. **ENO 断了却没人知道**：串联链中间出错，后面全部静默不执行。建议在链尾放一个"处理正常"标志线圈，或在链上用 GET_ERROR 抓错误号；
9. **RE_TRIGR 滥用**：正常程序每个周期远小于监控时间，不需要 RE_TRIGR。只有确实存在长任务时才用，并且不能用它掩盖真正的死循环；
10. **修改输入后忘记"立即修改"**：在监控表里改了 I0.2 但没点激活图标，程序根本没收到，误以为跳转失效；
11. **RE_TRIGR 的位置**：应放在长任务之前；放在周期末尾对"本周期超时"没有补救意义。

## 一、字符串基础

### 1.1 String 和 WString：单字节与双字节

字符串就是"一串字符"。S7-1500 提供两种字符串类型，核心区别是**每个字符占几个字节**：

| 对比项 | String | WString |
|--------|--------|---------|
| 每个字符占用 | 1 字节 | 2 字节 |
| 头部占用 | 2 字节 | 4 字节 |
| 最大长度 | 254 个字符 | 16383 个字符 |
| 能否存中文 | 不保证（依赖字符集，**不推荐**） | 完整支持（UTF-16 编码） |
| 声明写法 | String[n] | WString[n] |
| 对应的单字符类型 | Char（1 字节） | WChar（2 字节） |
| 典型场景 | ASCII 报文、与老设备/仪表通信 | HMI 画面显示、含中文的内容 |

打个比方：String 像只能写英文和数字的窄格子笔记本，一个格子一个符号；WString 像双行格子的笔记本，每个符号占两个格子，所以能装下汉字这种"大块头"。**凡是内容里要出现中文的，一律选 WString。**

### 1.2 字符串的定义和初始化

字符串在**全局 DB 或块接口**中声明，方括号里写最大长度：

- `产品批号 : String[10]` —— 最多放 10 个字符，实际占用 12 字节（2 字节头部 + 10 字节字符区）；
- `显示文本 : WString[30]` —— 最多放 30 个字符。

内存结构长这样（以 String[10] 存入 'PLC150' 为例）：

```
  字节编号:   [0]     [1]     [2]  [3]  [4]  [5]  [6]  [7]  [8] ~ [11]
  存放内容: | 最大=10| 实际=6 |  P  |  L  |  C  |  1  |  5  |  0  |  空   |
             └─头部2字节─┘ └────────── 字符区（最多10字节）──────────┘
```

**头部两个字节的含义**：

- 第 1 字节：声明的**最大长度**（决定这块"地皮"多大，永远不会变）；
- 第 2 字节：**当前实际长度**（随内容自动变化，LEN 指令读的就是它）。

**初始化方法**：在 DB 中给变量填"起始值"（如 `'PLC150'`），下载后 CPU 启动即有初值；也可以在 OB100 中用 MOVE 给字符串赋初值。注意：赋给字符串的内容超过声明的最大长度时，放不下的部分会被丢弃，指令 ENO 报错——声明长度要留足余量。

### 1.3 Char 类型的使用

Char 占 1 字节，专门存放**单个**字符，常用作"字符与数字对照"：

```
  'A' = 16#41      'a' = 16#61      '0' = 16#30      空格 = 16#20
```

- Char 变量可以和字符常量直接比较（CMP == 'A'），常用在报文校验里；
- WChar 是它的双字节兄弟，一个 WChar 可以就是一个汉字；
- 想从字符串里取出"第 i 个字符"，可用 MID 指令提取长度为 1 的子串（下一节讲）；Char 与 String 是不同类型，不能直接互相赋值，需要经过提取/转换。

## 二、字符串操作指令

> **指令位置**：本节的 LEN、CONCAT、LEFT、RIGHT、MID、FIND、DELETE、INSERT、REPLACE 以及 S_CONV，都在 TIA Portal 的【扩展指令 → 字符串 + 字符】目录中（在指令目录上方搜索框输入指令名可快速定位）。这些指令对 String 和 WString 都适用（同一网络中类型必须一致）。

### 2.1 LEN：查询字符串长度

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN | String / WString | 待测字符串 |
| OUT | Int | 字符个数（读的是头部的"实际长度"） |

```
  --------+----------------+
          |      LEN       |
          |                |
 「产品批号」-|IN           OUT|-- 「批号长度」(Int)
          +----------------+
```

小例子：「产品批号」= 'PLC150' → OUT = 6。注意是"字符个数"不是"字节数"，WString 里的 1 个汉字也只算 1 个字符。

### 2.2 CONCAT：字符串连接

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN1 | String / WString | 前半段 |
| IN2 | String / WString | 后半段 |
| OUT | 同类型 | 连接结果 |

```
  --------+--------------------+
          |       CONCAT       |
          |                    |
 「设备名称」-|IN1             OUT|- 「前半段」
      '-' -|IN2                 |
          +--------------------+
```

小例子：CONCAT('设备', '1') = '设备1'。CONCAT 一次只能接两段，三段要两个 CONCAT 串联（前一个的 ENO 接后一个的 EN）。结果超过 OUT 的最大长度 → ENO = 0。

### 2.3 LEFT / RIGHT / MID：提取子字符串

| 指令 | 引脚 | 含义 | 小例子（IN = 'PLC-1500'） |
|------|------|------|---------------------------|
| LEFT | IN / L / OUT | 从**左边**取 L 个字符 | L=3 → 'PLC' |
| RIGHT | IN / L / OUT | 从**右边**取 L 个字符 | L=4 → '1500' |
| MID | IN / L / P / OUT | 从第 **P** 位起取 L 个字符（P 从 1 数起） | L=4, P=5 → '1500' |

```
  --------+--------------------+
          |        MID         |
          |                    |
 「接收报文」-|IN              OUT|- 提取结果
  「长度L」--|L                   |
  「位置P」--|P                   |
          +--------------------+
```

注意：位置 P 从 **1** 开始数，不是 0——这和很多编程语言不同，是最容易出错的地方。L 为 0 时结果是空字符串。

### 2.4 FIND：查找子字符串位置

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN1 | String / WString | 要**找的**子串 |
| IN2 | String / WString | **被搜索的**长字符串 |
| OUT | Int | 子串第一次出现的位置（从 1 数起）；找不到 = 0 |

```
  --------+--------------------+
          |        FIND        |
          |                    |
      ':' -|IN1             OUT|- 「冒号位置」(Int)
 「接收报文」-|IN2                 |
          +--------------------+
```

小例子：FIND(IN1='1500', IN2='S7-1500') = 4（S 是第 1 位，1 是第 4 位）。**OUT = 0 是"没找到"的信号**，判断"报文里有没有冒号"就靠它。IN1 和 IN2 别接反：接反了就变成"在':'里找报文"，结果永远是 0。

### 2.5 DELETE：删除字符

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN | String / WString | 原字符串 |
| L | Int | 要删除的字符个数 |
| P | Int | 从第 P 位开始删（P 从 1 数起） |
| OUT | 同 IN | 删除后的结果 |

```
  --------+--------------------+
          |       DELETE       |
          |                    |
 「接收报文」-|IN              OUT|- 删除结果
  「个数L」--|L                   |
  「位置P」--|P                   |
          +--------------------+
```

小例子：DELETE(IN='ABCDEF', L=2, P=3) → 把第 3~4 位的 'CD' 删掉 → 'ABEF'。

### 2.6 INSERT：插入字符串

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN1 | String / WString | 要插入的字符串 |
| IN2 | String / WString | 被插入的原字符串 |
| P | Int | 插入到第 P 个字符**之后**（P=0 表示插在最前面） |
| OUT | 同类型 | 结果 |

```
  --------+--------------------+
          |       INSERT       |
          |                    |
 「插入文本」-|IN1             OUT|- 结果
 「原文本」---|IN2                 |
  「位置P」--|P                   |
          +--------------------+
```

小例子：INSERT(IN1='XYZ', IN2='12345', P=2) → 插到第 2 个字符后面 → '12XYZ345'。

### 2.7 REPLACE：替换字符串

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN1 | String / WString | 用来替换的"新文本" |
| IN2 | String / WString | 原字符串 |
| P | Int | 从第 P 位开始替换 |
| L | Int | 被替换掉的字符个数 |
| OUT | 同类型 | 结果 |

```
  --------+--------------------+
          |       REPLACE      |
          |                    |
 「新文本」---|IN1             OUT|- 结果
 「原文本」---|IN2                 |
  「位置P」--|P                   |
  「个数L」--|L                   |
          +--------------------+
```

小例子：REPLACE(IN1='XYZ', IN2='ABCDEF', L=2, P=3) → 从第 3 位起的 2 个字符 'CD' 被 'XYZ' 取代 → 'ABXYZEF'。

## 三、字符串与其他类型转换

### 3.1 S_CONV：最简单的转换（字符串 ↔ 数值）

**指令位置**：【扩展指令 → 字符串 + 字符】目录。

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN | String 或数值（Int/DInt/Real 等） | 待转换内容 |
| OUT | 与 IN 相反的类型 | 转换结果 |

S_CONV 是"双向通用"的，方向由 IN/OUT 的类型自动决定：

- IN 接数值：Int 123 → OUT（String）= '123'；
- IN 接字符串：String '45.6' → OUT（Real）= 45.6。

它的优点是简单，缺点是**没有格式控制**（不能指定小数位数、不能补齐位数）。要"漂亮的"格式输出，用下面的 VAL_STRG。

### 3.2 NUM_TO_STR / STR_TO_NUM 的真身：VAL_STRG 与 STRG_VAL

"数值转字符串 / 字符串转数值"这两件事，很多教材习惯称为 NUM_TO_STR / STR_TO_NUM。在 TIA Portal 中，对应的指令是：

- **VAL_STRG**（数值 → 字符串，即"NUM_TO_STR"）；
- **STRG_VAL**（字符串 → 数值，即"STR_TO_NUM"）。

注意：这两条位于【基本指令 → 转换】目录（不是字符串目录），功能比 S_CONV 强大得多，可以指定小数位数、符号格式等。

**VAL_STRG 引脚表**（数值转字符串）：

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN | SInt ~ LReal | 待转换的数值 |
| P | Int | 写入字符串的起始位置（从 1 数起） |
| SIZE | USInt | 结果占用多少个字符（含符号与小数点） |
| PREC | USInt | 小数位数（0 表示整数） |
| FORMAT | Word | 格式：b0=0 仅负数带负号 / 1=正数也带"+"；b1=0 小数点用"." / 1 用","；常用 16#0000 |
| OUT | String | 目标字符串 |

```
  --------+--------------------+
          |      VAL_STRG      |
          |                    |
 「温度值」---|IN              OUT|- 「温度字符串」(String[10])
        6 --|SIZE                |
        1 --|PREC（1位小数）     |
  16#0000 --|FORMAT              |
        1 --|P                   |
          +--------------------+
```

小例子：「温度值」(Real) = 23.5，SIZE=6，PREC=1 → OUT = '  23.5'（靠右对齐，不足位补空格）。

**STRG_VAL 引脚表**（字符串转数值）：

| 引脚 | 数据类型 | 说明 |
|------|----------|------|
| EN / ENO | Bool | 使能 / 出错指示 |
| IN | String | 源字符串 |
| P | Int | 从第几位开始读取数字（从 1 数起） |
| SIZE | USInt | 最多读取的字符个数 |
| PREC | USInt | 小数位数 |
| FORMAT | Word | 同上，常用 16#0000 |
| OUT | SInt ~ LReal | 转换出的数值 |

```
  --------+--------------------+
          |      STRG_VAL      |
          |                    |
 「设定文本」-|IN              OUT|- 「设定值」(Real)
        1 --|P                   |
        6 --|SIZE                |
        1 --|PREC                |
  16#0000 --|FORMAT              |
          +--------------------+
```

小例子：'85.5' → OUT = 85.5。字符串内容不是合法数字时 ENO = 0、OUT 保持旧值——这正是上一章 ENO 机制的用武之地。

## 四、典型案例一：拼接设备编号和状态信息字符串

### 4.1 任务描述

把设备编号和运行状态拼成一条给 HMI 显示的文本：电机 Q0.0 运行时显示「设备1-运行中」，停止时显示「设备1-停止」。内容含中文，所以全部使用 WString。

### 4.2 变量与资源清单

在全局 DB「报文数据」中创建：

| 名称 | 数据类型 | 起始值 | 用途 |
|------|----------|--------|------|
| 设备名称 | WString[10] | '设备1' | 设备编号 |
| 状态词 | WString[6] | '停止' | 运行/停止文本 |
| 前半段 | WString[15] | — | 中间结果：'设备1-' |
| 显示文本 | WString[30] | — | 最终拼接结果 |

（另有电机 Q0.0，来自启保停程序。）

### 4.3 程序（梯形图）

```
网络 1：电机运行 → 状态词 = '运行中'
        电机
         Q0.0
  --------|  |----+------------------+
                  |      MOVE        |
                  |                  |
      '运行中' ---|IN             OUT|--- 「状态词」(WString)
                  +------------------+

网络 2：电机停止 → 状态词 = '停止'
        电机(常闭)
         Q0.0
  --------|/|-----+------------------+
                  |      MOVE        |
                  |                  |
       '停止' ----|IN             OUT|--- 「状态词」(WString)
                  +------------------+

网络 3：拼前半段：设备名称 + '-'
  --------+--------------------+
          |       CONCAT       |
          |                    |
 「设备名称」-|IN1             OUT|- 「前半段」
      '-' -|IN2                 |
          +--------------------+

网络 4：拼最终文本：前半段 + 状态词
  --------+--------------------+
          |       CONCAT       |
          |                    |
  「前半段」--|IN1             OUT|- 「显示文本」
  「状态词」--|IN2                 |
          +--------------------+
```

### 4.4 程序分析

- 网络 1、2 是互斥的两条路：Q0.0 = 1 时状态词为'运行中'，否则为'停止'，状态词永远实时有效；
- 网络 3、4 每个扫描周期都执行（接母线），把「设备名称」+ '-' + 「状态词」三级拼接成「显示文本」；
- 两个 CONCAT 分两步完成三段拼接（CONCAT 每次只有两个输入）；工程上可把前一个 CONCAT 的 ENO 接后一个的 EN，任何一步出错（如超出最大长度）整条链立即停摆，防止产出残缺文本；
- 设备编号改名时只需改 DB 起始值'设备1'，不用动程序——这就是把"数据"和"逻辑"分开的好处。

### 4.5 PLCSIM 仿真验证步骤

**第①步：需要建立的变量清单**

| 名称 | 数据类型 | 地址/位置 |
|------|----------|-----------|
| 电机 | Bool | Q0.0 |
| 启动按钮 | Bool | I0.0 |
| 停止按钮 | Bool | I0.1 |
| 设备名称 | WString[10] | DB「报文数据」 |
| 状态词 | WString[6] | DB「报文数据」 |
| 前半段 | WString[15] | DB「报文数据」 |
| 显示文本 | WString[30] | DB「报文数据」 |

**第②步：启动仿真并下载程序**

1. 建立 DB「报文数据」并填好起始值，编译项目；
2. "启动仿真"打开 PLCSIM → 选择 CPU 确认 → "下载到设备"（接口 PLCSIM）→ 拨到 RUN。

**第③步：用监控表模拟输入/修改变量**

1. 添加监控表，放入 I0.0、I0.1、Q0.0 和 DB 中的四个字符串变量（监控表会以文本形式显示字符串内容）；
2. 点"监视"；用 I0.0 启动电机（置 1 后撤回），再用 I0.1 停止电机；
3. 也可以直接在监控表的"修改"列把「设备名称」改成'设备2'并点"立即修改"，观察显示文本跟随变化。

**第④步：预期结果**

- 电机运行：「状态词」= '运行中'，「显示文本」= '设备1-运行中'；
- 电机停止：「状态词」= '停止'，「显示文本」= '设备1-停止'；
- 手动改「设备名称」为'设备2'后，「显示文本」自动变为'设备2-运行中'（或'设备2-停止'）。

**第⑤步：功能验证清单（逐项）**

- ☐ 启动电机后显示文本为'设备1-运行中'；
- ☐ 停止电机后显示文本为'设备1-停止'；
- ☐ 「前半段」始终为'设备1-'；
- ☐ 修改设备名称变量，显示文本立即跟随；
- ☐ 电机反复启停，状态词在'运行中'/'停止'间正确切换。

**第⑥步：结果不符时的排查方法**

1. **显示文本为空**：检查两个 CONCAT 的 IN1/IN2 是否接对；确认 DB 变量有起始值且已下载；
2. **中文显示乱码或问号**：变量误用了 String（单字节），换 WString；
3. **只显示一半内容**：OUT 字符串最大长度声明太小（如显示文本只给了 WString[10]），内容被截断——把长度声明加大；
4. **状态词不变**：检查网络 1、2 的触点（常开/常闭是否写反），确认 Q0.0 真的在变化；
5. **监控表修改字符串不生效**：修改后需点"立即修改"；个别版本对 WString 直接编辑支持有限，可改用修改 DB 起始值再重新下载的方式测试。

## 五、典型案例二：解析从上位机接收的字符串命令

### 5.1 任务描述

上位机通过通信发来命令字符串，格式固定为 `CMD:命令字`，如 `CMD:START`（启动）、`CMD:STOP`（停止）。PLC 需要解析这条字符串：先确认命令头是 'CMD'，再取出命令字，分别驱动电机的启动/停止。

### 5.2 解析思路

对 'CMD:START' 做三步手术：

1. **FIND** 找冒号位置（如 4）→ 冒号位置 = 0 说明格式非法，直接不处理；
2. **LEFT** 取冒号之前的部分 → 命令头（长度 = 冒号位置 − 1）；
3. **DELETE** 删掉开头的冒号位置个字符（把 'CMD:' 整段删掉）→ 命令体；
4. 命令头 = 'CMD' 且命令体 = 'START' → 启动电机；'STOP' → 停止电机。

```
  'CMD:START'
   123456789  ← 位置从 1 数起，冒号在第 4 位
   ├─LEFT(冒号位置-1)─┤→ 'CMD'           （命令头）
   ├─DELETE(L=冒号位置, P=1)─┤→ 'START'  （命令体）
```

### 5.3 变量与资源清单

在全局 DB「通信数据」中创建：

| 名称 | 数据类型 | 起始值 | 用途 |
|------|----------|--------|------|
| 接收命令 | String[32] | '' | 上位机发来的原始字符串 |
| 冒号位置 | Int | 0 | FIND 的结果 |
| 头长度 | Int | 0 | 冒号位置 − 1 |
| 命令头 | String[10] | '' | 'CMD' |
| 命令体 | String[20] | '' | 'START' / 'STOP' |
| 上位机启动命令 | Bool | M0.3 | 解析出的启动请求 |
| 上位机停止命令 | Bool | M0.4 | 解析出的停止请求 |
| 命令处理完成 | Bool | M0.5 | 处理完毕标志 |

（另有电机 Q0.0、启动按钮 I0.0、停止按钮 I0.1。）

### 5.4 程序（梯形图）

```
网络 1：找冒号位置（直接接母线，每周期执行）
  --------+--------------------+
          |        FIND        |
          |                    |
      ':' -|IN1             OUT|- 「冒号位置」(Int)
 「接收命令」-|IN2                 |
          +--------------------+

网络 2：计算命令头长度 = 冒号位置 - 1（数学减法框 SUB）
  --------+--------------------+
          |        SUB         |
          |                    |
 「冒号位置」-|IN1             OUT|- 「头长度」(Int)
        1 --|IN2                 |
          +--------------------+

网络 3：冒号位置 > 0 → 取命令头（冒号前面的部分）
                     +-----------+
      冒号位置 ------|     >     |
                     |  (比较器) |----+（能流继续）
           0 --------|           |    |
                     +-----------+    |
                 +--------------------+
                 |        LEFT        |
 「接收命令」-----|IN              OUT-|---- 「命令头」(String[10])
  「头长度」------|L                   |
                 +--------------------+

网络 4：格式合法且命令头是 'CMD' → 删除'CMD:'得到命令体
                     +-----------+         +-----------+
      冒号位置 ------|     >     |---------|    ==     |
                     |           |         |  (比较器) |----+
           0 --------|           |  命令头 -|           |    |
                     +-----------+         +-----------+    |
                                              'CMD' --------+
                 +--------------------+
                 |       DELETE       |
 「接收命令」-----|IN              OUT-|---- 「命令体」(String[20])
  「冒号位置」----|L（删掉'CMD:'共P个）|
        1 -------|P（从第1位开始删）  |
                 +--------------------+

网络 5：命令头是 'CMD' 且 命令体 = 'START' → 置启动命令与处理完成标志
                     +-----------+         +-----------+
      命令头 --------|    ==     |---------|    ==     |----+----( S ) M0.3 上位机启动命令
                     |           |  命令体 -|           |    +----( S ) M0.5 命令处理完成
                     +-----------+         +-----------+
                      'CMD'                 'START'

网络 6：命令头是 'CMD' 且 命令体 = 'STOP' → 置停止命令与处理完成标志
                     +-----------+         +-----------+
      命令头 --------|    ==     |---------|    ==     |----+----( S ) M0.4 上位机停止命令
                     |           |  命令体 -|           |    +----( S ) M0.5 命令处理完成
                     +-----------+         +-----------+
                      'CMD'                 'STOP'

网络 7：启动命令 → 启动电机，并用完即清
        M0.3
  --------|  |----+----( S )  Q0.0  电机启动
                  +----( R )  M0.3  （自清，变成单次请求）

网络 8：停止命令 → 停止电机，并用完即清
        M0.4
  --------|  |----+----( R )  Q0.0  电机停止
                  +----( R )  M0.4

网络 9：处理完成 → 清空接收命令，防止同一条命令被反复解析
        M0.5
  --------|  |----+------------------+
                  |      MOVE        |
                  |                  |
        '' -------|IN             OUT|--- 「接收命令」
                  +------------------+
        M0.5
  --------|  |------------------( R )  M0.5
```

### 5.5 程序分析

- **网络 1、2** 每周期做"侦察"：报文里有冒号吗？在哪？命令头该有多长？
- **网络 3** 只在"冒号位置 > 0"（格式合法）时才提取命令头，防止对空字符串做无意义的手术；
- **网络 4** 在"格式合法 且 命令头是 'CMD'"双重条件通过后才提取命令体——命令头校验挡住了上位机发来的其他杂散报文；
- **网络 5、6** 用两个字符串比较识别命令字。字符串可以用 CMP 指令做 == / <> 比较（大小写敏感，'START' 和 'start' 是两个不同的字符串，上位机约定要一致）；
- **网络 7、8** 把解析结果变成对电机的启停动作，M0.3/M0.4 用完即清，变成"单次请求"；
- **网络 9** 至关重要：命令处理完立即清空「接收命令」。否则 M0.5 每个周期都会被置位、网络 7 每个周期都执行——功能上虽无大碍，但真实的上位机通信中会造成重复响应。

### 5.6 PLCSIM 仿真验证步骤

**第①步：需要建立的变量清单**

| 名称 | 数据类型 | 地址/位置 |
|------|----------|-----------|
| 接收命令 | String[32] | DB「通信数据」 |
| 冒号位置 | Int | DB「通信数据」 |
| 头长度 | Int | DB「通信数据」 |
| 命令头 | String[10] | DB「通信数据」 |
| 命令体 | String[20] | DB「通信数据」 |
| 上位机启动/停止命令 | Bool | M0.3 / M0.4 |
| 命令处理完成 | Bool | M0.5 |
| 电机 | Bool | Q0.0 |

**第②步：启动仿真并下载程序**

1. 建立 DB 并填写起始值（「接收命令」可先留空），编译；
2. "启动仿真"打开 PLCSIM → 选择 CPU 确认 → "下载到设备"（接口 PLCSIM）→ 拨到 RUN。

**第③步：用监控表模拟输入/修改变量**

1. 添加监控表，放入「接收命令」「冒号位置」「命令头」「命令体」、M0.3、M0.4、Q0.0；
2. 点"监视"；在「接收命令」的"修改"列输入 `CMD:START` 并点"立即修改"（模拟上位机发来启动命令）；
3. 观察各变量变化后，再把「接收命令」改为 `CMD:STOP`、以及故意输错的 `MSG:START`、不带冒号的 `CMDSTART`，分别观察。

**第④步：预期结果**

- 输入 `CMD:START`：冒号位置 = 4，命令头 = 'CMD'，命令体 = 'START'，随后 Q0.0 = 1（电机启动），且「接收命令」被自动清空；
- 输入 `CMD:STOP`：命令体 = 'STOP'，Q0.0 = 0（电机停止），接收命令清空；
- 输入 `MSG:START`：命令头 = 'MSG'，不等于 'CMD'，命令体保持空，电机无动作；
- 输入 `CMDSTART`（无冒号）：冒号位置 = 0，网络 3、4 均不执行，电机无动作，接收命令保留（可以再人工清空或扩展超时清理逻辑）。

**第⑤步：功能验证清单（逐项）**

- ☐ 'CMD:START' 能正确解析出命令头 'CMD'、命令体 'START'；
- ☐ 解析后电机启动（Q0.0 = 1），接收命令自动清空；
- ☐ 'CMD:STOP' 能使电机停止；
- ☐ 命令头不是 'CMD' 的报文被正确拒收；
- ☐ 无冒号的非法报文不会引起任何误动作；
- ☐ M0.3 / M0.4 为瞬时分发信号（用完即清），不会长期保持。

**第⑥步：结果不符时的排查方法**

1. **命令体解析为空**：DELETE 的 L 接错（应为冒号位置，即连同 'CMD:' 一起删掉 P 个字符）；P 忘了填 1；
2. **命令头多一个冒号**：LEFT 的 L 忘了减 1（直接用了冒号位置），把 ':' 也带进来了——检查网络 2 的 SUB；
3. **电机不动作但解析都正确**：检查网络 5/6 的字符串比较常量是否写对（注意大小写与空格）；检查网络 7/8 的 S/R 线圈；
4. **同一条命令反复触发**：网络 9（清空接收命令）没写或 M0.5 没被复位；
5. **冒号位置一直是 0**：FIND 的 IN1/IN2 接反（变成在':'里找整条报文）；或监控表里输入的字符串带了前后空格；
6. **输入中文或全角冒号无效**：本例按英文半角 ':' 设计（String 类型按 ASCII 处理），测试输入时务必用半角冒号和半角字母。

## ⚠️ 常见错误与注意事项

1. **用 String 存中文**：String 是单字节类型，存中文不保证正确。界面显示、含汉字的内容一律用 WString；
2. **位置从 0 数起**：TIA 的字符串指令中 P 都从 **1** 开始，MID('ABC', P=1) 取到的是 'A' 不是 'B'——与许多编程语言不同；
3. **FIND 的 IN1/IN2 接反**：IN1 是"要找的小串"，IN2 是"被搜的大串"，接反后结果永远为 0；
4. **忘记判断"找不到"**：FIND 结果为 0 表示没找到，后续用 P 做参数的指令必须先确认 P > 0，否则会出现 P=0 的非法操作；
5. **目标字符串最大长度不够**：CONCAT/INSERT/REPLACE 的结果超过 OUT 声明长度时被截断且 ENO = 0——声明长度要留余量，并用 ENO 检查；
6. **P=0 的特殊含义**：INSERT 的 P=0 表示插在最前面，不是"错误"，别当成 bug 排查；
7. **字符串比较大小写敏感**：'START' ≠ 'start' ≠ 'START '（尾部多空格）。解析外部报文时最好先做长度/格式校验，必要时约定全大写；
8. **MOVE 常量与变量类型不匹配**：给 WString 变量赋值必须用 WString 常量，String 与 WString 不能直接互相赋值；
9. **解析结果不清理**：命令解析完不清空接收缓冲区，会被反复解析、反复执行——务必配"处理完成"标志清空；
10. **被跳过/未执行的字符串指令保留旧值**：EN 断开或 ENO 中断时 OUT 保持上一次的结果，判断逻辑时不要误以为 OUT 会被清空；
11. **LEN 返回的是字符数**：WString 中一个汉字算 1 个字符但占 2 字节，估算通信缓冲区大小时要按字节算；
12. **监控表里输入字符串带了引号或空格**：直接输入文本内容即可（不要自己再加引号），前后空格会成为内容的一部分导致比较失败。

# 28 - 配方和数据记录：让 HMI 管理"工艺参数"与"历史档案"

## 📖 学习目标

学完本讲，你应该能够：

1. 说出**配方（Recipe）**和**数据记录（Data Logging）**的概念与典型工业应用场景。
2. 理解配方由"配方类型 + 配方数据记录"组成，并在 TIA Portal 中完成一次完整的配方配置。
3. 会用 HMI 画面上的**配方视图**控件选择、保存、装载配方记录，并把配方导出为 CSV 文件。
4. 会在 TIA Portal 中创建数据日志（日志结构、字段与变量、存储位置），并区分周期记录与事件触发。
5. 会把数据日志导出为 CSV 并用 Excel 打开分析。

---

## 一、开宗明义：配方和数据记录以 HMI（WinCC）侧为主

先划重点：在工业自动化工程中，**配方和数据日志最主流、最直观的实现方案是在 HMI/WinCC 侧配置**。

> 💡 **知识拓展**：虽然西门子 S7-1200/1500 PLC 的扩展指令库中也提供了基于存储卡（SMC）的指令（如 `DataLogCreate`/`DataLogWrite` 写入 CSV 日志、`RecipeExport`/`RecipeImport` 读写配方），但由于现场操作需要直观的人机交互画面、随时查看历史表格以及插拔 U 盘导出，工业界绝大多数配方与历史归档工作都在 HMI/WinCC 侧完成，PLC 侧通常扮演"按参数干活、提供实时数据"的角色：

```
┌─────────────────────────────┐      ┌─────────────────────────────┐
│  HMI（WinCC）—— 智能秘书    │      │  PLC（S7-1500）—— 车间主任  │
│                             │      │                             │
│  配方：存好几套参数，        │ 写入 │  收到参数后按参数干活        │
│  一键把某套参数写进 PLC      │─────▶│  （温度 MW20、速度设定等）   │
│                             │      │                             │
│  数据日志：定期抄表，        │ 读取 │  提供实时数据               │
│  把变量值记成表格存档、导出  │◀─────│  （产量 MW30、温度 MW20）    │
└─────────────────────────────┘      └─────────────────────────────┘
```

- 配方：HMI 保管**多套参数**，操作员切换产品时**一键下发**给 PLC。
- 数据日志：HMI 定期或按事件**抄变量值**，存成表格（CSV），供追溯和分析。

> 💡 **面板差异提示**：本课使用 WinCC 组态。**精智面板（Comfort）与 WinCC RT Advanced** 支持的配方/数据日志功能最完整；**精简面板（Basic）**也能用，但配方数量、记录条数、日志数量等有明显限制，部分高级选项（如外部存储位置）不齐。组态时以所选 HMI 设备的属性支持列表为准——TIA 会自动禁用该设备不支持的功能。纯 PLCSIM 仿真时，配方/数据日志要配合 WinCC 运行系统才有意义。

## 二、配方（Recipe）

### 2.1 什么是配方：面包机的"档位卡片"

想象一台家用面包机：做全麦面包要"和面 20 分钟、发酵 60 分钟、烘烤 40 分钟"；做法棍又是一套不同的时间和温度。厂家把每套参数写在一张卡片上，你做哪种面包就插哪张卡片——机器本身不变，变的只是参数。

工业现场一模一样：

| 场景 | 产品 A 参数 | 产品 B 参数 |
| --- | --- | --- |
| 灌装机 | 灌装量 500ml，速度 60 瓶/分 | 灌装量 1L，速度 40 瓶/分 |
| 烘箱 | 目标温度 MW20 = 180℃，时长 30min | 目标温度 MW20 = 220℃，时长 20min |
| 贴标机 | 标签长度 80mm | 标签长度 120mm |

没有配方功能时，换产品要操作员逐个变量手动改，改漏一个就出一批废品。配方功能把这些参数**打包命名**，一键切换，又快又不会漏。

### 2.2 配方的组成：配方类型 + 配方数据记录

配方体系有两个层级，务必分清：

```
配方类型（Recipe）"烘箱工艺"
│  ——定义"有哪些参数"（结构、模板）
│
├── 成分1：目标温度  → 关联 PLC 变量 MW20
├── 成分2：保温时长  → 关联 PLC 变量 "时长_s"
└── 成分3：搅拌速度  → 关联 PLC 变量 "速度设定"

配方数据记录（Data Record）——按这个结构填出来的具体值（实例）
├── 记录 1「面包」： 180℃，1800s，60 rpm
├── 记录 2「蛋糕」： 220℃，1200s，45 rpm
└── 记录 3「饼干」： 160℃，900s，30 rpm
```

| 术语 | 是什么 | 类比 |
| --- | --- | --- |
| 配方类型（Recipe） | 参数的**结构定义**：有几个成分、各自关联哪个 PLC 变量 | 面包机的"空白卡片模板" |
| 成分/组件（Component） | 结构中的一个参数项 | 卡片上的一个空格 |
| 配方数据记录（Data Record） | 按结构填好的一套**具体数值** | 填好的某一张卡片 |

### 2.3 在 TIA Portal 中配置配方的步骤（HMI 侧）

前提：项目里已有 HMI 站（如 HMI_1），且 HMI 与 PLC 建立了连接（HMI_1 的连接中已有到 PLC_1 的连接）。

**操作步骤（分步）：**

1. 在项目树中展开 **HMI_1 → 配方**，双击打开配方编辑器。
2. 新建一条配方，命名如 `烘箱工艺`；设置**存储位置**（内部 / SD 卡 / USB 存储卡，视面板支持而定）。
3. 在成分表中逐行添加**成分**，并关联 PLC 变量：
   - 成分名"目标温度" → PLC 变量：`温度设定`（对应 MW20 区域的设定值，本课案例中 PLC 程序读取它）；
   - 成分名"保温时长" → `时长_s`；
   - 成分名"搅拌速度" → `速度设定`。
   - 每个成分选择数据类型（Int/Real 等），与 PLC 变量一致。
4. 切换到配方的**数据记录**页签（编辑器下半部分），点"新建记录"创建若干条：
   - `面包`：180 / 1800 / 60
   - `蛋糕`：220 / 1200 / 45
   - `饼干`：160 / 900 / 30
5. 编译 HMI。若编译报"变量类型不匹配"，回去检查成分的数据类型与 PLC 变量是否一致。
6. （可选）在配方属性中设置权限：如"换配方需要操作员级别以上"，防止无关人员乱切。

> 📌 提示：配方编辑器的具体页签布局随版本略有差异（有的版本把"配方类型"与"数据记录"分成两个编辑器），但**先定义结构、再填记录**的顺序不变。

### 2.4 通过 HMI 配方视图控件管理配方

配方配好了，操作员在触摸屏上怎么用？——把**配方视图（Recipe View）**控件放到画面上。

**操作步骤（分步）：**

1. 打开画面_1，从"工具箱 → 控件"中把 **配方视图** 拖到画面上，调整大小。
2. 在控件属性 → 常规中，选择要显示的配方（如"烘箱工艺"），可限定只显示该配方。
3. 运行时，配方视图会呈现为一个"小软件"界面，常用操作：

| 配方视图中的操作 | 作用 |
| --- | --- |
| 选择配方类型 | 切换到目标配方（如烘箱工艺） |
| 选择数据记录 | 选中某一套参数（如"面包"） |
| 保存 | 把屏幕上修改后的值存为该记录（更新卡片） |
| 新建/删除记录 | 增加或删除一张"卡片" |
| **装载（下装）** | **把选中记录的值写入关联的 PLC 变量**——最关键的按钮 |
| 上载 | 从 PLC 当前值反向读回，存成记录（用于"现场调好的参数存档"） |
| 导入/导出 | 与 CSV 文件交换数据（见 2.5） |

4. 给关键按钮（如"装载"）设置操作权限，避免误触。

> 💡 不同版本/面板的按钮名称略有差异（"装载"也可能叫"下装/传输"），认准方向即可：**装载 = HMI → PLC；上载 = PLC → HMI**。

**配方视图的常用属性设置（选中控件 → 属性）：**

| 属性组 | 常用设置 | 作用 |
| --- | --- | --- |
| 常规 | 选择配方（如"烘箱工艺"） | 限定该视图只管这一类配方，操作员不会选错 |
| 常规 | 记录数显示/起始记录 | 控制列表浏览方式 |
| 列/显示 | 勾选显示"成分名、设定值、单位"等列 | 让操作员一眼看懂每行是什么 |
| 按钮 | 启用"保存/装载/上载/删除/导入/导出"等按钮 | 按权限决定操作员能做什么（不需要的按钮直接关掉，防误触） |
| 权限 | 装载/保存需要操作员级别 | 防止实习生一键改掉全线参数 |
| 外观 | 字体大小、行高 | 车间手套操作，屏幕字要够大 |

> 📌 初学建议：第一次跑通时把所有按钮都启用，跑熟后再按权限"收口"。很多现场问题不是功能不行，而是把删除按钮给了所有人。

### 2.5 配方的导入/导出（CSV 格式，U 盘/SD 卡）

配方记录本质是一张二维表，TIA 支持把它导出为 **CSV 文件**（逗号分隔的纯文本，Excel 可直接打开）：

- **为什么要导出**：批量修改配方（Excel 里改几百行比在屏上点快得多）、备份、把实验室调好的配方拷贝到产线设备。
- **存在哪里**：面板的 **SD 卡** 或 **USB 存储卡**（U 盘）；RT Advanced 则是电脑文件夹。
- **怎么导出**：运行系统中在配方视图使用"导出"功能（属性中可启用该按钮），或在事件（如按钮单击）中调用与配方导入导出相关的系统函数；文件路径指向所选存储介质（面板上常见类似 `\USB_X61.1\` 或 SD 卡目录的路径，随设备而异）。
- **怎么导入**：把按格式改好的 CSV 放回卡内，用"导入"读回配方记录。
- 离线状态下，也可以在开发电脑上对项目中的配方数据做导入导出（版本不同入口不同）。

> ⚠️ CSV 的列顺序、表头格式要符合 TIA 的导出格式，改 Excel 时别增删列、别改第一行表头，否则导入会失败。

### 2.6 PLC 程序与配方的数据交互

配方装载后，数据流是这样的：

```
操作员在配方视图选中"面包" → 点【装载】
        │
        ▼
WinCC 把记录 1 的值写入关联的 PLC 变量
   温度设定 = 180   时长_s = 1800   速度设定 = 60
        │
        ▼
PLC 程序像使用普通变量一样使用它们（示例，OB1）：

Network 1：烘箱加热控制（用配方下发的设定值）
   温度 MW20 ──[< 温度设定]──( Q0.0 )  加热器（低于设定值就加热）

Network 2：达到设定值后的保温计时由 PLC 用"时长_s"完成
```

要点：

- **PLC 不需要知道"配方"的存在**：它只看到普通变量（温度设定等）被更新了。配方这层"打包/切换"逻辑完全在 HMI。
- 变量的"归属"要规划好：哪些变量是"配方参数"（由配方装载）、哪些是"运行状态"（PLC 计算），不要混。
- 如果工艺参数要求**断电不丢**，把存放这些设定的 PLC 变量放在带保持性（Retain）的 DB 中（详见第 29 讲），配方装载和断电保持是两个互补的机制。

## 三、数据记录（Data Logging）

### 3.1 什么是数据记录：车间的"抄表本"

以前车间里有个抄表员，每小时把仪表读数抄到本子上：产量、温度、压力……月底翻本子查账。**数据日志（Data log）就是电子抄表本**：HMI 按一定节奏把若干变量的值抄成一行，一行一行攒成表格，存到存储卡上。

典型用途：

| 场景 | 记什么 | 谁在用 |
| --- | --- | --- |
| 每班产量记录 | 班次号、产量 MW30、停机时长 | 班组长/生产统计 |
| 批次追溯 | 批次号、各段温度 MW20、质检结果 | 质量追溯 |
| 能耗统计 | 电表值、气耗 | 设备/能源管理 |
| 故障留痕 | 故障代码、发生时刻的关键值 | 维修工程师 |

### 3.2 在 TIA Portal 中配置数据日志

**操作步骤（分步）：**

1. 项目树中展开 **HMI_1 → 历史数据**（有的版本叫"记录"），双击 **数据日志**。
2. 新建一个日志，命名如 `班产量日志`。
3. 设置**存储位置**：内部存储器 / SD 卡 / USB 存储卡（视设备支持；生产数据建议存可拔插的卡，方便取走）。
4. 定义**日志结构（字段）**——就是表格的列：

| 字段名 | 关联变量 | 数据类型 | 说明 |
| --- | --- | --- | --- |
| 班次号 | `班次号`(HMI 变量) | Int | 操作员在画面输入 |
| 计数值 | `计数值`（MW30，Int） | Int | 从 PLC 读取的累计值 |
| 温度 | `温度`（MW20，Int） | Int | 抄表时的工艺值 |
| 时间戳 | （自动） | — | 系统自动加，不必手建 |

5. 设置记录条数上限（如 1000 条，受存储容量与设备限制），满员后的策略按需选择（停止记录/循环覆盖，视版本支持情况）。
6. 编译 HMI。

> 📌 **精简/精智差异**：数据日志的字段数、日志数、条数上限在精简面板上更受限；精智面板与 RT Advanced 功能更完整。若组态时某选项灰掉，通常是所选设备不支持。

### 3.3 记录触发方式：周期记录与事件触发

日志不会自己抄表，需要告诉它"**什么时候抄一行**"：

| 触发方式 | 含义 | 典型用途 |
| --- | --- | --- |
| **周期记录** | 每隔固定时间抄一行（如每 1 分钟、每 1 小时） | 连续过程监视、能耗曲线 |
| **事件触发** | 某个事件发生时抄一行：按钮按下、变量上升沿、批次结束信号、报警发生 | 班产量结算、批次记录、故障留痕 |

**实现方式（以事件触发为例）：**

1. 打开画面，选中一个按钮（如"班次结束"按钮）。
2. 属性 → **事件 → 单击**。
3. 添加与数据日志相关的**系统函数**（在函数列表的"数据日志/记录"类别中，用于向日志写入一条记录、打开/关闭日志等；具体函数名随设备与版本有所不同，以你版本的函数列表和 F1 为准）。
4. 周期记录同理：可在循环事件/调度中周期性调用记录动作，或使用设备支持的周期性记录选项。

> 💡 别忘了配套的画面元素：可以用 **表格视图（数据日志表格）** 控件在画面上直接查看已记录的行；精智面板/RT 上还有"报表"等更高级的输出方式，初学先把"记录 + 导出"跑通。

**顺带分清两个长得像的名词（查资料时不再迷路）：**

| 名词 | 在哪组态 | 特点 | 典型用途 |
| --- | --- | --- | --- |
| 数据日志（Data log） | HMI → 历史数据 → 数据日志 | 行式表格，事件/周期触发写入，CSV 友好 | 班产量、批次记录（本讲主角） |
| 变量记录（Tag logging，归档） | HMI → 历史数据 → 变量记录（精智/RT 支持更完整） | 按采集周期/归档周期连续归档，配趋势控件 | 连续曲线、趋势回看 |

两者都算"数据记录"这个大概念，教程里说"记录数据"时先分清指的是哪一个。连续温度曲线选变量记录 + 趋势图；"每班抄一行"选数据日志。

### 3.4 数据存储位置：HMI 存储卡 / USB

| 位置 | 特点 | 适用 |
| --- | --- | --- |
| HMI 内部存储器 | 读写最快；面板断电数据仍在，但容量有限、取走不便 | 小容量、临时缓存 |
| SD 卡（面板专用存储卡） | 容量大、可拔出拿到电脑读 | 生产数据长期留痕（推荐） |
| USB 存储卡（U 盘） | 通用性强，注意工业环境插拔 reliability | 定期导数据 |

工程习惯：**内部存储器做运行缓冲，定期导出到卡**；重要数据坚持"能导出、有备份"。同时注意卡的文件系统与剩余空间，卡满了记录会失败。

### 3.5 数据的导出和分析（CSV 导出、Excel 打开）

**导出步骤（分步）：**

1. 运行系统中，在数据日志表格控件上使用**导出**功能（或在事件中调用导出系统函数），目标选 SD 卡/USB/网络路径（视设备支持）。
2. 生成 **CSV 文件**（文本格式，一行一条记录，逗号/分号分隔）。
3. 把卡/U 盘取下（或通过网络路径），在电脑上用 **Excel 直接打开** CSV。
4. 在 Excel 里做分析：筛选某班次、计算日产量、画温度曲线（插入折线图）等；也可交给 MES/报表系统。

导出的 CSV 用记事本打开大致长这样（一行一条记录，第一行通常是表头）：

```
Date;Time;班次号;计数值;温度
2026-11-02;08:00:03;1;356;82
2026-11-02;16:00:05;2;402;79
2026-11-02;23:59:58;3;388;81
```

拿到 Excel 后能做的典型分析：

| 分析需求 | Excel 操作 |
| --- | --- |
| 每班产量排序/对比 | 对"计数值"列排序或做透视表 |
| 温度波动是否超标 | 对"温度"列做条件格式（超 85 标红） |
| 产量趋势 | 选中两列插入折线图 |
| 找异常班次 | 筛选器过滤计数值低于阈值的行 |

> ⚠️ Excel 打开 CSV 时注意**编码与分隔符**：中文乱码多半是编码问题（另存为或用"数据 → 自文本导入"选择编码），列挤在一起是分隔符问题（分号/逗号）。这些都是 Excel 侧小技巧，与组态无关。

## 四、综合案例：班产量记录 + 一键换产配方

把本讲两个功能串在一个小项目里，体会"HMI 管参数、PLC 管执行、日志管留痕"的分工。

**变量与结构：**

| 名称 | 位置 | 说明 |
| --- | --- | --- |
| 温度 | MW20（Int） | PLC 实测温度 |
| 计数值 | MW30（Int） | 本班产量计数 |
| 温度设定 / 搅拌速度 | PLC 变量（由配方成分关联） | 配方下发的工艺参数 |
| 配方 `产品工艺` | HMI 配方 | 记录：产品A / 产品B / 产品C |
| 日志 `班产量日志` | HMI 数据日志 | 字段：班次号、计数值、温度 |

**流程图：**

```
换产品：  操作员选配方记录"产品B" →【装载】→ 设定参数写入 PLC → PLC 按新参数运行
   │

   │

   ▼

```

**仿真验证步骤（PLCSIM + WinCC 运行系统）：**

1. 完成 PLC（简单生产计数程序）、HMI（配方视图、数据日志、按钮）组态并编译。
2. "下载并仿真"启动 PLCSIM，CPU 置 RUN；启动 WinCC 运行系统。

## 五、配方 vs 数据记录：一张表看懂分工

两个功能都和"表格数据"打交道，容易混。放到一起对比一次，思路就清晰了：

| 对比项 | 配方（Recipe） | 数据记录（Data Logging） |
| --- | --- | --- |
| 方向 | **写为主**：HMI → PLC 下发参数 | **读为主**：PLC → HMI 抄录数据 |
| 内容 | 产品的工艺参数（目标值） | 生产过程的历史事实 |
| 结构 | 配方类型（成分 + 关联变量） | 日志结构（字段 + 关联变量） |
| 一行是什么 | 一套参数（一个产品） | 一个时刻的快照 |
| 谁发起 | 操作员选记录 → 点装载 | 周期到点 / 事件发生自动触发 |
| 典型文件 | 配方 CSV（导入导出交换参数） | 日志 CSV（导出做分析） |
| 类比 | 面包机的档位卡片 | 车间的抄表本 |

记忆口诀：**配方管"接下来按什么参数干"，数据记录管"刚才干了什么"。**

## 📌 本章小结

- 配方和数据日志都是 **HMI/WinCC 侧功能**：配方管"参数打包下发"，数据日志管"历史数据抄表留痕"；PLC 只负责按参数执行、提供数据。
- 配方两层结构：**配方类型**（结构模板：成分 + 关联 PLC 变量）与**配方数据记录**（一套套具体数值）。
- 配方视图控件的核心操作：选记录 → **装载**（HMI→PLC）/ 上载（PLC→HMI）/ 保存 / 删除 / 导入导出。
- 配方可导出为 **CSV**（存 SD 卡/U 盘），用 Excel 批量编辑后再导回。
- 数据日志三要素：**结构（字段与变量）、触发（周期/事件）、存储位置（内部/SD/USB）**；数据可导出 CSV 用 Excel 分析。
- 精简面板功能受限、精智面板/RT Advanced 功能完整，以设备支持列表为准。

## ⚠️ 常见错误与注意事项

1. **混淆 PLC 侧与 HMI 侧配方**：工程中推荐在 HMI 侧做配方管理（自带视图控件、支持 U 盘导出），PLC 仅接收下发的目标变量；虽然 PLC 有 `RecipeImport/Export` 扩展指令，但没有屏幕 UI 支撑，维护复杂得多。
2. **成分数据类型与 PLC 变量不一致**：编译报错或装载后数值异常（如 Real 存进 Int）。建配方时逐项核对类型。
3. **"装载"和"上载"方向搞反**：方向反了会把 PLC 当前值覆盖掉你的配方记录。记口诀：装载=下发，上载=收回。
4. **装载后参数断电丢失**：配方下发的设定值存在普通变量里，断电后回到初始值；需要持久化的参数要放进带 Retain 的 DB（第 29 讲），两套机制配合使用。
5. **日志没有触发动作**：只建了日志、没在任何事件里调用记录动作，结果表格永远空着——日志不会自动抄表（周期方式也要确认所选设备支持并已启用）。
6. **存储位置选错**：仿真环境选了 SD/USB 卡路径导致记录失败；RT 仿真请选本机文件夹/内部存储。
7. **记录条数上限设太小或卡满**：日志写满后（视策略）停止或覆盖，造成数据缺口；上线前按数据量估算容量。
8. **CSV 手工编辑破坏格式**：增删列、改表头、改编码都会导致导回失败；改配方表时保持导出格式原样。
9. **把重要数据只存在 HMI 里**：HMI 卡损坏=数据全丢；重要记录要定期导出备份。

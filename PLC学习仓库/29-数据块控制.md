# 29 - 数据块控制：DB 的进阶玩法与断电保持

## 📖 学习目标

学完本讲，你应该能够：

1. 准确区分**全局 DB 与背景 DB**、**优化访问与标准访问**，并根据场合选型。
2. 会把 DB 设置为**只读（写保护）**，理解它的用途与影响。
3. 认识 DB 的运行时操作指令族（CREATE_DB / DELETE_DB / READ_DBL / WRIT_DBL），知道它们的使用前提与"少用"的原因。
4. 理解 **保持性（Retain）** 的原理，会在 DB 中逐变量或整块设置保持性，并了解 S7-1500 保持存储器的容量限制（约 128KB 量级，以 CPU 为准）。
5. 能实现"断电不丢的运行参数存储"案例，并用 PLCSIM 验证。

## 一、数据块（DB）深入

### 1.1 快速回顾：DB 就是 PLC 的"储物柜"

DB（Data Block，数据块）是用户程序存放数据的区域，相当于给程序配的一组储物柜：一个柜子（DB）里有很多格子（变量），每个格子有名字（如`温度设定`）、类型（Int/Real…）和大小。

前面章节我们一直在用全局 DB 存变量。本讲把它讲透，并介绍几个"运行时才动手"的高级操作。

### 1.2 全局 DB vs 背景 DB

全局 DB 谁都能用；背景 DB 是 FB 的"私人记账本"——每次调用 FB 时，它的形参和静态变量都存在背景 DB 里。

```
┌────────────────────────────┐        ┌────────────────────────────┐
│ 全局 DB：公共储物柜        │        │ 背景 DB：FB 的私人账本      │
│                            │        │                            │
│  OB1/FB1/FC1/FB2...        │        │   FB"电机控制" 的实例       │
│   ↘ 任何块都可以直接访问   │        │  ┌────────────────────┐    │
│                            │        │  │ 输入引脚的影子      │    │
│  例：运行参数DB            │        │  │ 输出引脚的影子      │    │
│      - 温度设定 (Int)      │        │  │ InOut 的影子       │    │
│      - 累计产量 (DInt)     │        │  │ Static 静态变量     │    │
└────────────────────────────┘        │  └────────────────────┘    │
                                      └────────────────────────────┘
```

| 对比项 | 全局 DB | 背景 DB |
| --- | --- | --- |
| 怎么来的 | 手动"添加新块 → 全局数据块" | 调用 FB 时自动生成（或手动建实例） |
| 内容 | 自己声明的变量 | FB 接口（Input/Output/InOut/Static）的映射，**不能自己增删变量** |
| 谁能访问 | 任何块、HMI 都可直接访问 | 理论上可按绝对地址访问，但正规做法是**只通过 FB 的形参**读写 |
| 典型用途 | 公共参数、配方数据、日志缓冲 | 每个"对象"的状态（每台电机的启停状态等） |
| 数量关系 | 独立存在 | 一个 FB 可生成多个实例（每台设备一个实例 DB） |

> 💡 记忆法：全局 DB 像**车间公告栏**（谁都能看、谁都能写）；背景 DB 像**每位员工的个人工作日志**（内容由岗位决定，别人不直接翻）。多重实例则是"多个员工共用一本主管日志的不同分页"。

### 1.3 优化访问 vs 标准访问

新建 DB 时，属性里默认勾选了"**优化的块访问**"。这两种方式的本质区别是**变量在 DB 里有没有固定的"门牌号"（偏移地址）**：

```
标准访问 DB（关掉"优化块访问"）          优化访问 DB（默认）
┌──────────────────────┐               ┌──────────────────────┐
│ 偏移    变量          │               │ 变量（无固定偏移）    │
│  0.0    启动指令 Bool │               │  启动指令  Bool      │
│  0.1    停止指令 Bool │               │  温度设定  Int       │
│  2.0    温度设定 Int  │               │  速度设定  Real      │
│  4.0    速度设定 Real │               │   （地址由系统安排，  │
└──────────────────────┘               │     且可能随编辑变化）│
  外部可按 DB10.DBW2 访问               └──────────────────────┘
                                        外部按符号名"DB.温度设定"访问
```

| 对比项 | 标准访问（绝对寻址） | 优化访问（符号寻址，S7-1500 推荐） |
| --- | --- | --- |
| 地址确定方式 | 你定义顺序 → 固定偏移（DB10.DBX0.0） | 系统内部安排，无固定偏移 |
| 访问方式 | 符号或绝对地址均可 | **只能符号访问**（程序内）；部分接口可用"插入未定义变量"等特殊方式 |
| 改变量顺序 | 可能让外部按绝对地址访问的一方读错位 | 无影响（外部本来就按符号） |
| HMI 访问 | 绝对/符号都行 | 建立连接后按变量表/符号访问 |
| 性能与功能 | 一般 | 更优；支持复杂数据类型（Struct/Array of PLC 数据类型等）、Retain 逐变量设置 |
| 与老系统/特殊指令的兼容 | 兼容老 S7 程序、某些按绝对地址工作的场合 | 部分"老派"用法不支持 |

**何时选标准访问（少见的例外场合）：**

- 移植老项目（S7-300/400）且大量使用绝对地址；
- 外部系统（某些旧 HMI/上位机、第三方软件）按 `DB号.偏移` 的绝对地址读写；
- 少数要求标准访问的指令/通信方式（例如第 29 讲要讲的 WRIT_DBL/READ_DBL 使用的装载数据块要求非优化）。

其余情况一律用优化访问——这是 S7-1500 的默认与推荐。

### 1.4 只读 DB 的设置

如果某 DB 里放的是**校准常数、设备铭牌参数**这类"程序只许读、不许改"的数据，可以给 DB 上"写保护"。

**操作步骤：**

1. 右键 DB（如 `校准参数DB`）→ **属性 → 常规（属性）**。
2. 勾选 **"数据块中已写保护"**（部分版本显示为"写保护/在设备中写保护"之类的名称，含义相同）。
3. 编译。此后用户程序中任何**写**该 DB 的指令都会在编译时直接报错。

效果与边界：

- 程序侧：只读，试图写 → 编译报错（等于让编译器帮你查"谁改了不该改的数据"）。
- 监控/在线修改值、通过调试手段修改变量不受这条属性限制——它保护的是"程序逻辑"，不是"加密"。
- 类比：把参考答案（常数）过塑封起来，谁也不许拿笔往上写，但大家可以看。

## 二、DB 的运行时操作（扩展指令）

这一族指令位于 **指令 → 扩展指令 → 数据块函数/数据块控制** 组（组名随版本略有差异），能在**程序运行中**对 DB 做创建、删除、读写装载存储器等操作。

> 📌 **先泼冷水**：这些属于高级指令，日常项目里**很少使用**。常规需求（存参数、存配方、断电保持）用"建普通 DB + Retain + HMI 配方"就够了。运行时操作主要服务于特殊场景（如记录条数运行时才知道的配方管理、工具机的动态数据区）。初学阶段目标是"看懂、知道何时想起它"，不必强行上项目。

### 2.1 CREATE_DB：运行时创建数据块

**作用：** 程序运行中动态创建一个新的 DB（在装载存储器和/或工作存储器中），不改 CPU 运行模式。

**主要参数（以 F1 帮助为准）：**

| 参数 | 方向 | 类型 | 含义 |
| --- | --- | --- | --- |
| REQ | 输入 | Bool | 上升沿启动创建数据块作业 |
| LOW_LIMIT | 输入 | UInt / Word | 允许分配的 DB 编号范围下限 |
| UP_LIMIT | 输入 | UInt / Word | 允许分配的 DB 编号范围上限 |
| COUNT | 输入 | UDInt | 新 DB 的大小（以字节为单位） |
| ATTRIB | 输入 | Byte | 属性设置（如是否设为保持性等） |
| SRCBLK | 输入 | Variant | 模板数据块或 UDT（初始内容复制到新 DB 中） |
| RET_VAL | 输出 | Int | 错误代码/状态回执（0 表示无错误） |
| BUSY | 输出 | Bool | TRUE 表示异步创建进行中 |
| DB_NUMBER | 输出 | DB_ANY / UInt | 实际分配成功的 **DB 编号** |

**使用要点：**

- 新建的 DB **没有变量名**——你没法写 `新DB.温度`，只能用 PEEK/POKE 按字节地址间接读写，或用 SRCBLK 类参数把一块模板数据复制进去。这就是它"难伺候"的根源。
- 编号范围必须挑"编译时未占用"的区间（比如预留 DB900 以上），否则创建失败。
- 异步执行类：状态未完成前要持续调用该指令（按帮助的调用约定）。

### 2.2 DELETE_DB：运行时删除数据块

- 作用：删除**由 CREATE_DB 创建**的 DB（输入 DB_NUMBER 引用）。
- 限制：删不了编译时就存在的"正经 DB"——对它们调用会返回错误（通过 ERROR/STATUS 或 RET_VAL 反馈，名称以版本为准）。
- 类比：能撕掉自己现场打的草稿纸，撕不掉装订进图纸册的正式页。

### 2.3 OPEN_DB / CLOSE_DB：如实说明

老一代 S7-300/400 的 STL 编程里有"打开当前 DB"（OPN）的机制：先打开某个 DB，之后的指令就在"当前 DB"上下文里按偏移访问，用完关闭。**在 S7-1500/TIA Portal 中没有对应的 OPEN_DB/CLOSE_DB 指令**——S7-1500 全面符号化访问，访问任何 DB 都直接写"DB 名.变量名"，不存在"当前 DB"的概念。

- 如果你在老资料、老程序迁移时遇到 OPEN_DB/CLOSE_DB，正确的做法是**改写为符号访问**，而不是找替代指令。
- 本讲列出它们，是为了让你在资料海洋里能"对上号"：这是经典 STE P7 的遗产，不是 1500 的功能。

### 2.4 READ_DBL / WRIT_DBL：读写装载存储器中的 DB

这两个是本族指令里最有实用价值的，理解它们要先理解 CPU 的两种存储器：

```
┌─────────────────────────────┐        ┌─────────────────────────────┐
│  工作存储器（内存条类比）    │        │  装载存储器（硬盘/SIMATIC卡）│
│  程序运行时真正读写的地方    │        │  存放程序与 DB 的"底稿"      │
│  断电后：保持区保留，        │        │  断电后：内容原样保留        │
│          非保持区回初始值    │        │                              │
└─────────────────────────────┘        └─────────────────────────────┘
          ▲            │                          ▲            │
          │            │  WRIT_DBL（写→装载存储器）│            │
          │  READ_DBL  └──────────────────────────┘            │
          │  （读←装载存储器）                                  │
          └──────── 上电时 CPU 自动从装载存储器恢复 ─────────────┘
```

**解决什么问题：** 现场调试时你在 HMI 上把"速度设定"调好了，这个值只改在**工作存储器**里——一旦断电重启，CPU 会用装载存储器里的"底稿（起始值）"恢复数据，你调的值**丢了**。WRIT_DBL 可以把工作存储器里的当前值**写回装载存储器**，相当于"把修改保存为新的底稿"，断电重启后依然有效（不依赖保持存储器容量）。

**引脚说明（两个指令结构相同）：**

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| REQ | 输入 | Bool | 触发请求（上升沿启动一次读写作业） |
| SRCBLK | 输入 | Variant | 源数据区（写入时=工作存储器中的 DB/变量；读取时=装载存储器中的 DB） |
| RET_VAL | 输出 | Word | 状态与错误码（16#0000=完成；16#7001/7002=进行中；16#8xxx=出错，如 80B1"源与目标长度不一致"） |
| BUSY | 输出 | Bool | TRUE 表示异步作业正在执行中 |
| DSTBLK | 输出 | Variant | 目标数据区（写入时=装载存储器中的 DB；读取时=工作存储器中的 DB/变量） |

**使用前提（容易踩坑，重点）：**

1. 在项目里专门建一个"装载数据块"：普通全局 DB 的属性中勾选**"仅在装载存储器中存储（Only store in load memory）"**，它平时不占用宝贵的工作存储器。
2. 该装载数据块必须为**标准访问（非优化）**——优化 DB 不受支持（编译会直接报错）。
3. `SRCBLK` 与 `DSTBLK` 的结构与长度必须完全匹配。
4. WRIT_DBL 会**磨损存储介质**（写内部闪存/SIMATIC 卡），绝不能每个扫描周期都写！必须用上升沿脉冲 + 低频稀疏触发（如操作员点击保存参数时）。

> 💡 与 Retain 的关系：**断电保持优先用 Retain**（简单、无磨损）；WRIT_DBL 是"把在线修改持久化为新起始值"的另一条路，适合参数多、保持存储器不够用、或需要"出厂底稿 vs 现场底稿"管理的场合。

**WRIT_DBL 典型程序结构（"保存参数"按钮触发）：**

```
Network 1：操作员在 HMI 点"保存参数"按钮 → 置位"保存请求"(M5.0)

Network 2：边沿触发 + 异步调用 WRIT_DBL
     M5.0
   ──[P]──┬──( S )── "作业激活"(M5.1)
          │
   M5.1 ──┤REQ                                      BUSY ├── M5.2
 工作DB"运行参数DB" ──SRCBLK                         RET_VAL ├── MW34 ("写入状态")
 装载DB"参数底稿DB" ──DSTBLK
          └──────────────────────────────────────────────┘

Network 3：完成后收尾
  MW34 == 16#0000 且 M5.1 ──[ ]──( R )── M5.1   （作业完成，复位激活位）
```

**RET_VAL 状态检查思路（数值含义以 F1 帮助为准）：**

| RET_VAL 类别 | 含义 | 该做什么 |
| --- | --- | --- |
| 16#0000 | 作业完成、无错误 | 复位 M5.1，提示"保存成功" |
| 16#7001 / 16#7002 | 作业进行中（BUSY=TRUE） | 保持调用（下个周期继续跑这段），等待结束 |
| 16#8xxx（如 80B1 长度不符、8090 目标不存在） | 参数或组态错误 | 停止重试，核对 DB 属性（是否仅在装载存储器）、访问方式（非优化）及数据类型 |

三种"持久化手段"放在一起对比，选型不再纠结：

| 手段 | 原理 | 优点 | 代价/限制 |
| --- | --- | --- | --- |
| Retain 保持性 | 掉电时由系统存入掉电保存区 | 简单、自动、无感 | 共享约 128KB 量级的保持区，以 CPU 为准 |
| WRIT_DBL 写装载存储器 | 把当前值写成 DB 新"底稿" | 容量只受存储器限制，可"保存为新默认值" | 需标准访问装载数据块；写入有磨损，须低频 |
| 修改起始值后重新下载 | 离线把起始值改成现场值再下载 | 适合调试收尾一次性固化 | 要停机/在线下载，不能由程序自动做 |

## 三、数据块的保持性（Retain）

### 3.1 什么是保持性变量：便签 vs 存进硬盘

CPU 里数据的命运取决于它"写在哪儿"：

- **非保持变量** = 写在**便签**上：下班（断电）时保洁一擦就没了，重新上电回到"出厂初始值（起始值）"。
- **保持性（Retain）变量** = **保存到硬盘**：断电重启后，值还在，接着上次继续。

为什么有这个机制？S7-1500 没有电池。断电瞬间，CPU 把保持性数据区的内容存到 Flash（掉电不挥发）；上电时再恢复。非保持区则直接用 DB 的起始值初始化。

**上电流程图：**

```
上电
 │
 ▼
系统自检、装载程序
 │
 ├─ 保持性数据：从掉电保存区恢复 ──▶ 上次的值（累计产量 12580 还在）
 │
 └─ 非保持数据：用 DB 起始值初始化 ─▶ 恢复为组态的初始值（如 温度设定=100）
 │
 ▼
进入 RUN
```

### 3.2 如何在 DB 中设置保持性

**方式一：优化 DB 中逐变量设置（常用）**

1. 双击打开优化访问的全局 DB（如 `运行参数DB`）。
2. 找到变量行的 **"保持性（Retain）"** 列。
3. 对需要断电保持的变量打勾（如`累计产量`），不需要的不勾（如`当前批次号`每次开机清零反而合理）。
4. 编译下载。

**方式二：优化 DB 整块设置**

1. 右键 DB → 属性。
2. 在属性中找到**保持性**设置（下拉选项如"无保持性 / 保持 / 在 IDB 中设置"，名称以版本为准）。
3. 选"保持"= 整个 DB 全部变量断电保持。

**方式三：标准 DB 中设置**

标准访问 DB 的变量表同样有 Retain 列，逐个勾选即可（优化 DB 的"整块保持"选项在标准 DB 上不适用）。

**背景 DB** 的保持性在 FB 接口的 Static 变量上设置（Retain 列）——若 FB 内部有需要掉电记忆的中间状态或累计值，勾选其 Static 变量的 Retain 列即可。

**验证（PLCSIM）：**

1. 下载程序到 PLCSIM，RUN。
2. 在监控表中把 `累计产量` 改成 666。
3. 用仿真 CPU 窗口上的**电源开关**关闭再打开（不同版本按钮外观略有差异），CPU 重新启动。
4. 观察：勾了 Retain 的 `累计产量` 仍是 666；没勾的变量回到起始值。

### 3.3 保持存储器的限制

保持性不是免费的：

- S7-1500 的**保持存储器容量约为 128KB 量级**（不同 CPU 型号有差异，**具体以所用 CPU 的技术手册为准**）。
- 所有 DB 的保持变量、FB 的保持性静态变量、位存储器（M）的保持区等**共享**这块空间。超出时**编译报错**，无法下载。
- 所以工程原则：**只把真正需要断电续算的数据设为保持**（累计产量、总运行小时、整定参数），控制柜温度这种重新上电重测的数据不要保持。
- 非保持区的掉电行为：回到 DB 起始值（你组态的初始值）。**起始值要精心设计**——它就是"每次开机时的默认状态"。

| 需求 | 方案 |
| --- | --- |
| 几十个参数断电不丢 | 直接 Retain（容量足够） |
| 大块数据断电不丢（保持区不够） | WRIT_DBL 写装载存储器（注意写入频率） |
| 程序和组态本身 | 编译下载时已在装载存储器，天然不丢 |

## 四、典型案例

### 4.1 断电保持的设备运行参数存储

**需求：** 一台小型包装机——`累计产量`（断电必须继续累计，这是跟客户结算的数据！）和`设定速度`（工艺参数，断电保持）不能丢；`本班计数`则希望每天清零。

**建块：** 全局 DB `运行参数DB`（优化访问），变量如下：

| 变量 | 数据类型 | Retain | 起始值 | 说明 |
| --- | --- | --- | --- | --- |
| 设定速度 | Real | ✔ 勾选 | 50.0 | 工艺参数，HMI 可改 |
| 累计产量 | DInt | ✔ 勾选 | 0 | 与结算相关，绝不许丢 |
| 本班计数 | Int | ✘ 不勾 | 0 | 每天重新开始 |
| 温度 | Int（对应 MW20 场景值） | ✘ | 0 | 实测值，上电重新采集 |

**程序（OB1，配合统一引脚约定的电机案例）：**

```
Network 1：电机启停（复习）
   I0.0 启动按钮 ──┬──[/]── I0.1 停止按钮 ──( )── Q0.0 电机
                   │                        │
                   └────────(自锁)──────────┘

Network 2：产量累计（每出一个产品，脉冲位 M1.0 接通一次）
   产品计数脉冲 M1.0 ──[P]──┬── CALCULATE/ADD：本班计数 +1 → 本班计数
                            └── ADD：累计产量 +1   → 累计产量（DB 内，带 Retain）

Network 3：运行指示
   Q0.0 电机 ──( )── Q0.4 运行指示灯
```

（计数实现可用 CTU 计数器指令：CV 输出接本班计数，R 端接"换班复位"；累计产量用 ADD 指令在脉冲沿加 1，保证在 DB 中且 Retain 勾选。）

**验证步骤（PLCSIM）：**

1. 编译下载到 PLCSIM，RUN。
2. 监控表中强制若干个"产品脉冲"，观察 `本班计数` 与 `累计产量` 同步增加（如 12 与 3468）。
3. 关闭再打开仿真 CPU 电源，CPU 重启进入 RUN。
4. 验证点：`累计产量` 仍为 3468（保持生效）、`设定速度` 仍为修改后的值；`本班计数` 回到起始值 0。
5. 故意把 `累计产量` 的 Retain 取消后重复实验——重启后归零，直观感受保持性开关的意义。

### 4.2（简要）动态创建配方数据块的思路（CREATE_DB 的使用场景）

设想一台柔性设备：客户现场可能要存 5 套也可能要存 200 套参数记录，**编译时无法确定数量**。思路：

```
运行时：设备开机 → 读配置（要 N 套记录）
   → CREATE_DB 循环创建 N 个配方数据块（编号在预留区间，如 DB900+）
   → 每套记录用一个 DB，模板数据用复制指令灌入
   → 用 WRIT_DBL 把记录写入装载存储器，断电不丢
   → 换产品：PEEK/POKE 或复制指令把对应 DB 内容搬到工作区
   → 套数调整：DELETE_DB 删多余块、CREATE_DB 补建
```

**如实说明：这套思路完整但复杂，实际项目中较少使用**，原因：

- 新建 DB 无符号名，全程只能按字节间接寻址，程序可读性差、易出错；
- 涉及装载存储器写入，要控制磨损与作业状态管理；
- 绝大多数"多配方"需求用 **HMI 配方功能**（第 28 讲）或**固定数量的数组 DB**（用 Array 下标切换）就能优雅解决。

初学者的正确姿势：**知道有这条路、看得懂别人的老程序**；自己设计时优先选数组/HMI 配方案。

## 📌 本章小结

- 全局 DB 是公告栏（谁都能访问）；背景 DB 是 FB 的私人账本（随调用生成、存接口影子与静态变量，一个 FB 可多实例）。
- 优化访问（符号、无固定偏移、S7-1500 默认推荐）vs 标准访问（固定偏移、可绝对寻址，用于老程序/特殊外部访问/装载数据块等例外）。
- DB 属性"数据块中已写保护"= 程序只读；写它会在编译期报错，适合放常数。
- 运行时 DB 操作（扩展指令，少用）：CREATE_DB（运行时建 DB，输出 DB_NUMBER，需预留编号区间）、DELETE_DB（只能删自己建的）、READ_DBL/WRIT_DBL（工作存储器 ↔ 装载存储器，配"仅存储在装载存储器中"的标准 DB，通过 SRCBLK/DSTBLK 交换，注意介质磨损与低频触发）；OPEN_DB/CLOSE_DB 是老 S7 的遗产，1500 无此概念。
- 保持性（Retain）：DB 变量列勾选（或整块设置）；保持区约 128KB 量级、以 CPU 手册为准；非保持区上电回起始值。
- 断电保持优先 Retain；大数据量持久化再考虑 WRIT_DBL；多配方优先 HMI 配方或数组，而非 CREATE_DB。

## ⚠️ 常见错误与注意事项

1. **把该保持的变量忘了勾 Retain**：现场数据"莫名归零"十有八九是这个。结算类、整定类数据逐一核对保持性。
2. **什么都设成保持**：保持区只有约 128KB 量级，滥设保持会编译报错或挤占其他保持数据；只保持真正需要的。
3. **以为 Retain 了起始值就会生效**：保持变量的"起始值"只在第一次下载/无历史数据时生效；之后重启恢复的是上次运行值。想要"恢复出厂"要另写初始化逻辑。
4. **WRIT_DBL 当普通写指令用**：每个周期 REQ 常 TRUE 会快速磨损存储介质，甚至引发作业堆积。必须边沿触发 + 低频调用（如保存按钮确认时）。
5. **对优化 DB 用 WRIT_DBL/READ_DBL**：装载数据块必须标准访问，优化访问会报错（新版本编译期即报）。建"装载数据块"时先关掉优化块访问。
6. **SRCBLK 与 DSTBLK 类型或长度不一致**：源与目标的结构必须完全相符，否则 RET_VAL 返回 16#8xxx 错误代码（可通过 F1 查阅对应代码排查）。
7. **DELETE_DB 去删编译期 DB**：删不掉，只会收到错误——它只管 CREATE_DB 的"亲儿子"。
8. **在 S7-1500 上找 OPEN_DB/CLOSE_DB**：找不到是正常的，1500 用符号访问，老程序请改写。
9. **只读 DB 误当加密**：写保护只约束用户程序的写指令，在线监控修改不受限；真正的防篡改要靠保护等级和权限管理。
10. **仿真里验证保持性的方法用错**：要"断电重启"仿真 CPU（电源开关/重启命令），而不是 STOP→RUN——STOP 再 RUN 不会模拟掉电行为，保持与非保持都不初始化为起始值。

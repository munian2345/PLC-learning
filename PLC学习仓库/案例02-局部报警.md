# 案例02：局部报警系统——报警灯闪烁、蜂鸣器与确认按钮

## 📖 学习目标

1. 理解报警系统在工业现场中的作用，掌握"报警 → 确认 → 恢复"三段式处理流程；
2. 学会使用置位线圈（S）/复位线圈（R）实现"故障记忆"功能；
3. 掌握用两个 TON 定时器交替接力产生闪烁信号（方波）的经典方法；
4. 能够独立编写本案例的梯形图程序，并在 PLCSIM 中完成全流程仿真验证；
5. 了解多报警点、报警分级等工程扩展思路。

---

## 一、案例背景：工业中为什么要报警系统

走进任何一家现代化工厂，你会发现设备并不是"闷头干活"的：它们都有办法"喊人"。高速运转的机床、默默加压的液压站、不停传送的流水线——操作员不可能一天 24 小时盯着每一台设备，所以设备必须在自己"不舒服"的时候主动发出信号，这就是**报警系统**的作用。

生活里其实到处都是它的影子：

- 家里的**烟雾报警器**：检测到烟雾就"滴滴滴"响个不停，把你叫醒；
- 汽车的**故障灯加提示音**：仪表盘上亮起警告灯，同时"叮"一声提醒你；
- 微波炉的**结束提示**：响了三声，你不理它，它会一直显示"END"。

一个设计良好的报警系统，要解决三个问题：

1. **引起注意**：出事了，快来看！（灯闪烁 + 蜂鸣器响，声光并施）
2. **留下记忆**：我知道了，但问题还没解决。（按确认后声音停，灯转为常亮）
3. **明确恢复**：问题彻底解决，一切正常。（故障消除后灯才熄灭）

为什么不能"故障来了响一声就完事"？因为操作员可能根本不在设备旁边，一声提示音就错过了。为什么也不能一直响个不停？因为长时间刺耳的声音会让人烦躁，甚至掩盖掉新出现的报警。所以工程上约定俗成的做法就是：**声音可以消音（确认），灯光必须保持（记忆），故障消除才复位（恢复）**。本案例就要把这套"标准动作"用 S7-1500 的梯形图实现出来。

## 二、控制要求

1. **出现故障信号** → 报警灯闪烁 + 蜂鸣器响（引起注意）；
2. **按下确认按钮** → 蜂鸣器立即停止，报警灯变为**常亮**（表示"故障已被注意，但尚未解决"，即保持故障记忆）；
3. **故障消除** → 报警灯熄灭（一切恢复正常）。

各阶段行为对照表：

| 阶段 | 故障信号 I0.0 | 确认按钮 I0.1 | 报警灯 Q0.2 | 蜂鸣器 Q0.3 |
|---|---|---|---|---|
| ① 正常运行 | 0 | 0 | 灭 | 不响 |
| ② 故障发生 | 1 | 0 | 闪烁 | 响 |
| ③ 已确认（故障仍在） | 1 | 按过一下 | 常亮 | 停止 |
| ④ 故障消除 | 0 | —— | 灭 | 不响 |

特别注意第③阶段：灯必须**常亮**而不是熄灭，这就是"故障记忆"——只要故障还没排除，就不能让操作员把它忘掉。

### 报警系统常用术语

| 术语 | 含义 | 本案例对应 |
|---|---|---|
| 报警点 | 触发报警的那个现场信号 | 故障信号 I0.0 |
| 声光报警 | 用声音 + 灯光同时提醒，双保险 | 蜂鸣器 Q0.3 + 报警灯 Q0.2 |
| 确认（消音） | 操作员表示"已知悉"，声音停止、灯光保留 | 确认按钮 I0.1 → 确认标志 M0.1 |
| 报警记忆 | "报警发生过且尚未恢复"的状态被锁存 | 故障记忆 M0.0 |
| 复位（恢复） | 故障真正消失，报警状态解除 | I0.0 变 0 → M0.0、M0.1 清零 |
| 闪烁（方波） | 灯亮灭周期性交替的信号 | 闪烁方波 M10.0（周期 2 秒） |

## 四、编程思路总览

拿到控制要求，先别急着画梯形图，把它拆成三个小问题：

**问题 1：怎么表达"有故障"这件事？**

用置位（S）/复位（R）：故障信号为 1 时，置位"故障记忆" M0.0；故障信号为 0（故障消除）时，复位 M0.0。这样，程序中所有输出都只需要看 M0.0 这一个位，逻辑会非常清爽。

**问题 2：蜂鸣器什么时候响？**

有故障（M0.0 = 1）**且**还没确认（M0.1 = 0）→ 响。按下确认按钮就把 M0.1 置位，蜂鸣器立刻停。

**问题 3：灯什么时候闪、什么时候常亮、什么时候灭？**

- 有故障 且 未确认 → **闪烁**（灯 = 故障记忆 与 闪烁方波 相"与"）；
- 有故障 且 已确认 → **常亮**（灯 = 故障记忆 与 确认标志 相"与"，不经过方波，所以闪不起来）；
- 无故障 → **灭**（M0.0 = 0，上面两条路都不通）。

其中"闪烁方波"由两个 TON 定时器交替接力产生，这是本案例的技术核心，第六节会掰开揉碎讲清楚。

## 五、梯形图逻辑分析（逐网络段）

程序共 7 个网络段，扫描时按 1→2→3→4→5→6→7 的顺序，每个扫描周期执行一遍。

### 网络段1：故障到来，置位故障记忆

```
     故障信号                      故障记忆
      I0.0                          M0.0
   ----| |--------------------------(S)----
```

**文字分析：**

- I0.0 变为 1（有故障）→ 常开触点接通 → 置位线圈 (S) 把 M0.0 写成 1。
- (S) 是**置位线圈**：一旦通电，就把操作数"锁"在 1，之后即使 I0.0 变回 0，M0.0 依然是 1——这正是"记忆"的来源。要把它变回 0，只能靠复位线圈 (R)（网络段2）。
- 故障信号持续为 1 期间，(S) 每个扫描周期都在执行，但结果不变（本来就是 1），没有任何副作用。

### 网络段2：故障消除，复位故障记忆与确认标志

```
     故障信号
      I0.0
   ----|/|----+----------------------(R)----  M0.0 故障记忆
              |
              +----------------------(R)----  M0.1 确认标志
```

**文字分析：**

- I0.0 = 0（故障消除）→ 常闭触点接通 → 两个复位线圈 (R) 同时把 M0.0、M0.1 清零。
- M0.0 清零 → 报警灯失去"故障"这个前提 → 灯灭，满足要求 3。
- M0.1 为什么要一起清？因为它是"已确认"标志。如果不清零，下一次故障来的时候蜂鸣器会被上一次的"确认"消音，等于新报警被旧状态"吃掉"了。
- 平时没有故障时，这一段也在持续复位，但两个位本来就是 0，无影响。

### 网络段3：确认按钮，置位确认标志

```
     确认按钮                      确认标志
      I0.1                          M0.1
   ----| |--------------------------(S)----
```

**文字分析：**

- 按下确认按钮 → M0.1 置 1。此后：蜂鸣器停（网络段6 的常闭触点断开），报警灯由闪烁转为常亮（网络段7 切换到下分支）。
- 这里用普通触点 + 置位线圈即可：人手按下按钮再快也远超一个扫描周期，PLC 一定能捕捉到。学完第 6 章的边沿指令后，你也可以把它改成 P 触点写法，更严谨。
- 小细节：本程序允许"无故障时按确认"（M0.1 会被提前置位）。如果工程上想限制"只有报警期间按确认才有效"，在本段串联一个 M0.0 的常开触点即可。

### 网络段4：闪烁发生器第一拍（决定"亮"的 1 秒）

```
     故障记忆       切换脉冲       +----------------+
      M0.0          M10.1         |   TON_闪烁1    |
   ----| |----------|/|------------+IN              |
                                   |           Q    +----(  )---- M10.0 闪烁方波
                                   | PT := T#1s     |
                                   +----------------+
```

**文字分析：**

- 两个串联条件：有故障（M0.0 = 1），且 M10.1 没有接通（常闭触点）。
- 条件满足后 TON_闪烁1 开始计时，1 秒计时到 → 输出 Q = 1 → M10.0 = 1。
- 复习一下 TON（通电延时定时器）的三个关键引脚：**IN** 计时允许（有能流才开始计时），**PT** 预设时间，**Q** 计时到后输出 1；IN 断开瞬间计时值清零、Q 回 0。

### 网络段5：闪烁发生器第二拍（决定"灭"的 1 秒）

```
     闪烁方波                      +----------------+
      M10.0                       |   TON_闪烁2    |
   ----| |------------------------+IN              |
                                   |           Q    +----(  )---- M10.1 切换脉冲
                                   | PT := T#1s     |
                                   +----------------+
```

**文字分析：**

- M10.0 变 1 后，TON_闪烁2 开始计时；1 秒到 → M10.1 = 1。
- M10.1 = 1 会立刻"打断"网络段4（那里的常闭触点断开）→ TON_闪烁1 复位 → M10.0 = 0；
- M10.0 = 0 又让网络段5 的输入断开 → TON_闪烁2 复位 → M10.1 = 0 → 网络段4 重新开始计时……如此周而复始。
- 最终效果：**M10.0 亮 1 秒、灭 1 秒，周期 2 秒的方波**。两个定时器就像两班倒的工人，互相交接班，谁也不许偷懒。

### 网络段6：蜂鸣器控制（未确认就响）

```
     故障记忆       确认标志         蜂鸣器
      M0.0          M0.1             Q0.3
   ----| |----------|/|--------------( )----
```

**文字分析：**

- 有故障（M0.0 = 1）且未确认（M0.1 = 0）→ 蜂鸣器响。
- 按下确认（M0.1 = 1）→ 常闭触点断开 → 立刻静音。
- 故障消除（M0.0 = 0）→ 同样不响。

### 网络段7：报警灯控制（未确认闪烁、确认常亮、消除熄灭）

```
     故障记忆      闪烁方波      确认标志          报警灯
      M0.0         M10.0         M0.1              Q0.2
   ----| |--+------| |-----------|/|--------------( )----
            |
            |    确认标志
            |     M0.1
            +------| |--------------------------------
```

**文字分析：**

- **上分支**：有故障、闪烁方波为 1、且未确认 → 灯亮。方波每 2 秒翻转一次 → 灯闪烁。
- **下分支**：有故障且已确认（M0.1 = 1）→ 灯常亮（这条路不经过方波，所以是稳定的亮）。
- 两个分支互斥：未确认时下分支断开（M0.1 常开不通）；已确认时上分支被 M0.1 常闭切断。不会出现"两条路同时抢一个线圈"的情况。
- 无故障时 M0.0 = 0，两个分支都断 → 灯灭。

**程序整体执行顺序回顾**：网络段1、2 决定"有没有故障"，网络段3 决定"确没确认"，网络段4、5 产出方波，网络段6、7 根据这些标志驱动输出。把网络段4、5 放在网络段7 之前，是为了让灯用到的 M10.0 是"本周期刚算出来的新值"。

### 扫描级推演：一次完整报警的生命周期

| 扫描时刻 | I0.0 | I0.1 | M0.0 | M0.1 | Q0.3 蜂鸣器 | Q0.2 报警灯 |
|---|---|---|---|---|---|---|
| T0 平时 | 0 | 0 | 0 | 0 | 0 | 0 |
| T1 故障出现 | 1 | 0 | 1（网络段1 置位） | 0 | 1 | 闪 |
| T2 故障持续 | 1 | 0 | 1 | 0 | 1 | 闪（M10.0 每秒翻转） |
| T3 按下确认 | 1 | 1 | 1 | 1（网络段3 置位） | 0（被 M0.1 常闭切断） | 1 常亮（切到下分支） |
| T4 松开确认 | 1 | 0 | 1 | 1（置位保持） | 0 | 1 常亮 |
| T5 故障消除 | 0 | 0 | 0（网络段2 复位） | 0（同时被复位） | 0 | 0 |
| T6 再次故障 | 1 | 0 | 1 | 0 | 1 | 闪（新一轮报警） |

这张表完整验证了"响 → 确认 → 常亮 → 消除 → 灭"的三段式流程；而且从 T5 回到 T1 后系统能原样再来一遍，这正是复位彻底（M0.0、M0.1 一起清零）带来的好处。

## 六、报警灯闪烁的实现方法（两个 TON 交替，详细解释）

### 6.1 为什么一个定时器不够？

新手常会想："让灯的线圈隔一秒通断一次不就行了？"但 PLC 没有现成的"隔一秒"指令，必须靠定时器。而**一个定时器只能"到点输出"，不能自己把自己取消再重来**——TON 的 IN 一直接通时，它到时后 Q 就一直是 1，不会再产生周期性变化。所以要用**两个定时器互相接力**：一个负责"亮"持续多久，另一个负责"灭"持续多久。

### 6.2 接力过程逐拍分析

初始状态（无故障）：M10.0 = 0，M10.1 = 0，两个定时器都未计时。故障出现（M0.0 = 1）之后：

| 时间段 | TON_闪烁1 | TON_闪烁2 | M10.0 | M10.1 | 报警灯 |
|---|---|---|---|---|---|
| 0 ~ 1s | 计时中 | 未计时 | 0 | 0 | 灭 |
| 1 ~ 2s | 已到时，Q=1 | 计时中（被 M10.0 触发） | 1 | 0 | 亮 |
| 2s 时刻 | Q=1 | 到时，Q=1 | 1 | 1（瞬时） | 亮 |
| 2s 后第一拍 | 被 M10.1 常闭切断 → 复位 | 因 M10.0=0 → 复位 | 0 | 0 | 灭 |
| 2 ~ 3s | 重新计时 | 未计时 | 0 | 0 | 灭 |
| 3 ~ 4s | ……循环往复 | | 1 | | 亮 |

时序图（文字版）：

```
I0.0 故障信号   ┌──────────────────────────────────────►  有故障
              ──┘

M10.0 闪烁方波  ┐           ┌───────────┐           ┌──────
              ──┘───────────┘           └───────────┘
               灭 1s   亮 1s     灭 1s     亮 1s   灭 1s
               0~1s    1~2s      2~3s      3~4s    4~5s
                              ↑ 周期 = 2 秒，占空比 50%

M10.1 切换脉冲 ─────────────────┐┌────────────────────────
                                └┘ ← 仅瞬时接通，负责"交接班"
                                ↑
                               2s（亮转灭的时刻）

Q0.2 报警灯     与 M10.0 一致（未确认期间）→ 闪烁
```

记住口诀：**一个定时器管"亮多久"，另一个管"灭多久"，M10.1 是两个定时器交接用的临时脉冲。**

### 6.3 改变闪烁频率与占空比

- 两个 PT 都是 T#1s → 亮 1 秒、灭 1 秒（本案例默认）；
- 想要急促闪烁（如紧急报警）→ 都改成 T#200ms；
- 想要"亮 0.3s、灭 0.7s"的非对称闪烁 → 两个 PT 分别设 T#300ms 和 T#700ms；
- **周期 = PT1 + PT2**，亮、灭时间互不影响，分别由两个定时器决定。

1. 程序编写完成后，先点"保存"，再对 PLC_1 执行"编译 → 软件（全部编译）"，确认 0 错误；
2. 点击工具栏"启动仿真"按钮（或菜单"在线 → 仿真 → 启动仿真"），PLCSIM 窗口打开，选择 SIMATIC S7-1500 系列 CPU；
3. 回到 TIA Portal，在项目树中选中 PLC_1，点击"下载到设备"（硬件和软件一起下载）；
4. 在"装载预览"对话框中点击"装载"；出现"停止模块？"提示时选择停止，随后在"装载结果"中选择"全部启动"；
5. 下载完成后将 PLCSIM 中的 CPU 切换到 **RUN**，TIA 项目树中 PLC_1 的"在线"状态变为绿色，表示一切就绪。

### ③ 用监控表模拟输入信号

1. 项目树 → PLC_1 → "PLC 变量" → "添加新监控表"，命名为"报警测试"；
2. 把 ① 中的变量逐行拖入监控表；
3. 点击监控表工具栏的"监视"图标（眼镜），进入在线监视状态，此时能看到各变量实时值；
4. 模拟故障：在"故障信号 I0.0"行的"修改"列输入 **1**，点击"修改"图标（或按回车后点修改）→ 相当于故障信号接通；输入 **0** 再修改 → 相当于故障消除；
5. 模拟确认：在"确认按钮 I0.1"行输入 1 并修改（按下），约半秒后改回 0（松开），模拟"按一下"的动作。

> 另一种更直接的办法：直接在 PLCSIM 窗口里的 SIM 表格中勾选 / 取消勾选 I0.0、I0.1 的复选框，效果与监控表修改完全相同。两种方式任选其一，本课程后续统一使用监控表——因为它还能同时监视 Q、M 和背景DB变量，调试信息更全。

### ④ 预期结果

- **I0.0 置 1 瞬间**：M0.0 变 1；蜂鸣器 Q0.3 立即变 1；报警灯 Q0.2 的监视值在 0/1 之间每秒变化一次（闪烁）；M10.0 同步翻转；TON_闪烁1、TON_闪烁2 的 ET 值在 0~1s 之间来回爬升；
- **按下 I0.1（确认）**：Q0.3 立即变 0（消音）；M0.1 变 1；Q0.2 恒定为 1 不再变化（常亮）；
- **松开 I0.1**：Q0.2 仍为 1——置位标志保持了"故障记忆"；
- **I0.0 置 0（故障消除）**：Q0.2 = 0，M0.0 = 0，M0.1 = 0，一切归零；
- **再次 I0.0 置 1**：报警重新开始（灯闪 + 蜂鸣器响），说明系统能循环使用。

### ⑥ 结果不符时的排查方法

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 灯常亮不闪 | 两个 TON 的 PT 写错；网络段7 上分支漏串 M10.0；M10.0/M10.1 触点开闭用反 | 监视 M10.0 是否在翻转；核对网络段4、5、7 |
| 灯一直灭 | 网络段1 没写成 (S)（写成普通线圈后又被网络段2 复位）；M0.0 从未置位 | 监视 M0.0；检查 (S)/(R) 用法 |
| 蜂鸣器按确认后不停 | 确认按钮地址写错；M0.1 没置上；网络段6 误用常开触点 | 监视 I0.1、M0.1 |
| 确认后灯不常亮反而熄灭 | 网络段7 下分支没写或 M0.1 触点类型错 | 检查下分支 M0.1 常开触点 |
| 闪烁太快或太慢 | PT 值与预期不符（如写成 T#100ms） | 核对 T#1s |
| 下载失败/找不到设备 | PLCSIM 未先启动；PG/PC 接口未选 PLCSIM | 先启动仿真再下载，接口选 PLCSIM |
| CPU 报错停机（SF 灯亮） | 访问了不存在的变量或已删除的背景DB | 打开"在线与诊断"查看诊断缓冲区 |

## 八、扩展：多报警点处理思路

真实设备往往不止一个故障点（过热、超压、缺料、堵转……）。几种常见扩展思路：

**思路 1：多点并联报警（最简单）**

把各故障点的常开触点**并联**，共同去置位同一个"故障记忆" M0.0——任何一个故障都会触发报警：

```
     故障1 I0.4
   ----| |--+
     故障2 I0.5
   ----| |--+--------------------(S)----  M0.0 故障记忆
     故障3 I0.6
   ----| |--+
```

注意：复位条件要相应改成"所有故障信号常闭触点**串联**"（即全部无故障才复位），否则一个故障没消除，其他故障消除了灯却灭了。

**思路 2：故障字方式（工程上最常用）**

用一个字（如 MW30）的每一位对应一个报警点，各位置位/复位互不干扰：

```
MW30（故障字）
  位：   M30.0     M30.1     M30.2     M30.3 …
含义：   液压故障   电机过热   缺料      气压低
触发：   I0.4 置1   I0.5 置1   I0.6 置1  I0.7 置1
```

报警总条件用比较指令"MW30 <> 0"判断——只要故障字不为 0，就说明至少有一个报警点在报警，触发本案例的报警灯与蜂鸣器逻辑。上 HMI 画面时还能按位显示具体报警文本，一目了然。

**思路 3：瞬时故障捕捉**

有的故障一闪而过（持续时间不到一个扫描周期），用电平采集会漏掉。可以用第 6 章的 P 触点先捕捉故障信号的上升沿，再置位记忆位，保证"来了就记录"：

```
     故障信号 I0.4                 故障锁存
       ----|P|--------------------(S)----  M1.0
       边沿存储位 M1.5
```

即使故障信号只出现一个扫描周期，M1.0 也被锁存下来，之后由人工确认或定时延时复位。

**思路 4：分级报警**

不同严重程度用不同表现：预警 = 黄灯慢闪；重要 = 红灯快闪；紧急 = 红灯快闪 + 蜂鸣器响。方法就是把本案例的电路按不同参数复制几套。

**思路 5：与 HMI 配合**

在 TIA 中组态 HMI 的"离散量报警"，由 PLC 中的位变量触发，自动记录报警时间与文本。这是更进一步、也是工厂里最普遍的做法，后续 HMI 章节会介绍。

## 📌 本章小结

- 报警系统三段式：**灯闪 + 响（引起注意）→ 确认后灯常亮（记忆）→ 故障消除灯灭（恢复）**；
- 置位 (S) / 复位 (R) 实现"记忆"，是报警类程序的灵魂：故障到来置位记忆位，故障消除复位；
- 两个 TON 交替接力 = 最经典的方波/闪烁发生器：一个管"亮多久"，一个管"灭多久"，周期 = PT1 + PT2，M10.1 只做"交接班"的瞬时脉冲；
- 多个输出复用 M0.0（故障记忆）、M0.1（确认标志）等中间继电器，让程序条理清晰、便于扩展；
- 多报警点可用并联置位、故障字（MW）、边沿捕捉、分级报警等思路扩展。

## ⚠️ 常见错误与注意事项

1. **(S) 和 (R) 别用错**：网络段1 必须是 (S)。如果写成普通线圈 ( )，M0.0 会跟着 I0.0 变，故障一消除记忆就丢了，网络段2 的复位也就失去意义。
2. **不要双线圈**：Q0.2 只在网络段7 输出一次。若你在两个网络里都用普通线圈写 Q0.2，"后写的覆盖先写的"，逻辑会乱套。需要多分支时，把分支并联到同一个线圈上。
3. **两个 TON 必须各有各的背景DB**：TON_闪烁1 和 TON_闪烁2 不能共用一个实例，共用会互相覆盖数据，定时完全错乱。
4. **M10.1 在监控表里几乎看不到**：它是持续一两个扫描周期的瞬时脉冲，肉眼大概率捕捉不到，属于正常现象，不要因此怀疑程序错了。
5. **确认按钮的硬件接法**：实际工程中，停止、急停类按钮推荐硬件上接**常闭触点**（断线也能被发现，更安全），此时程序里要用**常开**触点；本课程教学程序按"按钮硬件常开、程序里用常闭触点实现停止逻辑"的约定编写。两种接法逻辑相反，切勿混淆。
6. **PT 的书写格式**：必须写成 T#1s 这种格式（T# 开头），写成"1s"或漏掉 T# 会编译报错。
7. **修改输入不生效**：在监控表改完数值后要点"修改"图标才真正写入，只输入数字回车不一定生效。
8. **复位要彻底**：故障消除时 M0.0 和 M0.1 要一起复位，否则下次报警蜂鸣器不响（被旧的"已确认"状态消音）。

# 案例03：计数亮灯——按一次亮一盏，数到 5 全部熄灭循环

## 📖 学习目标

1. 巩固 CTU 计数器的使用，掌握"计数 + 比较"这一经典组合思路；
2. 学会用比较指令（CMP ==/≥）根据计数值分别驱动不同的输出；
3. 理解"计到目标值后自动复位、循环往复"的实现方法；
4. 能独立完成本案例梯形图编写，并在 PLCSIM 中完成全流程仿真验证；
5. 了解用移位指令实现同样功能的更优思路。

---

## 一、控制要求

**需求描述**：有一个按钮，每按一次计数值加 1：

- 计数值 = 1 → 灯 1 亮；
- 计数值 = 2 → 灯 2 亮（灯 1 灭）；
- 计数值 = 3 → 灯 3 亮（只有灯 3 亮）；
- 计数值 = 4 → 灯 4 亮（只有灯 4 亮）；
- **计数值 = 5 → 所有灯全部熄灭，计数值自动清零复位**；
- 之后从头开始：再按一次又是灯 1 亮……如此**循环往复**。

行为对照表（按一次 = 一个完整的"按下并松开"动作，即一个上升沿）：

| 按压次数 | 计数值 CV | 灯1 Q0.0 | 灯2 Q0.1 | 灯3 Q0.2 | 灯4 Q0.3 |
|---|---|---|---|---|---|
| 初始 | 0 | 灭 | 灭 | 灭 | 灭 |
| 第 1 次 | 1 | **亮** | 灭 | 灭 | 灭 |
| 第 2 次 | 2 | 灭 | **亮** | 灭 | 灭 |
| 第 3 次 | 3 | 灭 | 灭 | **亮** | 灭 |
| 第 4 次 | 4 | 灭 | 灭 | 灭 | **亮** |
| 第 5 次 | 5 → 自动清 0 | 灭 | 灭 | 灭 | 灭 |
| 第 6 次 | 1 | **亮** | 灭 | 灭 | 灭（新一轮循环） |

另外补充一个便民设计：任何时刻按**复位按钮**，计数值清零、所有灯熄灭，方便随时从头开始。

> 说明：本案例为独立的练习工程，I/O 地址独立分配（灯 1~灯 4 占用 Q0.0~Q0.3），与前面案例中的报警灯 Q0.2 等约定不冲突。

### 几个名词约定

- **按压一次**：指一个完整的"按下并松开"过程，在 PLC 眼里就是输入信号的一个上升沿（0→1）。按住不松手，无论多久都只算一次；
- **全灭复位**：计数值到达 5 时，4 盏灯全部熄灭、计数值清零回到 0。这一步由程序**自动**完成，不需要人按任何按钮；
- **循环往复**：清零之后从"计数值 1 亮灯 1"重新开始，5 个状态周而复始，永远循环下去；
- **手动复位**：额外的便民功能——任何时刻按复位按钮立即清零、全灭，方便从头再来。

### 用"状态机"的眼光看本案例

把 5 个状态排成一串，状态之间唯一的前进动力就是"按压"：

```
 全灭 → 灯1亮 → 灯2亮 → 灯3亮 → 灯4亮 → 全灭 → 灯1亮 → ……
  ↑                                │
  └────────── 自动清零 ←────────────┘
 （每个箭头 = 按压一次，即一个上升沿）
```

系统永远在"全灭 / 灯1 / 灯2 / 灯3 / 灯4"这 5 个状态里转圈，走到哪一格完全由"当前计数值"决定。这种"一个状态接一个状态往下走"的结构，专业上叫**顺序控制**，本案例就是它最迷你的样子——将来学到步进/顺控编程时，你会发现思想与此完全一致。

## 三、实现思路（计数器 + 比较思路）

### 3.1 核心思想："计数值"是全场唯一的主角

这个需求看起来有 4 盏灯、5 种状态，好像很复杂。抓住一个关键：**灯亮不亮，完全由计数值决定**。计数值是几，就亮几号灯；计数值是 5（或 0），就全灭。

所以整个程序只需要两件事：

1. **准确地把计数值数出来**：用 CTU，每次按钮的上升沿加 1（第 7 章讲过，CTU 输入自带上升沿检测，普通触点直接接 CU 即可）；
2. **把计数值"翻译"成灯**：用 4 条比较指令——CV 等于 1 点亮灯 1，等于 2 点亮灯 2……就像老师点名：喊到 1 号，1 号起立；喊到 2 号，2 号起立，1 号自动坐下（因为比较条件不再满足，灯自动熄灭）。

### 3.2 自动复位怎么实现

计到 5 要"全灭 + 清零"。全灭不用做——CV=5 时没有任何一条比较条件成立，4 盏灯自然全灭。**要做的只有清零**。

方法：用比较指令"CV ≥ 5"产生一个复位脉冲 M0.1，把它和手动复位按钮 I0.1 并联，一起接到计数器的 **R 引脚**。执行顺序上，计数网络在前、比较网络在后：第 5 次按压让 CV 变成 5 → 同一扫描周期比较结果为真、M0.1=1 → **下一个扫描周期** R=1 把 CV 清零 → 比较结果变假、M0.1 回 0。M0.1 只"亮"一个扫描周期，完成一次干净利落的自动复位，之后 CV 从 0 重新开始计数，实现循环。

> 为什么用 ≥ 而不用 ==？两者在本程序中效果相同（CV 不可能超过 5，因为一到 5 就被复位）。但 ≥ 更保险：万一以后程序改动导致计数值跳过 5，用 == 就会"数过头再也回不来"，用 ≥ 则稳稳兜住。工程上养成"复位条件用 ≥"的习惯。

### 3.3 数据类型匹配

背景DB选 CInt，CV 是 Int 类型；比较指令两侧的类型必须一致——左侧接 CV（Int），右侧填十进制常数 1/2/3/4/5（TIA 会自动按所选比较类型处理常数），比较器选"== Int"和"≥ Int"。

### 3.4 一个被否掉的思路：用置位/复位逐个点亮

有同学会想：计到 1 置位灯 1、计到 2 复位灯 1 再置位灯 2……不也能做出来吗？能，但不好：

- 每盏灯都要写"上一盏复位 + 自己置位"，网络数量大约翻一倍；
- 灯与灯之间互相牵连，手动复位、循环清零时要额外处理每一盏灯的复位，漏一盏就是 bug；
- 而"比较驱动"的灯：计数值一变，比较条件自然不成立，灯自动灭，**复位灯的逻辑一行都不用写**。

对比之后你会发现：让"计数值"当唯一主角、所有输出都去跟它比较，程序最短、最不容易出错。这里还藏着一个重要的编程思想——**尽量让中间变量（计数值）成为唯一的状态来源，输出全部由它派生**。状态只有一个源头，程序就不会自相矛盾。

### 3.5 比较指令家族速览

本案例只用到 == 和 ≥，但比较器是一个家族，顺手认识一下：

| 比较方式 | 符号 | 含义 | 本案例中的用途 |
|---|---|---|---|
| 等于 | == | 左边 = 右边时导通 | 各盏灯的点亮条件 |
| 不等于 | <> | 左边 ≠ 右边时导通 | 例：判断"故障字非 0" |
| 大于 / 小于 | > / < | —— | 范围判断 |
| 大于等于 / 小于等于 | ≥ / ≤ | —— | 自动复位条件 CV≥5 |

比较器两侧可以是"变量比常数"，也可以是"变量比变量"（比如两个计数器的当前值互相比），唯一要求是**两侧数据类型必须一致**。

## 四、梯形图逻辑分析（逐网络段说明）

程序共 6 个网络段：1 段计数、1 段自动复位、4 段亮灯。

### 网络段1：按钮计数（CTU）

```
                                     +------------------+
     计数按钮                         |  CTU_亮灯计数    |
      I0.0                           |                  |
    ----| |--------------------------+CU                |
                                     |                  |
     复位按钮        +---------------+R                 |
      I0.1           |               |                  |
    ----| |----------+               |PV := 5           |
                                     |                  |
     复位脉冲        +---------------+                  |
      M0.1           |               |            Q     |----（悬空不接）
    ----| |----------+               |            CV    |----（悬空，监控表
                                     +------------------+      里看 CTU_亮灯计数.CV）
```

文字分析：

- **CU** 接计数按钮 I0.0：每个上升沿 CV 加 1。按住不松只加 1 次，必须完整按压；
- **R** 引脚接的是两路并联信号：手动复位按钮 I0.1（常开触点）+ 自动复位脉冲 M0.1。任何一路为 1，CV 立刻清零。R 优先级最高，R=1 期间不计数；
- **PV := 5**：预设值。注意（第 7 章的细节）：CV 到 5 后并不会自动停下，所以必须靠网络段2 主动复位；
- **Q** 引脚本例悬空（有没有"数到 5"由网络段2 的比较来判断）；**CV** 也悬空，调试时在监控表里直接监视背景DB变量。

**小问答：能不能把 I0.1 和 M0.1 分成两条网络分别接到 R 上？** 不能。一个 CTU 框只有一个 R 引脚，两路信号要汇入同一个引脚，就必须在引脚前做并联（本案例的做法）；或者先把两路信号"或"成一个中间位，再拿中间位去接 R。总之，一个引脚只能接一条线。

### 网络段2：计到 5，产生自动复位脉冲

```
      CTU_亮灯计数.CV          5
    ----------[≥ Int]--------------( )----  M0.1 复位脉冲
```

文字分析：

- 比较器：左边取计数器的当前值 CV，右边是常数 5，比较方式"≥（大于或等于）Int"；
- CV ≥ 5 时 → M0.1 = 1 → 送给网络段1 的 R 引脚，下一个扫描周期把 CV 清零；
- 清零后 CV=0，比较条件不成立，M0.1 自动回 0——它天然就是一个"只亮一个扫描周期"的脉冲，不需要额外做边沿检测；
- 扫描顺序提醒：本网络段必须放在网络段1 **之后**，这样第 5 次按压当拍就能看见 CV=5，下一拍完成复位，动作衔接干净。

### 网络段3：计数值为 1，点亮灯 1

```
      CTU_亮灯计数.CV          1
    ----------[== Int]--------------( )----  Q0.0 灯1
```

文字分析：

- CV = 1 → 灯 1 亮；
- CV 变成其他任何值（0、2、3、4）时，比较不成立 → 灯 1 自动灭。**灯的亮灭不需要额外的复位逻辑，比较条件本身就是"亮"与"灭"的开关**——这就是"计数 + 比较"思路最省心的地方；
- 同一时刻最多只有一个"== 比较"成立，所以 4 盏灯天然互斥，绝不会两盏同时亮。

### 网络段4：计数值为 2，点亮灯 2

```
      CTU_亮灯计数.CV          2
    ----------[== Int]--------------( )----  Q0.1 灯2
```

文字分析：与网络段3 完全同构，只是比较值换成 2、输出换成灯 2。计数值为 2 时，只有灯 2 亮。

### 网络段5：计数值为 3，点亮灯 3

```
      CTU_亮灯计数.CV          3
    ----------[== Int]--------------( )----  Q0.2 灯3
```

文字分析：比较值 3、输出灯 3，逻辑同上。

### 网络段6：计数值为 4，点亮灯 4

```
      CTU_亮灯计数.CV          4
    ----------[== Int]--------------( )----  Q0.3 灯4
```

文字分析：比较值 4、输出灯 4，逻辑同上。计数值为 5 时四个"== 比较"全都不成立 → 全灭；同时"≥ 5"成立 → 清零 → 回到起点，循环开始新一轮。

### 程序整体执行顺序串讲

每个扫描周期：网络段1 先数数（或复位）→ 网络段2 判断要不要自动复位 → 网络段3~6 按最新计数值点亮对应的灯。按 5 次按钮的完整过程：CV 走过 1→2→3→4→5，灯 1→2→3→4 依次点亮、前灯自动熄灭，第 5 次按压后全灭清零，第 6 次按压又是灯 1 亮，周而复始。

### 扫描级推演：第 5 次按压前后发生了什么

| 扫描周期 | 事件 | CV（网络段1 执行后） | M0.1（网络段2 执行后） | 点亮的灯 |
|---|---|---|---|---|
| n | 第 4 次按压刚发生 | 4 | 0 | 灯 4 |
| n+1 ~ n+k | 没有按压 | 4 | 0 | 灯 4（比较一直成立，自保持） |
| n+k+1 | 第 5 次按压上升沿 | 5 | 1（CV≥5 成立） | 无（4 个 == 全不成立，全灭） |
| n+k+2 | R 引脚 = M0.1 = 1 | 0（被清零） | 0（CV 已是 0，条件不再成立） | 无 |
| n+k+3 之后 | 等待下一次按压 | 0 | 0 | 无 |
| …… | 第 6 次按压 | 1 | 0 | 灯 1（新一轮循环） |

看 n+k+1 和 n+k+2 两行，就能理解"自动复位"的全部秘密：M0.1 当拍亮起，下一拍把 CV 清零，随后自己熄灭——接力只有两拍，干净利落，不需要任何边沿指令帮忙。

### 动手编写：在 TIA Portal 中的操作步骤

1. 新建项目，添加 CPU（如 CPU 1511-1 PN），打开 OB1（LAD 编辑器）；
2. 在 PLC 变量 → 默认变量表中，按第二节的清单建立全部 I/Q/M 变量（统一中文名）；
3. 网络段1：从右侧指令面板"基本指令 → 计数器"把 CTU 拖入网络 → 在弹出的"调用选项"对话框中选"单个实例"、名称填"CTU_亮灯计数"、数据类型选 CInt → 确定；
4. 在 CTU 框上填引脚：CU ← I0.0 计数按钮常开触点；R ← 先接 I0.1 常开触点，再用"分支"工具把 M0.1 常开触点并联进来；PV 填常数 5；Q、CV 悬空；
5. 网络段2：拖入比较器（基本指令 → 比较器）选"≥ Int"，左操作数点开选择框，在"全局变量 → 默认变量表 → CTU_亮灯计数"下选 CV，右操作数填 5，输出接 M0.1；
6. 网络段3~6：复制网络段2，比较方式改为"== Int"，常数分别填 1/2/3/4，输出分别接 Q0.0~Q0.3；
7. 保存 → 编译 → 按第五节步骤下载到 PLCSIM 验证；
8. 全部验证通过后，把项目另存一份留作对照——学完移位指令章节后，可以用 SHL 把本案例重写一遍，直观对比两种思路的程序长度。

**编写小技巧**：网络段3~6 与网络段2 结构几乎相同。先写好网络段2，再用"复制网络 + 粘贴"生成其余三条，然后逐条修改三处——比较方式（≥ 改为 ==）、比较常数（5 改为 1/2/3/4）、输出地址（改为 Q0.0~Q0.3）。粘贴后务必逐条核对这三处，漏改一处，症状就是"某盏灯永远不亮"或"两盏灯同时亮"。

### ④ 预期结果

- 初始：CV=0，4 盏灯全灭；
- 第 1 次 0→1：CV=1，灯 1（Q0.0）变 1，其余为 0；松开后灯 1 保持亮（比较条件一直成立）；
- 第 2 次：CV=2，灯 1 自动灭、灯 2 亮；
- 第 3 次：CV=3，只有灯 3 亮；第 4 次：CV=4，只有灯 4 亮；
- 第 5 次：CV 短暂到达 5 后被自动清零，最终 CV=0，**4 盏灯全灭**（M0.1 的脉冲太快，监控表里可能看不到它变 1，正常）；
- 第 6 次：CV=1，灯 1 又亮——新一轮循环开始；
- 任意时刻按 I0.1：CV 立即归 0、全部灯灭；
- 全程"至多一盏灯亮"的规律始终成立——4 条"== 比较"天然互斥，任何时刻最多一条导通；
- 复位按钮按住不放时：R 引脚持续为 1，期间按压计数按钮不会计数（复位优先），松开后一切恢复正常。

### ⑥ 结果不符时的排查方法

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 按了按钮 CV 不变 | I0.0 没回 0（上次置 1 后没复位）；R 引脚被长期置 1 | 监视 CTU_亮灯计数.CU 和 R 的实际值 |
| 某盏灯从来不亮 | 对应比较网络没写、比较常数填错、输出地址写错 | 逐条核对网络段3~6 的常数与地址 |
| 两盏灯同时亮 | 比较方式误用成 ≥/< 而不是 == | 检查网络段3~6 的比较类型 |
| 数到 5 不清零、再按无反应 | 网络段2 漏写或 CV 引脚取错变量；M0.1 没接入 R | 监视 M0.1 与 R；核对比较器左操作数必须是 CTU_亮灯计数.CV |
| 复位后马上又亮一盏 | 复位瞬间又误按了计数按钮（监控表操作手滑） | 重新干净地操作一遍 |
| 编译报类型不匹配 | 比较器类型与 CV 类型不一致（如选了 DInt） | 比较器统一选 ==Int / ≥Int，与 CInt 背景DB匹配 |
| 下载失败 | PLCSIM 未启动或接口选择错误 | 先启动仿真，PG/PC 接口选 PLCSIM |
| CV 数过 5 还能涨到 6、7 | 网络段2 的比较左操作数取错（如取成 PV），或比较方式/常数填错 | 核对比较器左操作数必须是 CTU_亮灯计数.CV |
| 复位后计数值马上又变成 1 | 复位时误触发了计数按钮 | 监控表操作分步进行：先复位完成，再计数 |
| 灯亮的顺序错乱 | 网络段3~6 复制后常数没改对（如两条都填 2） | 逐条核对比较常数与输出地址 |
| 手动复位后立即又计数 | 复位按钮与计数按钮共用监控表操作失误 | 一次只修改一个变量，分步操作 |

### 常见问答

**问：为什么第 5 次按压后看不到任何灯闪一下？**
答：因为没有任何一条"== 比较"在 CV=5 时成立，全灭是自然结果；而且 CV=5 只存在一个扫描周期，随即被清零。

**问：能改成"数到 10 才复位"吗？**
答：能。把 PV 改成 10、网络段2 的比较常数改成 10 即可；灯只有 4 盏的话，状态 5~9 就是"全灭多停留几拍"，程序依然成立——这也是比较思路"可裁剪"的体现。

**问：按压太快会漏计吗？**
答：监控表手工操作不会；真实硬件上，只要每次按压产生的脉冲宽度超过一个扫描周期就不会漏。窄脉冲漏计的原理与对策详见第 7 章第六节。

**问：用 == 比较驱动灯，会不会输出抖动？**
答：不会。两次按压之间 CV 保持不变，比较结果也就稳定不变，灯的状态是稳稳的"电平"；只有计数值跳变的那一个扫描周期比较结果会切换，肉眼完全不可见。

**问：想改成"数到 5 时灯 4 快闪三下再全灭"行不行？**
答：可以。思路是给灯 4 的输出再叠加上"闪烁方波"和一个短暂的定时窗口，学完定时器闪烁与振荡电路后可以回头实现，是一个很好的综合练习。

**问：按到第 4 次后灯 4 一直亮着，中间这段时间程序在干什么？**
答：每个扫描周期都照常执行全部 6 个网络段——只不过 4 条比较里只有"CV==4"这一条成立，其余全部不导通。PLC 就是这样周而复始地值守，直到下一次按压到来。

## 六、扩展：用更优的方式实现（移位指令思路，简述原理）

### 6.1 移位思路是什么

"计数 + 比较"的写法直观，但有个小缺点：**灯越多，比较网络越多**——如果有 8 盏灯，就得写 8 条比较。移位指令提供了另一种视角：把"亮灯的位置"看成一根**接力棒**，每按一次按钮，就让它在输出字节里**向左挪一格**。

先认识两个要素：

- **QB0**：输出字节，它的 8 个位就是 Q0.0~Q0.7——直接给 QB0 赋值，就能同时控制 8 个输出点；
- **SHL（左移指令）**：把字节里的每一位整体向左挪一位，右边空出的位补 0。

### 6.2 工作过程演示

1. 复位/开始时：用 MOVE 指令把 2#0000_0001 送入 QB0 → 只有 Q0.0（灯 1）亮；
2. 每按一次按钮（上升沿），执行一次"SHL 左移 1 位"：

```
QB0 的值： 0000_0001  →  0000_0010  →  0000_0100  →  0000_1000  →  0001_0000
             灯1亮        灯2亮        灯3亮        灯4亮       Q0.4（没接灯 → 全灭！）
                SHL       SHL          SHL          SHL
```

3. 当 QB0 = 2#0001_0000（16#10）时，"1"已经移出灯区，4 盏灯自然全灭——这时用一条比较"QB0 = 16#10"触发复位：再用 MOVE 把 2#0000_0001 写回 QB0，接力棒回到灯 1，循环重新开始。

程序骨架大概长这样（示意，指令细节留待后续章节）：

```
网络段1（初始化/复位）：
   复位按钮 或 "QB0=16#10"比较
  ----| |------+----[MOVE]----
               |    IN := 2#0000_0001
               |    OUT := QB0

网络段2（移位）：
   计数按钮 I0.0
  ----|P|------+----[SHL]----
                    IN := QB0，N := 1（左移 1 位）
                    OUT := QB0
```

对比一下：计数 + 比较思路要 4 条灯网络，移位思路灯的网络为 0 条（灯由 QB0 的位直接点亮），三个网络就完成了全部功能。灯的数量增加时，比较思路要每灯加一条网络，移位思路只需调整复位判断的值——这就是"更优"的含义。8 盏以上、跨字节的移位玩法，留到移位指令章节细讲。

### 动手练习（学完本案例试试）

1. 把 PV 和各比较常数相应放大，改成"数到 10 全灭复位"（需要 9 盏灯吗？不需要——只把比较网络改成你手头有的灯数即可，体会思路的可裁剪性）；
2. 增加一个蜂鸣器 Q0.4：计数值到达 4 时短响一声提示"下一拍就复位"，想想用哪些比较条件；
3. 把手动复位改成"按住 2 秒才复位"（提示：用 TON），防止误碰；
4. 按第六节提示，等学完移位指令后用 SHL 把本案例重写一遍，对比两个版本的程序长度。

### 6.3 与"计数 + 比较"的对比

| 对比项 | 计数 + 比较（本案例） | 移位思路 |
|---|---|---|
| 网络数量 | 每盏灯一条比较，灯越多网络越多 | 移位 1 条 + 复位判断 1 条，灯再多也不加 |
| 可读性 | 直观，一眼看懂"几亮几" | 需要理解位与字节的对应关系 |
| 安全性 | 各灯独立比较，互不牵连 | 直接整字节写 QB0，若程序里还用到 Q0.4~Q0.7 会互相影响 |
| 适用场景 | 灯少、状态含义明确 | 灯多、规律移动（流水灯、顺序步进） |

一句话：**"计数 + 比较"适合刚入门、状态不多的情况；移位思路网络更少、扩展性更强**。移位指令 SHL/SHW/ROL/ROR 的详细用法，将在后续"移位与循环移位指令"章节专门讲解，届时可以回头把本案例用移位方式重写一遍作为练习。

顺带认识一个近亲指令 **ROL（循环左移）**：它移出去的位会绕回最低位，用它做"流水灯"连复位判断都省了；不过本案例"到 5 全灭"的需求，反而是"补 0 的 SHL + 复位比较"更贴合。工具没有绝对优劣，匹配需求才最重要。

## 📌 本章小结

- 本案例的骨架是"**计数器 + 比较**"：CTU 负责把按压次数数准，4 条 == 比较负责把计数值翻译成灯的亮灭，比较条件天然互斥、灯自动切换，无需额外复位灯的逻辑；
- 自动复位的实现：用"**CV ≥ 5**"的比较结果产生复位脉冲 M0.1（只亮一个扫描周期），与手动复位按钮并联接到计数器 R 引脚，实现"数到 5 全灭清零、循环往复"；
- 计数器数的是上升沿：一次完整按压 = 0→1→0；按住不松只计一次；
- 比较指令两侧数据类型必须一致：CInt 背景DB对应 Int 比较器与 Int 常数；
- 移位指令思路（把"1"在 QB0 里逐位左移）是更省网络的替代方案，适合灯多、规律移动的场合，后续章节详细展开。

## ⚠️ 常见错误与注意事项

1. **计数输入必须"完整按压"**：监控表里模拟时，I0.0 要 0→1→0 完整翻转才算一次；只置 1 不回 0，CV 只加 1。
2. **比较器类型要统一**：背景DB选 CInt，比较就选 ==Int / ≥Int。类型混用（如 DInt）会编译报错。
3. **比较器的左操作数必须是"CTU_亮灯计数.CV"**：漏掉背景DB前缀直接写 CV 会找不到变量；写错成 PV 则永远只亮一盏灯。
4. **别指望计数器自己停在 5**：CV 会继续增长，必须靠"≥ 5"的比较加 R 复位来实现循环，否则数到 5 之后再按就"数丢"了。
5. **不要用置位/复位驱动灯**：如果给每盏灯用 (S)/(R) 按次数点亮/熄灭，网络数量翻倍且容易漏复位；比较驱动的灯会随计数值自动灭，逻辑最简洁。
6. **复位脉冲 M0.1 可能看不见**：它只存在一个扫描周期，监控表里通常捕捉不到，属于正常现象。
7. **R 引脚优先级最高**：手动复位按钮按住期间，按压计数按钮不会计数（R=1 封锁计数），这是正常特性，不是故障。
8. **本案例 I/O 与其他案例相互独立**：灯 1~灯 4 用 Q0.0~Q0.3 只针对本练习工程；不同案例分别下载到 PLCSIM 验证，不要把两套程序的变量混在一个工程里比对地址。

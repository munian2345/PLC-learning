# 案例05 四站点呼叫小车控制

## 📖 学习目标

1. 理解"有轨小车"这类往返搬运设备的控制特点，掌握正/反向行驶与到位停车的逻辑建模方法。
2. 学会用"状态记忆"三件套——呼叫记忆、位置记忆、方向标志——来描述一辆会跑的小车。
3. 掌握多目标呼叫的优先级处理思路，理解"编号优先"方案的设计理由。
4. 能独立搭建"呼叫锁存 → 方向判断 → 行车输出 → 到位停车"四模块程序框架，并在 PLCSIM 中完成全流程验证。

---

## 一、案例背景与控制要求

### 1.1 案例背景

在自动化仓库和柔性生产线上，经常能看到一种沿着直线轨道来回奔波的**有轨搬运小车**：生产线旁有 4 个工位（站点），每个工位需要物料时按下呼叫按钮，小车就自动跑到对应工位送取货，送到后原地待命，等待下一次呼叫。

这类控制和人召出租车很像，要解决三个问题：

- **去哪？**——谁按了呼叫（目标记忆）；
- **往哪个方向走？**——目标在我前面还是后面（方向判断）；
- **什么时候停？**——到了目标站（到位停车）。

PLC 没有眼睛，它靠**到位传感器**判断小车到了哪一站：每个站点轨道旁装一个传感器，小车经过或停靠时传感器接通。

### 1.2 行驶方向与到位停车是怎么定义的

四个站点沿轨道从左到右排成一条线，编号 1→2→3→4：

```
  1号站        2号站        3号站        4号站
   ┋────────────┋────────────┋────────────┋
   ○            ○            ○            ○      ○ = 到位传感器
  [呼叫1]      [呼叫2]      [呼叫3]      [呼叫4]
   ↑                                         ↑
 小车初始停在这里                          轨道终点
```

- **正向行驶（Q0.0）**：向编号**增大**的方向走（1→2→3→4）；
- **反向行驶（Q0.1）**：向编号**减小**的方向走（4→3→2→1）；
- **目标判断**：小车记住自己"现在在哪一站"（位置记忆），再对照"哪一站有呼叫"（呼叫记忆）：目标编号比当前位置大 → 正转；比当前位置小 → 反转；
- **到位停车**：小车一进入某站（该站传感器接通），先更新位置记忆；如果该站恰好有呼叫记忆，就**清除呼叫**。呼叫一清，"目标"不存在了，行车输出自然断电——小车就停了。如果清完呼叫后同方向还有别的站呼叫着，小车**不停**，继续往前开（顺路捎带处理）。

### 1.3 控制要求汇总

1. 四个站点各有 1 个呼叫按钮、1 个到位传感器。
2. 按下某站呼叫按钮后，小车自动驶向该站并停在那里，等待下一次呼叫。
3. 小车行进途中路过某个"也有呼叫"的站点时，同样停靠响应。
4. 多个站同时呼叫时，按既定优先级逐个响应（见第二章）。
5. 任何时刻正转、反转输出不得同时接通。
6. 小车停在某一站时收到"本站呼叫"，视为无效（人已经在站里了），不动作。
7. 上电后默认小车停在 1 号站（用首次扫描位写入初始位置）。

## 二、多个站同时呼叫的优先级处理

### 2.1 两种常见方案对比

| 方案 | 规则 | 优点 | 缺点 |
|------|------|------|------|
| 就近优先 | 先响应距当前位置最近的呼叫站 | 等待时间总体最短 | 必须随时计算"目标编号 − 当前位置"的距离并比大小，梯形图要引入减法和多个比较指令，逻辑复杂、易出错 |
| 编号优先 | 固定按站点编号顺序响应（本案例取**小编号方向优先**） | 只需判断"目标编号在当前位置哪一侧"，触点逻辑即可实现；行为完全确定，调试直观 | 极端情况下不是最优路径（比如 4 号站近在咫尺而 1 号站很远，仍要先跑 1 号） |

### 2.2 本案例的选择：编号优先（小编号方向优先）

**规则**：当小车的两侧同时存在呼叫时，**先处理编号小的方向（反向），再处理编号大的方向（正向）**。举例：小车停在 3 号站，1 号和 4 号同时呼叫——小车先反向去 1 号，送完再正向去 4 号。

**选择理由**：

1. **实现最简单**：方向判断只需要"位置记忆 + 呼叫记忆"的触点组合（见 Network 14/15），再反向输出上串一个"反向标志"的常闭触点完成互锁，一个减法指令都不用写。对初学者最友好，也最不容易埋雷。
2. **行为确定、不摇摆**：优先级一旦固定，无论多少个呼叫挤在一起，响应顺序都可以提前推演出来。就近优先方案在"左右两边等距"时还要处理平局规则，否则小车会在两站之间犹豫。
3. **贴近直觉**：与梯形图"从上往下、从小号开始扫描"的习惯一致，讲解和验证都方便。

**工程提示**：如果是站点很多、响应速度要求高的真实仓库，通常改用 SCL 语言写"取最近目标"的算法，或在工艺上规定巡回路线。本案例是教学程序，编号优先是性价比最高的选择。

## 四、实现思路：状态记忆 + 方向判断 + 到位清除

### 4.1 三大核心要素

PLC 眼里的这辆小车，其实就是**两组开关量记忆 + 两级判断**：

1. **呼叫记忆（M0.0~M0.3）——"去哪"**
   呼叫按钮是点动的，手一松信号就没了，所以必须用置位指令 (S) 把呼叫**锁存**下来；到达目标站后再用复位指令 (R) 清除。呼叫记忆 = 小车的"待办清单"。
2. **位置记忆（M2.0~M2.3）——"我在哪"**
   任何时候四个位置记忆**有且只有一个**为 1（互斥）。传感器接通一次，就把对应位置置 1、其余三个清 0。位置记忆 = 小车的"定位标签"。
3. **方向判断 + 到位清除——"怎么走、何时停"**
   把"位置"和"呼叫"放在一起比较：有编号更大的站呼叫 → 正转；有编号更小的站呼叫 → 反转（编号优先时反向优先）。行驶途中每当传感器闪一下，位置记忆就前进一步；到达有呼叫的站，呼叫被清除——没有呼叫了，输出线圈断电，停车是**水到渠成的逻辑结果**，不需要单独写"停车"网络。

### 4.2 程序总体框架（模块划分）

```
┌─────────────────────────────────────────────────────┐
│ Network 1   模块0：上电初始化（FirstScan 写入初始位置） │
├─────────────────────────────────────────────────────┤
│ Network 2~5  模块1：呼叫锁存——按钮 (S) 呼叫记忆        │
├─────────────────────────────────────────────────────┤
│ Network 6~9  模块2：位置记忆——传感器 (S)本站 (R)其余    │
├─────────────────────────────────────────────────────┤
│ Network 10~13 模块3：到位停车——传感器×呼叫记忆 (R)呼叫  │
├─────────────────────────────────────────────────────┤
│ Network 14~15 模块4：方向判断与行车输出（正/反转互锁）  │
└─────────────────────────────────────────────────────┘
```

**扫描顺序很重要**：呼叫锁存（模块1）写在到位清除（模块3）之前，才能保证"小车停在某站时收到本站呼叫"在同一个扫描周期内就被清掉；位置记忆（模块2）写在方向判断（模块4）之前，保证方向判断用的总是"刚更新过"的位置。初学时建议照这个顺序摆放网络。

### 4.3 动作推演示例

**例**：小车停在 1 号站，操作工按下 3 号站呼叫：

```
信号                 时间 →
呼叫记忆3 M0.2       ________########________________
正转 Q0.0            ________########________________
位置记忆1 M2.0       ########________________________
位置记忆2 M2.1       ________________##______________    ← 路过 2 号站（传感器2 瞬间接通）
位置记忆3 M2.2       ________________________########    ← 到达 3 号站（传感器3 接通）

推演过程：
 ① 按下呼叫3 → M0.2 置位锁存；
 ② Network 15：位置1 × 呼叫记忆3 → 正转条件成立，Q0.0=1，小车出发；
 ③ 路过 2 号站：传感器2 闪一下 → 位置记忆由"1"更新为"2"，呼叫3 仍锁存 → 正转条件仍成立，小车不停；
 ④ 到达 3 号站：传感器3 接通 → 位置记忆更新为"3"；Network 12：传感器3 × 呼叫记忆3 → 呼叫3 被清除；
 ⑤ 呼叫清零后，正转条件不复存在 → Q0.0=0，小车停在 3 号站，等待下一次呼叫。
```

## 五、梯形图逻辑分析（逐网络）

### Network 1：上电初始化——假设小车初始停在 1 号站

```
    FirstScan           位置记忆1
  --| |--+-----------------(S)--
   (M1.0)|                 (M2.0)
```

**分析**：上电第一个扫描周期 FirstScan=1，把位置记忆1 置位。之后该位一直为 0，初始化只执行一次。位置记忆 2~4 上电默认为 0，无需处理。没有这一步，方向判断将因"位置全 0"而失明——小车不知道自己在哪，任何呼叫都无法触发正确的方向。

### Network 2：呼叫锁存（1 号站；2~4 号站同理）

```
    呼叫按钮1            呼叫记忆1
  --| |--+-----------------(S)--
   (I0.0)|                 (M0.0)
```

**分析**：按钮按下瞬间把呼叫记忆1 置位。因为用的是 (S)，即使按钮马上松开，"1 号站有人呼叫"这件事也被牢牢记住，直到小车真正到达 1 号站才被清除。Network 3~5 结构完全相同，只是地址换成 I0.1→M0.1、I0.2→M0.2、I0.3→M0.3。

### Network 3~5：呼叫锁存（2~4 号站）

```
    呼叫按钮2            呼叫记忆2         呼叫按钮3            呼叫记忆3
  --| |--+-----------------(S)--          --| |--+-----------------(S)--
         |                 (M0.1)                |                 (M0.2)

    呼叫按钮4            呼叫记忆4
  --| |--+-----------------(S)--
         |                 (M0.3)
```

### Network 6：位置记忆（1 号站；2~4 号站同理）

```
    到位传感器1
  --| |--+-----------------(S)--  位置记忆1 (M2.0)
         |
         +-----------------(R)--  位置记忆2 (M2.1)
         |
         +-----------------(R)--  位置记忆3 (M2.2)
         |
         +-----------------(R)--  位置记忆4 (M2.3)
```

**分析**：传感器1 接通说明小车在 1 号站：置位 M2.0 的同时**必须把其余三个位置记忆全部复位**，保证四个位置记忆永远互斥。如果漏写复位支路，位置记忆会出现"既是 1 又是 2"的矛盾状态，方向判断立刻乱套。Network 7~9 同理（传感器2→M2.1 等）。

### Network 7~9：位置记忆（2~4 号站）

结构同 Network 6：各自"置位本站、复位其余三站"，地址对应 I0.5→M2.1、I0.6→M2.2、I0.7→M2.3。

### Network 10：到位清除呼叫（1 号站；2~4 号站同理）

```
    到位传感器1          呼叫记忆1
  --| |--+----------------| |--+---------(R)--
   (I0.4)|                 (M0.0)|          (M0.0)
```

**分析**：传感器接通**且**该站有呼叫记忆，才清除呼叫。两个条件缺一不可：只看传感器会让"没有呼叫的路过"凭空清掉不存在的东西（无害但逻辑不严谨），只看呼叫记忆则无法知道"车到了没"。正是这个网络同时完成了两件事——**响应呼叫 + 到位停车**（呼叫清零 → 行车条件消失）。Network 11~13 同理。

### Network 11~13：到位清除呼叫（2~4 号站）

```
    到位传感器2          呼叫记忆2         到位传感器3          呼叫记忆3
  --| |--+----------------| |--+----(R)--   --| |--+----------------| |--+----(R)--
                                  (M0.1)                                   (M0.2)

    到位传感器4          呼叫记忆4
  --| |--+----------------| |--+----(R)--
                                  (M0.3)
```

### Network 14：反向判断与反转输出（小编号方向优先的第一优先）

```
     位置记忆4 (M2.3)  呼叫记忆3 (M0.2)
    -------| |----+-------| |-------+
                  |呼叫记忆2 (M0.1) |
                  +-------| |-------+
                  |呼叫记忆1 (M0.0) |
                  +-------| |-------+
     位置记忆3 (M2.2)  呼叫记忆2 (M0.1)  |      反向标志 (M3.0)
    -------| |----+-------| |-------+----+--------( )---
                  |呼叫记忆1 (M0.0) |    |
                  +-------| |-------+    |      小车反转 (Q0.1)
     位置记忆2 (M2.1)  呼叫记忆1 (M0.0)  |    +--------( )---
    -------| |------------| |-------+
```

**分析**：整块逻辑的含义是"目标编号比当前位置小"：

- 在 4 号站：1/2/3 号任一呼叫 → 反转；
- 在 3 号站：1/2 号任一呼叫 → 反转；
- 在 2 号站：1 号呼叫 → 反转；
- 在 1 号站：没有更小的编号，永远不反转。

条件成立时同时驱动 M3.0（反向标志，供 Network 15 互锁用）和 Q0.1（反转输出）。

### Network 15：正向判断与正转输出（受反向优先级压制）

```
     位置记忆1 (M2.0)  呼叫记忆2 (M0.1)
    -------| |----+-------| |-------+
                  |呼叫记忆3 (M0.2) |
                  +-------| |-------+
                  |呼叫记忆4 (M0.3) |
                  +-------| |-------+
     位置记忆2 (M2.1)  呼叫记忆3 (M0.2)  |     反向标志 (M3.0)       小车正转 (Q0.0)
    -------| |----+-------| |-------+--------|/|----------------( )---
                  |呼叫记忆4 (M0.3) |
                  +-------| |-------+
     位置记忆3 (M2.2)  呼叫记忆4 (M0.3)  |
    -------| |------------| |-------+
```

**分析**：整块逻辑的含义是"目标编号比当前位置大"，结构与 Network 14 左右镜像。输出前串了 M3.0 的**常闭触点**——这就是"编号优先"的实现：两侧同时有呼叫时，反向条件先成立并把 M3.0 拉起来，正向输出被压制，小车先去编号小的站；等那边呼叫清零、反向条件消失后，M3.0 断开，正向输出才有机会接通。由于 M3.0 互锁的存在，Q0.0 与 Q0.1 **不可能同时接通**（软件互锁）；实际工程还应在电气上给正反转接触器加机械互锁，双保险。

### 方向判断速查表

| 当前位置记忆 | 有哪些呼叫记忆时正转 | 有哪些呼叫记忆时反转 |
|-------------|--------------------|--------------------|
| 1 号站 | 呼叫2 / 呼叫3 / 呼叫4 | 无（1 号已是最小编号） |
| 2 号站 | 呼叫3 / 呼叫4 | 呼叫1 |
| 3 号站 | 呼叫4 | 呼叫1 / 呼叫2 |
| 4 号站 | 无（4 号已是最大编号） | 呼叫1 / 呼叫2 / 呼叫3 |

## 六、PLCSIM 仿真验证步骤

> **重要说明**：PLCSIM 里没有真小车。所谓"小车行驶"，就是由**人来扮演电机**——行车输出接通后，手动把沿途各站的到位传感器按先后顺序置 1 再置 0，模拟小车经过。输出断开的瞬间，说明逻辑已让小车停车，你就不用再动传感器了。

### ① 需要建立的变量清单

| 变量名称 | 数据类型 | 绝对地址 | 备注 |
|---------|---------|---------|------|
| 呼叫按钮1~4 | Bool | I0.0~I0.3 | 点动模拟 |
| 到位传感器1~4 | Bool | I0.4~I0.7 | 手动置 1/置 0 模拟小车位置 |
| 小车正转 | Bool | Q0.0 | 观察 |
| 小车反转 | Bool | Q0.1 | 观察 |
| 呼叫记忆1~4 | Bool | M0.0~M0.3 | 观察 |

## 七、设计难点与解决方法

### 难点 1：呼叫记忆与清除——"记下来容易，忘掉要挑对时机"

**难在哪**：按钮是点动信号；而小车从出发到到达可能要几十秒。如果不用 (S) 锁存，呼叫瞬间就丢了。反过来，清除时机也不能太早——如果小车"一出发就清呼叫"，途中遇到干扰断电重启，小车就不知道该去哪了；也不能太晚——到了站不清，小车会在终点和下一站之间来回鬼打墙。

**解决**：把清除条件精确写成"**目标站的传感器接通 × 该站呼叫记忆仍为 1**"。传感器接通 = 人到了；呼叫记忆 = 这一站正是要去的地方。两者同时成立才清除，天然排除了"路过无呼叫的站"和"没有呼叫的停留"。

### 难点 2：同站呼叫——"人已经在站里了，还喊什么车"

**难在哪**：小车正停在 2 号站，操作工手滑按下 2 号呼叫。呼叫记忆被置位，可小车"到达 2 号站"这个事件永远不会再来（它就在那儿），这个呼叫永远清不掉，程序里留下一颗定时炸弹。

**解决**：到位清除网络用的是**电平条件**（传感器 AND 呼叫记忆），不是"到达瞬间"的边沿条件。小车停在 2 号站期间传感器2 一直接通，所以本站呼叫在置位后的下一个扫描周期内就被自动清除——不响车、不留尾巴。扫描顺序上把"呼叫锁存"放在"到位清除"之前，保证清除必然发生在置位之后。

### 难点 3：运行途中收到新呼叫——"接不接？什么时候接？"

**难在哪**：小车正从 1 号站开往 4 号站，半路 2 号站呼叫了。如果直接改目标，小车要中途折返，工艺上乱；如果不理，呼叫又不能丢。

**解决（本案例的做法）**：新呼叫照常锁存。由于方向判断是"实时比较位置与所有呼叫"，小车路过 2 号站时传感器自动触发到位清除，顺路完成停靠；随后继续前往 4 号站。一句话：**先完成当前方向上的所有呼叫，方向条件自然消失后再去处理另一侧**——这正是编号优先方案的配套行为。

**教学程序的一个诚实声明**：如果新呼叫出现在"当前位置的反方向且优先级更高"（反向优先），小车可能在两站之间、位置记忆未更新时就中途换向。实际工程会引入"目标锁定"：出发时把目标站号存入专用寄存器，到达前不响应改向，只有到达站点后才重新选目标。这属于进阶改进，本案例不展开。

### 难点 4：位置记忆的初始化——"上电时小车在哪，PLC 并不知道"

**解决**：启用系统存储器位，用 FirstScan（首次扫描）在第一个周期把"位置 1"写入位置记忆。工程前提是**操作规程规定小车停在第 1 站后再上电**（或加装原点开关做回原点动作，属于进阶内容）。

### 难点 5：正反转互锁——"方向可以选错，绝不能同时选"

**解决**：软件上用反向标志 M3.0 的常闭触点压制正向输出，保证一个扫描周期内两个方向条件不可能同时成立；硬件上要求正、反转接触器互相机械互锁。软件 + 硬件双保险，才能避免相间短路的恶性事故。

## 📌 本章小结

1. 有轨小车的控制核心是三组状态：**呼叫记忆**（去哪）、**位置记忆**（在哪）、**方向标志**（往哪边优先）。
2. 程序框架四大模块：呼叫锁存 → 位置记忆 → 到位清除（停车）→ 方向判断与行车输出，扫描顺序影响逻辑正确性。
3. 到位停车不需要专门的"停车网络"：呼叫清除后行车条件自然消失，输出断电即停车——让逻辑自己"算"出停车点。
4. 多目标优先级选定"编号优先（小编号方向优先）"：实现简单、行为确定，用 M3.0 常闭触点完成正反转软件互锁。
5. 同站呼叫靠"电平式"到位清除自动消化；运行中新呼叫靠锁存 + 顺路停靠消化；初始位置靠 FirstScan 写入。
6. PLCSIM 仿真这类"运动对象"的诀窍：人扮演电机，按行程顺序手动翻转各站传感器。

## ⚠️ 常见错误与注意事项

1. **呼叫不锁存**：用普通线圈 --( )-- 代替 (S)，按钮一松呼叫丢失，小车永远不出发。点动信号必须 (S) 锁存、到位 (R) 清除。
2. **到位后呼叫不清除**：小车到达目标站后呼叫记忆仍是 1，下一次扫描又满足行车条件，小车在两站间来回振荡。牢记"到达即清除"。
3. **位置记忆忘记互斥**：只写 (S) 本站、漏写 (R) 其余三站，出现两个位置记忆同时为 1，方向判断精神分裂。四个 (S)/(R) 支路一个都不能少。
4. **上电不初始化位置**：位置记忆全 0 时任何方向条件都不成立（或反向条件误成立），小车装死或乱跑。FirstScan 初始化不能省。
5. **正反转没有互锁**：漏写 M3.0 常闭触点，两侧同时呼叫时 Q0.0、Q0.1 同时接通——真设备上就是相间短路跳闸。软件互锁 + 硬件互锁缺一不可。
6. **同站呼叫没有处理**：清除条件写成"只有到达时才清"，导致本站呼叫永久残留。用"传感器 × 呼叫记忆"的电平清除即可自动覆盖同站情形。
7. **扫描顺序摆放错误**：把方向判断放在位置记忆之前，方向判断用的是上一周期的旧位置，临界情况下少停一站或多跑一站。按"锁存→记忆→清除→判断"的顺序组织网络。
8. **PLCSIM 操作失误当成程序错误**：传感器置 1 后忘记置 0、呼叫按钮还没生效就急着翻传感器、没开监控表就下结论。先核对输入状态，再排查逻辑。
9. **系统存储器位没启用**：程序里写了 FirstScan（%M1.0），但 CPU 属性没勾选启用，初始化永远不执行。下载前检查 CPU 属性。
10. **过度追求"完美小车"**：本教学程序不含加减速、定位微动、防冲过头等功能，这些需要编码器/变频器配合。先掌握状态记忆的思想，再逐步逼近工程实现。

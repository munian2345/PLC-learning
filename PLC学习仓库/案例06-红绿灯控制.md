# 案例06 十字路口红绿灯控制

## 📖 学习目标

1. 理解十字路口两组信号灯"此亮彼灭"的时序配合关系，学会把一个长循环拆解成若干相位。
2. 掌握"定时器链式控制"的实现方法：四个 TON 接力计时 + 末级复位形成无限循环。
3. 了解"总时间比较法"的思路，能对比两种方案的优劣并做出合理的工程选型。
4. 能独立编写并仿真验证红绿灯程序，掌握"缩短时间常数快速调试"的实用技巧。
5. 了解行人过街按钮的扩展思路：请求锁存 + 最短绿灯 + 提前切换。

---

## 一、控制要求与路口模型

### 1.1 路口模型

十字路口有两组信号灯，分别管控两个方向的车流：

```
                 ▲  北
                 │
        ┌────────┼────────┐
        │  南北  │  南北  │      南北方向：管控南北向车流
──西────┤ 红黄绿 ├ 红黄绿 ├────东──   东西方向：管控东西向车流
        │  东西  │  东西  │
        └────────┼────────┘
                 │
                 ▼  南

  南北方向车流（开车上下穿过路口）与东西方向车流（左右穿过路口）
  绝对不允许同时放行——这就是红绿灯控制的第一原则。
```

### 1.2 控制要求

1. 按下启动按钮后系统循环运行；按停止按钮后所有灯熄灭。
2. **南北方向**：绿灯亮 **30 秒** → 黄灯亮 **3 秒** → 红灯亮 **33 秒**，之后回到绿灯，周而复始。
3. **东西方向**：红灯亮 → 绿灯亮 30 秒 → 黄灯亮 3 秒，之后回到红灯，周而复始。
4. 一个完整循环为 **66 秒**（30 + 3 + 33）。
5. 任意时刻，两个方向**不允许同时出现"放行信号"**（绿或黄），即一组亮绿/黄时，另一组必须亮红。

### 1.3 时序说明：东西红灯为什么必须是 33 秒

细心的同学会发现：东西方向"红 30 + 绿 30 + 黄 3"只有 63 秒，和 66 秒对不上。这不是笔误可以掩盖的小事，而是**安全要求**决定的：

- 南北方向"能通行"的时段 = 绿 30 秒 + 黄 3 秒 = **33 秒**；
- 南北车流通行的整段时间里，东西方向**必须一直是红灯**；
- 所以东西红灯的时长 = 30 + 3 = **33 秒**，而不是 30 秒。

如果东西红灯只亮 30 秒，那么第 30~33 秒（南北黄灯期）东西已经变绿——南北正在清空路口，东西已经放行，3 秒的冲突空档足以酿成事故。记住这个换算方法：**一组灯的红灯时长 = 另一组灯的绿灯 + 黄灯**。这也是很多教材把本案例写成"东西红 30s"时需要修正的地方，本程序按安全的 33 秒实现，循环恰好 66 秒。

## 二、时序图

### 2.1 文字描述

上电启动后，从"南北绿 + 东西红"开始，按下面四拍循环：

1. **第 1 拍（0~30s）**：南北绿灯亮，东西红灯亮——南北车流通行，东西等待；
2. **第 2 拍（30~33s）**：南北黄灯亮，东西红灯仍亮——南北警示清空路口，东西继续等；
3. **第 3 拍（33~63s）**：南北红灯亮，东西绿灯亮——交换放行权，东西通行；
4. **第 4 拍（63~66s）**：南北红灯仍亮，东西黄灯亮——东西清空路口，随后回到第 1 拍。

### 2.2 ASCII 时序图（两组灯画在同一时间轴上）

每个字符代表 3 秒，# = 灯亮，. = 灯灭：

```
              0s        30s 33s               63s 66s
              |         |   |                |   |
南北绿灯      ##########....................
南北黄灯      ..........#...................
南北红灯      ...........###########........
东西红灯      ###########...................
东西绿灯      ...........##########.........
东西黄灯      .....................#........

对齐解读：
  0~30s   ：南北绿 # ｜ 东西红 #        → 南北放行 30s
  30~33s  ：南北黄 # ｜ 东西红 #        → 南北清空 3s
  33~63s  ：南北红 # ｜ 东西绿 #        → 东西放行 30s
  63~66s  ：南北红 # ｜ 东西黄 #        → 东西清空 3s
```

**检查规律**：任何一列（即任何一个时刻）上，绿/黄与另一侧的红总是"一一对映"，两组的绿、黄从不同时出现——满足安全第一原则。

### 2.3 相位划分表

| 相位 | 时间段 | 时长 | 南北 | 东西 | "当班"定时器 |
|------|--------|------|------|------|--------------|
| 1 | 0~30s | 30s | 绿灯 | 红灯 | TON_南北绿 计时中（Q=0） |
| 2 | 30~33s | 3s | 黄灯 | 红灯 | TON_南北黄 计时中 |
| 3 | 33~63s | 30s | 红灯 | 绿灯 | TON_东西绿 计时中 |
| 4 | 63~66s | 3s | 红灯 | 黄灯 | TON_东西黄 计时中，计满触发全链复位 |

## 四、实现思路：两种方案对比与选型

### 4.1 方案A：定时器链式控制

四个 TON 像**接力赛**一样首尾相连：TON_南北绿 计满 → 拉起 TON_南北黄 → 计满 → 拉起 TON_东西绿 → 计满 → 拉起 TON_东西黄；东西黄计满时，用一个"NOT 东西黄.Q"的常闭触点把链条源头（TON_南北绿 的 IN）掐断——整条链瞬间复位，下一扫描周期从头再跑。**灯的亮灭由"哪几个定时器 Q 处于什么状态"组合出来。**

### 4.2 方案B：总时间比较法

只用**一个**自复位循环定时器：TON_循环 的 IN = 系统运行 AND NOT 自身 Q，PT = T#66s。每到 66 秒，Q 闪一下把自身复位，ET 从头再数。然后拿 ET 和时间常数做**比较指令**划分相位：

- 南北绿 = ET < T#30s
- 南北黄 = ET ≥ T#30s 且 ET < T#33s
- 南北红 = ET ≥ T#33s
- 东西红 = ET < T#33s
- 东西绿 = ET ≥ T#33s 且 ET < T#63s
- 东西黄 = ET ≥ T#63s

自复位循环定时器的接法示意：

```
    系统运行        TON_循环.Q           TON_循环
  --| |--+-----------|/|----------------+------------+
   (M0.0)|           (自复位)            | TON        |
         |                               | IEC_TIMER  |
         |                               +------------+
         |                               | IN      Q  |
         |                       T#66s --| PT      ET |----→ ET 供比较指令使用
         |                               +------------+
```

比较指令划分相位的示意（以东西绿灯为例，需两个比较串联）：

```
    TON_循环.ET          +-----------+
  --| |--+---------------|  CMP >=   |
         |        T#33s--|           |----+   +-----------+
         |               +-----------+    +---|  CMP <    |
         |                         T#63s--|   |           |----( )-- 东西绿灯 Q0.4
         |                               +---+-----------+
```

### 4.3 两种方案对比与选型

| 对比项 | 方案A 定时器链式 | 方案B 总时间比较法 |
|--------|----------------|-------------------|
| 定时器数量 | 4 个 TON | 1 个 TON + 多组 CMP 比较 |
| 相位可读性 | 每相位一个"当班"定时器，监控 Q 即知走到哪一拍 | 要盯着 ET 数值在脑内画时间轴 |
| 修改时序 | 直接改对应 TON 的 PT | 改比较常数，相位多时容易改漏、改错边界 |
| 新增相位 | 在链尾再接一棒 | 增加比较区间，边界条件易冲突 |
| 边界风险 | 定时器到点即切换，边界天然清晰 | 比较用 ≥ 还是 > 、区间开闭，容易出 1 秒重叠或空档 |
| 适用场合 | 相位少、循环固定的时序控制 | 相位多、时间参数需从 HMI 在线调整 |

**选型结论**：本案例只有 4 个相位、时序固定，**选用方案A（定时器链式）**详细实现——逻辑直观、调试方便，也最能巩固上一章学过的 TON 接力技巧。方案B 在相位很多或需要 HMI 修改时间时更有优势，作为思路储备。

### 4.4 方案A 的链式设计细节

1. **接力**：后一个 TON 的 IN 接前一个 TON 的 Q，计时逐棒传递：30s → 3s → 30s → 3s，总长 66s。
2. **复位**：TON_东西黄.Q 出现的瞬间（66s 处），用它的常闭触点切断 TON_南北绿 的 IN，链条在一两个扫描周期内全部复位、重新开始——这就是"无限循环"的诀窍。
3. **灯的条件**：用 4 个 Q 的" 0/1 组合"表达相位，例如"南北黄 = 南北绿.Q=1 且 南北黄.Q=0"，见第五章逐网络分析。
4. **启停**：系统运行标志 M0.0 串在链条源头，停止时整条链失电复位，所有灯灭；再次启动时从相位1（南北绿）重新开始，不会从半截相位恢复。

## 五、梯形图逻辑分析（逐网络）

### Network 1：启动——置位系统运行标志

```
    启动按钮             系统运行标志
  --| |--+-----------------(S)--
   (I0.0)|                 (M0.0)
```

**分析**：点动按下启动按钮，M0.0 置位并保持，作为整条定时器链和所有灯的总电源开关。

### Network 2：停止——复位系统运行标志

```
    停止按钮             系统运行标志
  --| |--+-----------------(R)--
   (I0.1)|                 (M0.0)
```

**分析**：按下停止，M0.0 复位。链条源头失电 → 四个 TON 依次复位 → 六个灯的输出条件全部不成立，全路口灯灭（实际工程中停止往往切换为"全红"或"黄闪"模式，本教学程序从简，见常见错误第 9 条的讨论）。

### Network 3：相位1 计时——南北绿灯 30 秒（链条源头）

```
    系统运行标志    TON_东西黄.Q          TON_南北绿
  --| |--+-----------|/|-----------------+---------------+
   (M0.0)|           (循环复位)            | TON           |
         |                                | IEC_TIMER     |
         |                                +---------------+
         |                                | IN         Q  |----→ 拉起下一棒、参与灯条件
         |                         T#30s--| PT         ET |
         |                                +---------------+
```

**分析**：系统运行且"东西黄尚未计满"时，计时 30 秒。串联 TON_东西黄.Q 的**常闭触点**是循环的关键：66 秒那一拍东西黄计满、Q=1，本触点断开 → 源头 IN=0 → 整条链自动复位，下个周期重新开始。这就是"定时器链"自我循环的全部秘密。

### Network 4：相位2 计时——南北黄灯 3 秒（第二棒）

```
   TON_南北绿.Q                          TON_南北黄
  --| |--+-------------------------------+---------------+
         |                               | TON           |
         |                               | IEC_TIMER     |
         |                               +---------------+
         |                               | IN         Q  |----→ 拉起下一棒、参与灯条件
         |                         T#3s--| PT         ET |
         |                               +---------------+
```

**分析**：南北绿计时到（30s 处），第二棒开始计时 3 秒。Q=1 的时段正好对应"南北黄灯"。

### Network 5：相位3 计时——东西绿灯 30 秒（第三棒）

```
   TON_南北黄.Q                          TON_东西绿
  --| |--+-------------------------------+---------------+
         |                               | TON           |
         |                               | IEC_TIMER     |
         |                               +---------------+
         |                               | IN         Q  |----→ 拉起下一棒、参与灯条件
         |                        T#30s--| PT         ET |
         |                               +---------------+
```

**分析**：南北黄结束（33s 处），东西绿开始计时 30 秒。

### Network 6：相位4 计时——东西黄灯 3 秒（第四棒）

```
   TON_东西绿.Q                          TON_东西黄
  --| |--+-------------------------------+---------------+
         |                               | TON           |
         |                               | IEC_TIMER     |
         |                               +---------------+
         |                               | IN         Q  |----→ 计满触发 Network 3 复位
         |                         T#3s--| PT         ET |
         |                               +---------------+
```

**分析**：东西绿结束（63s 处），东西黄计时 3 秒；66s 处 Q=1，回送 Network 3 的常闭触点，完成一个循环的闭环。

### Network 7：南北绿灯输出

```
    系统运行标志 (M0.0)  TON_南北绿.Q       南北绿灯 (Q0.0)
  --------| |----------------|/|----------------( )---
```

**分析**：南北绿灯 = 系统运行 且 TON_南北绿 还没计满（0~30s）。到 30s 时 Q 变 1，常闭断开，绿灯熄灭，交棒给黄灯。

### Network 8：南北黄灯输出

```
    TON_南北绿.Q         TON_南北黄.Q       南北黄灯 (Q0.1)
  --------| |----------------|/|----------------( )---
```

**分析**：南北黄灯 = 南北绿已计满、南北黄还没计满（30~33s）。用"前一棒 Q=1 串后一棒 Q=0"这种**相邻比较**的写法，可以精确切出相位时段，是链式程序的通用技巧。

### Network 9：南北红灯输出

```
    TON_南北黄.Q                            南北红灯 (Q0.2)
  --------| |-----------------------------------( )---
```

**分析**：南北红灯 = TON_南北黄 已计满（33s 起）。此后南北黄.Q 一直保持 1 直到 66s 链条复位，所以红灯正好亮 33 秒（33~66s），覆盖东西的绿灯和黄灯两拍。**一个触点就写完 33 秒红灯**，这正是链式设计顺手的地方。

### Network 10：东西红灯输出

```
    系统运行标志 (M0.0)  TON_南北黄.Q       东西红灯 (Q0.3)
  --------| |----------------|/|----------------( )---
```

**分析**：东西红灯 = 系统运行 且 南北黄尚未计满（0~33s），正好覆盖"南北绿 30s + 南北黄 3s"，实现 1.3 节推导的安全时序。

### Network 11：东西绿灯输出

```
    TON_南北黄.Q         TON_东西绿.Q       东西绿灯 (Q0.4)
  --------| |----------------|/|----------------( )---
```

**分析**：东西绿灯 = 南北黄已计满、东西绿未计满（33~63s）。

### Network 12：东西黄灯输出

```
    TON_东西绿.Q                            东西黄灯 (Q0.5)
  --------| |-----------------------------------( )---
```

**分析**：东西黄灯 = 东西绿已计满（63~66s）。计满后触发链条复位，Q 归零，黄灯自动熄灭，回到相位1。

> **关于周期交界处的"一眨眼"**：链条复位发生在 66s 处的一两个扫描周期内（毫秒级），期间可能出现瞬间"南北绿闪一下"的现象。由于一个扫描周期通常只有几毫秒，肉眼完全不可见，教学程序无需处理；追求严谨的工程可增加"全红过渡相位"。

| 灯 | 输出条件 | 亮的时间段 |
|----|---------|-----------|

| 南北黄 Q0.1 | TON_南北绿.Q=1 且 TON_南北黄.Q=0 | 30~33s |
| 南北红 Q0.2 | TON_南北黄.Q=1 | 33~66s |

| 东西绿 Q0.4 | TON_南北黄.Q=1 且 TON_东西绿.Q=0 | 33~63s |
| 东西黄 Q0.5 | TON_东西绿.Q=1 | 63~66s |

### ② 启动仿真并下载程序

1. 全部编译，确认 0 错误。
2. 选中 PLC_1 → 点击"开始仿真" → 在 PLCSIM 中创建对应 CPU 站点。
3. 点击"下载到设备"，完成装载，CPU 切到 **RUN**。

### ③ 用监控表模拟输入信号

1. 建立监控表并开启监视；六个灯建议集中排列，方便对照。
2. 启动：I0.0 置 1 再置 0（点动）；停止：I0.1 置 1 再置 0。
3. **强烈推荐的调试技巧**：66 秒一个循环，等一次太久。先把四个 PT 临时改成等比例缩短的"10 倍速"调试版——T#3s / T#300ms / T#3s / T#300ms（循环 6.6 秒），验证相位顺序正确后再改回 T#30s / T#3s / T#30s / T#3s 重新下载做最终确认。
4. 扩展功能验证时，用 I0.2 模拟行人按钮点动。

### ④ 预期结果（以正式时序为例）

1. 初始：六个灯全灭，四个 TON 的 ET = T#0ms。
2. 点动启动按钮：**南北绿灯与东西红灯立即点亮**，TON_南北绿 的 ET 从 0 开始上涨。
3. **30 秒**：南北绿灭、南北黄亮（东西红保持）；TON_南北黄 的 ET 开始计时。
4. **33 秒**：南北黄灭、南北红亮；同时东西红灭、**东西绿亮**（交换放行权）；TON_东西绿 的 ET 开始计时。
5. **63 秒**：东西绿灭、东西黄亮（南北红保持）。
6. **66 秒**：东西黄灭，链条复位——回到"南北绿 + 东西红"，开始下一个循环。以后每 66 秒重复一遍。
7. 任意时刻点动停止按钮：六个灯全部熄灭、ET 全部归零；再次启动，从"南北绿 + 东西红"重新开始（不会从半截相位恢复）。
8. 扩展功能：南北绿期间按下 I0.2 → M1.0=1；最迟 20 秒后南北绿提前熄灭转入黄灯（例如第 5 秒按下，则第 25 秒切换）；相位切换后 M1.0 自动清零。

### ⑥ 结果不符时的排查方法

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 只跑一个循环就停 | Network 3 漏串 TON_东西黄.Q 的常闭复位触点 | 检查链条源头 IN 是否含 --|/|-- 自复位条件 |
| 相位顺序错乱 | 四个 TON 的接力关系接错（IN 没接上一棒的 Q） | 对照 4.4 节接力表逐个核对 IN 来源 |
| 某方向绿灯和对面绿灯/黄灯同亮 | 灯条件写错（如南北红写成 TON_南北绿.Q） | 对照第五章"灯条件对照总表"逐条检查 |
| 黄灯时长不对或没有黄灯 | T#3s 写错，或黄灯条件漏了"前一棒 Q"或"本棒 Q 取反" | 监控两个相关 TON 的 Q 翻转时刻 |
| 停止后再启动从半截相位开始 | 停止只灭了灯、没有让 M0.0 切断链条源头 | 确认 Network 3 的 IN 里串有 M0.0 |
| 六个灯全不亮 | M0.0 没置位（启动按钮网络问题）或 CPU 在 STOP | 监控 M0.0；确认 RUN 状态与下载成功 |
| 改了 PT 现象没变 | 修改后未重新编译下载 | 重新下载并确认版本一致 |
| 周期交界处灯"乱闪一帧" | 链条复位用了一两个扫描周期，属正常毫秒级现象 | 监控表高刷新率下才能看到，可忽略；工程上可加全红过渡 |
| 行人按钮无效果 | M1.0 未置位或 TON_行人 的 IN 条件写错 | 监控 M1.0 与 TON_行人.ET；确认只在南北绿期间计时 |

## 七、扩展：加入行人过街按钮

### 7.1 需求分析

路口南北侧装有行人过街按钮：行人要过马路时按一下，系统记住请求，**南北向车流的绿灯提前结束**（但保证最短绿灯时间 20 秒），尽快转入"南北红 / 东西绿"相位，让行人利用南北车流停止的间隙通过。设计要点有三条：

1. **请求要锁存**：按钮是点动的，用 (S) 把请求存进 M1.0；
2. **最短绿灯保护**：不是按了立刻切——用 TON_行人 计时 20 秒，保证南北绿至少亮 20 秒（这也是行人走过马路的最短时间）；
3. **请求用后即清**：相位切换（南北绿结束）时把请求复位，避免残留到下个循环造成误动作。

### 7.2 修改与新增的网络

> [!IMPORTANT]
> **常见误区警示**：初学者常试图在 Network 3 的 `TON_南北绿` 的 IN 端串联 `NOT TON_行人.Q` 常闭触点来"掐断"绿灯。但西门子 IEC 定时器（TON）的运行规则是：**一旦 IN 变为 0，ET 立即清零，Q 强制归 0！** 掐断 `TON_南北绿` 后它的 Q 永远不会变 1，导致下一棒 `TON_南北黄` 无法启动，且绿灯还会因为 `NOT Q` 再次点亮，系统直接卡死。
> 
> **正确的工程思路**：定义一个**"南北绿完成标志（M1.1）"**，将"正常计满 30s（TON_南北绿.Q）"与"行人请求满 20s（TON_行人.Q）"做并联（或运算）。只要任一条件满足，就拉起 M1.1，从而启动黄灯并关熄绿灯。

```
Network 13（新增）：锁存行人请求
    行人按钮 (I0.2)       行人请求 (M1.0)
  --------| |-------------------(S)---

Network 14（新增）：行人延时——南北绿期间收到请求，计时 20 秒
    行人请求 (M1.0)     TON_南北黄.Q          TON_行人
  --------| |----------------|/|--------------+---------------+
                      (南北黄启动即停止计时)   | TON           |
                                              | IEC_TIMER     |
                                              +---------------+
                                              | IN         Q  |----→ 行人提前切换信号
                                      T#20s --| PT         ET |
                                              +---------------+

Network 14b（新增）：南北绿完成标志（正常计满 30s 或 行人到点 20s）
    TON_南北绿.Q                              南北绿完成 (M1.1)
  --------| |--------------------+-------------( )---
    TON_行人.Q                   |
  --------| |--------------------+

Network 4（修改）：南北黄启动输入改为"南北绿完成"
   南北绿完成 (M1.1)                     TON_南北黄
  --------| |-----------------------------+---------------+
                                          | TON           |
                                          | IEC_TIMER     |
                                          +---------------+
                                          | IN         Q  |----→ 拉起下一棒
                                   T#3s --| PT         ET |
                                          +---------------+

Network 7（修改）：南北绿灯输出改受"南北绿完成"控制
    系统运行标志 (M0.0)  南北绿完成 (M1.1)  南北绿灯 (Q0.0)
  --------| |----------------|/|----------------( )---

Network 8（修改）：南北黄灯输出改受"南北绿完成"控制
   南北绿完成 (M1.1)    TON_南北黄.Q       南北黄灯 (Q0.1)
  --------| |----------------|/|----------------( )---

Network 15（新增）：南北黄结束后复位行人请求
   TON_南北黄.Q          行人请求 (M1.0)
  --------| |-------------------(R)---
```

### 7.3 动作推演

1. 南北绿进行到第 5 秒，行人按下按钮 → M1.0=1，TON_行人 开始计时；
2. 第 25 秒（5 + 20）TON_行人.Q=1 → Network 14b 将 M1.1（南北绿完成）拉起；
3. Network 7 中 M1.1 常闭断开，南北绿灯提前熄灭；Network 4 中 M1.1 接通，TON_南北黄 开始计时 3 秒，南北黄灯点亮；
4. 3 秒后（第 28 秒）TON_南北黄.Q=1，南北黄灯灭、南北红灯亮，东西绿灯亮放行；Network 15 把行人请求 M1.0 复位，TON_行人 清零；
5. 如果行人按钮按得太晚（南北绿剩余不足 20 秒，如第 25 秒按），TON_行人 尚未计满，TON_南北绿 在第 30 秒先到点，TON_南北绿.Q 同样驱动 M1.1 变 1，时序平稳过渡到黄灯；
6. 请求在南北黄、南北红期间按下时，TON_行人 的 IN 条件被 TON_南北黄.Q 阻断，系统在南北黄结束时一并复位，不会对后续时序产生干扰。

> **工程提示**：真实路口的行人方案还要考虑行人信号灯（红/绿人形）、行人绿闪、机动车最短绿灯与全红清空时间等，属于"相位 + 请求"的进阶组合。本扩展的目的是让大家掌握"**请求锁存 + 最短时间保护 + 到点切换**"这一通用套路。

## 📌 本章小结

1. 红绿灯的本质是**多相位循环时序**：把 66 秒拆成 4 拍，每拍一组灯色组合，安全原则是"一侧放行（含黄灯清空）时另一侧必须红灯"，因此一侧红灯时长 = 另一侧绿 + 黄（33 秒）。
2. 方案A 定时器链式：四个 TON 接力（30s→3s→30s→3s），末级 Q 的常闭触点回送链条源头实现自动循环；灯条件用"前一棒 Q 串 后一棒 Q 取反"精确切相位。
3. 方案B 总时间比较法：一个自复位 TON + ET 与时间常数的 CMP 比较，适合相位多、参数在线可调的场合；边界（≥ 还是 >）要格外小心。
4. 相位少、时序固定选 A；本案例用 A 实现，六个灯各由一行触点逻辑驱动，条理清晰。
5. 行人过街扩展 = 请求锁存 (S) + 最短绿灯 TON + 相位切换清请求 (R)，"锁存—保护—清除"三步是各类"按钮请求"问题的通用解法。
6. 调试长循环程序的技巧：等比例缩短 PT（10 倍速）快速验证顺序，确认后再恢复正式时间。

## ⚠️ 常见错误与注意事项

1. **东西红灯时长写错成 30 秒**：导致 30~33 秒出现"南北黄灯未清空、东西已放行"的冲突空档，或 63~66 秒两组全灭。记住换算：红灯 = 对方绿灯 + 对方黄灯。
2. **链条没有复位条件**：Network 3 漏串 TON_东西黄.Q 常闭触点，程序只跑一个循环就永远停在"东西黄"状态。自复位触点是循环类程序的命根子。
3. **灯条件边界写错**：比如南北黄写成"TON_南北黄.Q=1"（那会亮 63 秒直到复位），必须用"前一棒 Q=1 且 本棒 Q=0"的相邻比较写法。写完对照时序图逐列检查。
4. **两组灯同时放行**：灯条件与相位表对不上（如南北红错接 TON_东西绿.Q），出现两侧同绿。这是安全级错误，仿真时必须逐拍核对六个灯。
5. **停止后再启动不从相位1 开始**：停止按钮只复位了灯而没让 M0.0 切断链条，定时器停在半截相位。M0.0 必须串在链条源头（Network 3 的 IN）。
6. **同一输出双线圈**：某个灯在两个网络都用普通线圈，后者覆盖前者。六个灯每个只允许出现一次线圈。
7. **比较法方案的边界隐患**：使用方案B 时，"ET ≥ T#30s 且 ET < T#33s"这类区间如果开闭方向写反，会出现 1 秒的两灯同亮或同灭；改时间参数时所有比较常数要同步改。
8. **行人扩展切勿直接掐断 TON_南北绿 的 IN**：TON 的 IN 断开会导致当前计时与 Q 瞬间清零，后一棒黄灯根本无法启动，系统直接卡死；必须使用"或逻辑"（M1.1）合成提前完成标志。另外 TON_行人 的 20 秒最短绿灯保护不能省，否则请求一到就切黄灯，南北向机动车猝不及防。
9. **教学简化与现实差距**：本程序停止后六灯全灭，真实路口停止/故障时应切换"全红"或"黄闪"模式并报警；周期交界处毫秒级的复位闪动在真实工程中也会用全红过渡吸收。学完本案例应意识到"教学逻辑 → 工程逻辑"还差安全模式这一层。
10. **验证不充分**：只看了一两个相位就下结论。长循环程序至少完整盯守一个循环（10 倍速 6.6 秒即可），并用监控表的 ET 值核对每一拍时长。

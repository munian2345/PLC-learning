## 一、项目背景与需求分析

### 1.1 系统功能描述

某电商仓库的入库工段：货车把货物卸到入库口，操作工按下启动按钮后，传送带把货物送入库区；货物经过分拣位时，系统根据货位占用情况自动把货物推入对应货架（本项目用一个分拣气缸模拟"推入"动作）；每完成一件入库，系统自动累加库存；库存接近上限时预警，达到上限时停止入库并报警；气缸动作超时、仓库高温等异常会触发报警；一切状态都在 KTP700 触摸屏上实时可见，并可通过屏幕完成启停、出库登记、消音、复位等操作。

### 1.2 控制要求详述

1. **启动/停止**：按下启动按钮（I0.0），运行指示灯（Q0.4）亮，传送带电机（Q0.0）运行；按下停止按钮（I0.1），传送带不立即停，延时 5 秒停止（让带上的货物走完）；急停按钮（I0.2，常闭接线）随时立即停止一切输出。
2. **货物检测**：入库口光电传感器（I0.3）每检测到一件货物接通一次，用于来料确认。
3. **分拣动作**：货物到达分拣位（I0.4 接通）后，先延时 0.5 秒对位，随后分拣气缸（Q0.5）伸出，伸出到位（I0.5）后保压 1 秒，然后缩回，缩回到位（I0.6）算一次分拣完成；气缸伸出后 3 秒仍未到位，判定设备故障并报警。
4. **库存计数**：每完成一次分拣，入库数加 1；操作工在 HMI 上每按一次"出库登记"，出库数加 1；当前库存 = 入库数 − 出库数（不小于 0），显示在 HMI 上。
5. **库存预警与库满**：库存达到预警值（90）时 HMI 弹出预警提示；达到上限（100）时触发库满报警：报警灯（Q0.2）闪烁、蜂鸣器（Q0.3）鸣响、传送带禁止再启动；库存降回上限以下 10 件（回差）后报警自动解除。
6. **设备故障**：气缸超时故障触发后锁定，报警灯闪、蜂鸣器响；需在 HMI 上按"报警复位"才能解除。
7. **高温报警**：仓库温度（模拟量 IW64 换算为 0~60°C，存 MD40）超过设定值 MW20（默认 45）时高温报警提示（不锁定，温度回落后自动恢复）。
8. **报警输出**：任一报警存在 → 报警灯 Q0.2 以 1Hz 闪烁；库满/设备故障/急停存在 → 蜂鸣器 Q0.3 长鸣；HMI 上按"消音"可临时关闭蜂鸣器（报警灯不受影响）。
9. **HMI 监控与操作**：画面显示传送带/气缸/报警状态指示灯、当前库存/入库数/出库数/占用率棒图、库存趋势曲线、报警列表；提供启动/停止/出库登记/消音/报警复位/清零按钮。
10. **上电初始化**：CPU 启动时（OB100）自动清报警、初始化设定参数、清输出，库存累计数据保留。

## 三、程序架构设计

### 3.1 OB / FC / FB / DB 的分工与结构图

```
OB100 (启动OB，LAD)：上电初始化
 |   - 清全部报警位、清输出(QB0=0)、载入 DB_设定参数 默认值
 v
OB1 (主循环，LAD)：每个扫描周期按固定顺序调用
 |
 |  [1] FB_电机控制   --> 背景DB「传送带电机」：启停、延时停止、急停保护
 |  [2] FB_分拣控制   --> 背景DB「分拣控制」  ：对位-伸出-保压-缩回 步序
 |  [3] 计数网络      --> 单实例DB「CTU_入库计数」「CTU_出库计数」
 |                     SUB 计算当前库存，结果写 DB_库存数据
 |  [4] FC_报警处理   (LAD)：报警判定/锁定/解除、报警灯与蜂鸣器输出
 |  [5] FC_HMI数据    (SCL)：库存钳位、占用率、温度换算、MW30/MD40 同步
 |
 v
全局DB：DB_库存数据、DB_报警状态、DB_设定参数
HMI(KTP700) <--PROFINET--> CPU：读写 M 区按钮 + DB 数据
```

### 3.2 各功能模块说明

| 块名 | 类型 | 职责 | 关键变量/资源 |
|---|---|---|---|
| OB1 | 组织块 | 主循环，按顺序调度全部模块 | —— |
| OB100 | 组织块 | 上电初始化：清报警、清输出、载默认参数 | M1.0 首次扫描 |
| FB_电机控制 | FB | 传送带启保停、延时 5s 停止、急停立即停、库满禁止启动 | 静态：停止延时标志、TON_延时停止（多重实例型 IEC_TIMER） |
| FB_分拣控制 | FB | 分拣四步时序（对位/伸出/保压/缩回）、气缸超时故障 | 静态：步1~步4 标志、TON_对位/TON_保压/TON_气缸超时 |
| CTU_入库计数 | CTU 单实例 DB | 每次分拣完成 +1 | CU=分拣完成脉冲，CV→当前入库数 |
| CTU_出库计数 | CTU 单实例 DB | 每次 HMI 出库登记 +1 | CU=M1.3 边沿，CV→当前出库数 |
| FC_报警处理 | FC | 五类报警的判定/锁定/解除，驱动 Q0.2/Q0.3 | 读 DB_库存数据、DB_报警状态 |
| FC_HMI数据 | FC(SCL) | 库存钳位与占用率计算、温度换算、MW30/MD40 同步 | 写 DB_库存数据、MW30、MD40 |

架构要点：**有记忆的逻辑放 FB**（步序标志、定时器实例存背景 DB），**无记忆的判定放 FC**（报警、数据整理），**共享数据进全局 DB**（库存、报警、设定值），**定时调用顺序固定**（先控制、再计数、再报警、最后整理数据）。OB100 负责给整个系统一个"干净的起点"。

## 四、核心功能实现

### 4.1 传送带控制（FB_电机控制）

**接口定义**

| 形参 | 区段 | 类型 | 说明 |
|---|---|---|---|
| 启动 | Input | Bool | I0.0 或 M1.6（OB1 里并联） |
| 停止 | Input | Bool | I0.1 或 M1.7 |
| 急停 | Input | Bool | I0.2（常闭接线：正常=1） |
| 禁止启动 | Input | Bool | 库满报警 OR 设备故障 |
| 运行 | Output | Bool | → Q0.0 |
| 停止延时标志 | Static | Bool | —— |
| TON_延时停止 | Static | IEC_TIMER | 多重实例 |
| 停止延时时间 | Static | Time | T#5S |

**梯形图程序**

```
网络1：急停立即复位（急停常闭接线，按下=0，常闭触点导通）
      #急停                                #运行
  ----|/|----------------------------------(R)----
      (同支路并列) (R) #停止延时标志

网络2：启动（急停正常且无禁止条件才允许）
      #启动        #急停      #禁止启动(常闭)      #运行
  ----| |-----------| |----------|/|--------------(S)----

网络3：停止/库满 → 请求延时停止
      #停止                      #运行         #停止延时标志
  ----| |------------+-----------| |-------------(S)----
      #禁止启动      |
  ----| |------------+

网络4：延时5秒后真正停止（让货物走完）
      #停止延时标志     TON_延时停止
  ----| |-------------(TON)----------
                      PT := #停止延时时间  Q──┬(R) #运行
                                             └(R) #停止延时标志

网络5：输出
      #运行                                #运行(输出)
  ----| |----------------------------------( )----
```

**逻辑分析**：急停是最高优先级，网络1 直接复位一切；启动必须"急停正常 + 无禁止条件"；按停止不立即断输出，而是置位延时标志，5 秒后（TON 计满）才真正复位运行——这就是"走完最后一件货"的柔性停止。OB1 中的调用（HMI 按钮与现场按钮并联）：

```
网络1：调用 FB_电机控制
      I0.0 ──启动 ────┐
      I0.1 ──停止 ────┤  FB_电机控制     (背景DB: 传送带电机)
      I0.2 ──急停 ────┤
      报警或标志 ──────┤  禁止启动 := DB_报警状态.库满报警
      Q0.0 ──运行 ←───┘              OR DB_报警状态.设备故障
```

### 4.2 货物检测与分拣（FB_分拣控制）

**时序分析（先画时序，再写程序）**

```
信号        时间轴 -->
I0.4分拣位  ────┐
                └──── 对位0.5s ────┐
Q0.5电磁阀                       ┌────── 伸出 ──────┐
                                 │  (到位I0.5=1)     │保压1s
I0.5伸到位                        └────────┐          │
                                          └──────────┘ → 缩回
I0.6缩到位                                      ┌──────┐
                                                        └→ 分拣完成脉冲
故障：伸出指令后3s内I0.5一直=0 → 气缸故障
```

**接口定义**：输入 允许分拣（=传送带运行）、分拣位传感器、伸出到位、缩回到位、故障复位（M1.4）；输出 气缸电磁阀（→Q0.5）、分拣完成（→M2.1）、气缸故障（→M2.2）；静态 步1_对位~步4_缩回（步序标志）、TON_对位（T#500MS）、TON_保压（T#1S）、TON_气缸超时（T#3S）、各边沿存储位。

```
      #步3_保压      TON_保压
  ----| |----------(TON)----------
                   PT := T#1S     Q──┬(S) #步4_缩回
                                       └(R) #步3_保压

网络7：缩回到位 → 输出分拣完成脉冲，回到空闲
      #步4_缩回      #缩回到位
  ----| |-----------| |------------------┬( ) #分拣完成
                                         └(R) #步4_缩回

网络8：HMI报警复位兼作故障复位
      #故障复位                              #气缸故障
  ----| |------------------------------------(R)----
```

**设计要点**：

- **边沿触发（网络1 的 P 触点）**：货物在分拣位会停留几秒，若不用边沿，步序会被反复触发；"到达瞬间"只发生一次，正好作为启动信号。
- **S/R 步进法**：每一步一个静态标志，"转下一步 + 复位当前步"成对出现，时序清晰、不会两步并存；这是顺序控制最朴素也最可靠的写法。
- **单周期脉冲**：网络7 用线圈输出"分拣完成"，条件在下一周期自动消失，天然形成宽度一个扫描周期的脉冲，供 OB1 里的 CTU 计数（FB 在 OB1 中先于计数网络被调用，脉冲恰好"送得到"）。
- **超时保护（网络5）**：TON_气缸超时以"伸出指令存在"为条件计时，货物一旦到位步2 复位、计时自动清零；3 秒未到位即判故障并中断步序——没有它，气缸卡死会让整条线"静悄悄地瘫痪"。

**计数网络（OB1，LAD）**

```
      DB_库存数据.当前入库数 ──IN1 ┌─────────┐
```

**数据整理（FC_HMI数据，SCL）**

```scl
// FC_HMI数据：每周期执行，负责所有"给人看"的数据
// 1) 当前库存钳位：不允许出现负库存
"DB_库存数据".当前库存 := "DB_库存数据".当前入库数 - "DB_库存数据".当前出库数;
IF "DB_库存数据".当前库存 < 0 THEN
    "DB_库存数据".当前库存 := 0;
END_IF;

// 2) 库存占用率(%)，防除零
IF "DB_库存数据".库存上限 > 0 THEN
    "DB_库存数据".库存占用率 :=
        INT_TO_REAL("DB_库存数据".当前库存)
        / INT_TO_REAL("DB_库存数据".库存上限) * 100.0;
ELSE
    "DB_库存数据".库存占用率 := 0.0;
END_IF;

// 3) 仓库温度换算：IW64 原始值(0~27648) → 0.0~60.0 °C
"MD40_温度工程量" := INT_TO_REAL("仓库温度原始值") / 27648.0 * 60.0;

// 4) 同步课程约定的镜像变量
"MW30_当前库存" := "DB_库存数据".当前库存;   // Int，监控表/HMI 直接用
// 高温判断在 FC_报警处理 中做：MD40 > INT_TO_REAL(MW20)
```

**设计要点**：计数用 IEC 计数器（单实例背景 DB）最省心；"入库 − 出库"的口径统一在 FC_HMI数据 里计算，别的块只管加减计数，避免多处计算口径不一致；INT_TO_REAL 的显式转换让类型一眼可见——这些都是编译通过之后少踩坑的经验。

### 4.4 报警系统（FC_报警处理）

**报警条件与处理方式总表**

| 报警 | 触发条件 | 处理方式 | 附加动作 |

| 18 | HMI 联动 | 运行系统仿真中操作 | 按钮可启停、数据显示实时、报警视图有条目、趋势滚动 | [ ] |

### 6.5 验证不通过时的排查方法

- **现象整体错乱**：先确认 CPU 在 RUN、程序已重新下载（改完必下）；STOP→RUN 一轮排除"脏状态"；
- **分拣时序不走**：按附录B 分段验证法——看步1_对位是否置位（ FB 背景DB「分拣控制」里监控静态变量），置位了看 TON_对位 的 ET 是否在增长；常见原因是网络1 忘了"允许分拣"条件（传送带没运行）；
- **计数不动**：监控 M2.1 是否有单周期脉冲；CTU 的 R 端是否被误置 1（清零按钮粘住）；
- **报警乱跳**：检查比较方向（>= 还是 <=）、回差阈值是否同步计算；MW30 被手工改写后与 DB 是否一致（FC_HMI数据 每周期会用 DB 覆盖 MW30，调试"库满"请直接改 DB_库存数据.当前入库数/当前出库数，或临时接受下一周期被同步回真实值）；
- **HMI 不联动**：核对 HMI 连接的 PLC 与 IP，确认 PLC 先于 HMI 启动，附录A 第九节排查表逐条过。

### 7.2 可扩展方向

1. **码垛功能**：分拣完成后增加码垛计数（如 5 件一垛），驱动虚拟码垛机按层摆放——练习多级计数与步序嵌套；
2. **条码识别**：入库口增加扫码枪（仿真用 M 区模拟扫码结果），按条码类别把货物分到不同货架位——练习字符比较与 Case 分支（SCL 的 SWITCH 或 LAD 的比较链）；
3. **出入库联运**：增加出库传送带与出库口（Q0.6 已预留），实现"入库-存储-出库"全自动，出库按先进先出（FIFO）用数组 + 指针实现库位管理——练习间接寻址；
4. **多巷道扩展**：把 FB_分拣控制多实例化（巷道1/巷道2/巷道3），参数化各巷道地址——体会 FB 复用的真正威力；
5. **与上位机通信**：用 S7 通信或 OPC UA 把 DB_库存数据 开放给 MES/上位系统（PLCSIM Advanced 支持虚拟以太网通信仿真）；
6. **数据记录升级**：换用精智面板，启用数据记录（DataLog）把每小时库存写入 CSV，配合历史趋势做产能分析；
7. **诊断增强**：为 OB80/OB82/OB86/OB121/OB122 组态处理逻辑，配合 GET_ERROR 做程序级错误捕获，让系统"报而不停"；
8. **安全完善**：把急停回路升级为安全模块 + 安全程序（F-CPU），理解软件急停与硬件安全回路的边界。

## 📌 小结

- 一个完整项目 = 需求分析 → 硬件设计（I/O 分配表 + 拓扑）→ 程序架构（OB/FB/FC/DB 分工）→ 编码 → HMI → 仿真验证；
- 本项目的四条主线：传送带（FB_电机控制：启保停+延时停+急停）、分拣（FB_分拣控制：边沿触发 + S/R 四步时序 + 超时保护）、库存（CTU 计数 + SUB 统计 + DB 管理）、报警（锁定/回差/闪烁/消音 + HMI 离散量报警）；
- 架构口诀：**有记忆放 FB，无记忆放 FC，共享数据进 DB，初始化进 OB100**；
- 时序类逻辑先画时序图再写程序；步序用"转下一步 + 复位当前步"成对置位复位；保护（急停、超时、禁止启动）永远优先于功能；
- HMI 的价值是"3 秒看懂"：状态可视化、数据数字化、报警列表化、趋势曲线化；
- 仿真验证要"清单化"：变量清单、时序步骤表、逐项验证表，一件一件打勾，全绿才算完工；
- 这个项目综合了前几章全部核心知识点——能独立完成并讲清每一处"为什么"，本课程的学习目标就达成了。

## ⚠️ 注意事项

- 急停按钮是常闭接线：程序中用常开触点读 I0.2 表示"正常"，用常闭触点表示"按下"，切勿按常开按钮的习惯照搬，否则上电即"急停"；
- 分拣步序的触发必须用边沿（P 触点），否则货物停留期间步序反复重启；每个 P 触点的边沿存储位必须独享；
- "分拣完成"是单周期脉冲，只在 FB 调用之后的网络里有效——OB1 中计数网络必须放在 FB_分拣控制 之后，调整调用顺序前先想清楚数据流向；
- 库满报警带 10 件回差，是为了避免库存恰好在 100 附近波动时报警灯"抽搐"；解除阈值已在 DB 中预计算，修改上限后记得同步；
- MW30/MD40 是镜像变量，FC_HMI数据 每周期会用 DB 计算结果覆盖它们——调试时想"造库存"，请改 DB_库存数据 里的入库/出库数，别和镜像变量较劲；
- 气缸超时保护不可省略：任何"等传感器"的步序都必须有超时出口，否则现场执行机构卡一次，整线就无声停摆；
- HMI 按钮写 M 区、由 PLC 程序统一决策，不要让 HMI 直接写 Q 输出——"PLC 是唯一决策者"是安全底线；
- 精简面板不支持数据记录/历史归档，本项目趋势为实时趋势；需要历史数据请扩展到精智面板或上位机方案；
- 全部功能以 6.4 清单逐项仿真验证通过为准，"看着差不多"不算完成——清单法就是从本项目开始养成的职业习惯。
